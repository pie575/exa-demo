Agent 通过 [Nevermined](https://nevermined.ai) 的 [x402 银行卡委托](https://nevermined.ai/docs/specs/x402-card-delegation)方案使用信用卡向 Exa 付款。每笔 **$7 购买**都会返回一个含 **$7 Exa 积分**的 Exa API 密钥。

<Info>
  请使用此 Nevermined 计划 ID：<br />`27800462147494506865542649899724877617306579171265399959488097895839186996870`<br />该 plan 运行在 Nevermined 的 live 环境 (API 密钥以 live 为前缀) 。此次购买针对的是 API 积分，而非单次 search 请求。
</Info>

对于首次付款的 Nevermined 付款方，`POST /team-management/nevermined/purchase-key` 会开通一个新的 Exa API 密钥并充入 $7 积分。若密钥积分用尽，可使用相同的委托 mint 一个新的 x402 token，并再次调用该端点。Exa 会返回同一个 API 密钥，并再追加 $7 积分。

## 购买密钥 {#buy-a-key}

```bash theme={null}
POST https://admin-api.exa.ai/team-management/nevermined/purchase-key
payment-signature: <x402-token>
```

* **费用：** 每次购买 $7，从 x402 token 所引用的委托对应的银行卡扣款。
* **响应 (首次付款方) ：** `{ status: "ok", apiKey: "…", expiresAt: null }` — 一个含 $7 积分的新 Exa API 密钥。
* **响应 (已有付款方) ：** `{ status: "ok", apiKey: "…", expiresAt: null }` — 仍是同一个 Exa API 密钥，额外增加 $7 积分。
* **响应 (重放的 token) ：** 返回缓存结果，不再扣款。
* **签名缺失/无效：** 返回 `402 Payment Required`，响应体中包含支付要求。

## 工作原理 {#how-it-works}

支付环节由 Nevermined 处理；Exa 只会看到已签名的 x402 token。

1. **一次性设置 (由持卡人完成) ：** 在 [nevermined.app](https://nevermined.app) 注册一张银行卡，在卡上创建一个**委托** (即支付权限：持卡人设定限额与有效期，并可将其限定到特定的 API 密钥) ，然后为 agent 签发一个 Nevermined API 密钥。
2. **agent 查找自己的委托。** Nevermined SDK 可让 agent 发现其密钥能够动用的委托，并从中挑选一个剩余预算充足 (至少 $7) 的委托。若没有可用委托，持卡人可在控制台中创建，完全自主的 agent 也可以在银行卡限额范围内通过 SDK 创建。
3. **agent 针对上述计划 ID mint 一个 x402 访问 token**，采用银行卡委托方案，并通过 ID 引用该委托。委托必须在 mint 之前就已存在；token 无法临时创建委托。
4. **agent 通过 `payment-signature` header 将 token POST 到上述端点**，并从响应中获取 Exa API 密钥。
5. **该密钥可立即用于**标准的 [Exa Search API](/zh/docs/search/quickstart)。

如需面向 agent 的完整操作说明 (SDK 方法、参数、委托的发现与创建、故障排查) ，请参阅 Nevermined 的 Exa integration guide：[nevermined.ai/docs/integrations/exa](https://nevermined.ai/docs/integrations/exa) (agent 可直接获取 [nevermined.ai/docs/integrations/exa.md](https://nevermined.ai/docs/integrations/exa.md)) 。

## $7 能用来做什么 {#what-7-buys}

积分按 Exa API 标准定价扣除。按当前费率，$7 的积分大致可覆盖：

| 端点或功能                                       |                  价格 |        大致用量 |
| ------------------------------------------- | ------------------: | ----------: |
| Search (`instant`、`fast`、`auto`) ，最多 10 条结果 |      $7 / 1,000 次请求 |   1,000 次请求 |
| Deep-Lite Search                            |     $10 / 1,000 次请求 |     700 次请求 |
| Deep Search                                 |     $12 / 1,000 次请求 |    ~583 次请求 |
| Deep-Reasoning Search                       |     $15 / 1,000 次请求 |    ~466 次请求 |
| Contents (`text`、`highlights` 或 `summary`)  | 每种内容类型 $1 / 1,000 页 |     7,000 页 |
| Search 或 Contents 的 AI 页面摘要                 |        $1 / 1,000 页 |   7,000 条摘要 |
| 超出前 10 条的额外结果                               |      $1 / 1,000 条结果 | 7,000 条额外结果 |
| Answer                                      |      $5 / 1,000 次请求 |   1,400 次请求 |
| Monitors                                    |     $15 / 1,000 次请求 |    ~466 次请求 |

搜索请求已包含最多 10 条结果的正文与 highlights。超出 10 条的额外结果以及 AI 摘要单独计费。<br />
完整定价详情请参见 [Exa 定价](https://exa.ai/pricing)。

## 密钥额度用尽时 {#when-the-key-runs-out}

当 API 密钥的积分耗尽后，Exa 会在常规 API 端点上返回 **`HTTP 402`**：

```json theme={null}
{
  "requestId": "...",
  "error": "You have exceeded your credits limit. Please top up to keep using Exa at dashboard.exa.ai",
  "tag": "NO_MORE_CREDITS"
}
```

使用相同的计划 ID 和委托 mint 一个新的 x402 token，然后再次 POST 到同一个 `/purchase-key` 端点。Exa 会为同一个 API 密钥再增加 $7 的积分。
