<Info>
  HIPAA 合规功能面向 Enterprise 客户提供，需先由 Exa 为你的团队启用。请联系 [sales@exa.ai](mailto:sales@exa.ai)，洽谈 Enterprise 使用权限、BAA 要求及启用事宜。
</Info>

HIPAA 模式通过顶层的 `compliance` field 逐个请求进行控制：

```json theme={null}
{
  "compliance": "hipaa"
}
```

当符合条件的团队设置了该 field 时，Exa 会在处理该请求时应用 HIPAA 合规控制措施。如果您的团队未启用该功能，API 将返回 `403 FEATURE_DISABLED`。

HIPAA 模式对这类请求包含 [Zero Data Retention](/zh/docs/admin/security/zero-data-retention)：Exa 不会保留 PHI。

## 支持的端点 {#supported-endpoints}

以下端点可识别 `compliance` field：

* [`/search`](/zh/docs/reference/search)
* [`/contents`](/zh/docs/reference/get-contents)

其他端点会拒绝该 field。

## 要求 {#requirements}

HIPAA 模式仅支持缓存检索。兼容的请求：

* 在 `/search` 上，将 `type` 设为 `instant` 或 `fast`
* 请求 `text` 或 `highlights` (而非 `summary`)
* 仅使用缓存内容：省略新鲜度相关 field，或在 `/contents` 上设置 `maxAgeHours: -1`

不兼容的请求将返回 `400 INVALID_REQUEST_BODY`，包括：

* 在 `/contents` 上使用 `summary`，或在 `/search` 上使用 `contents.summary`
* 需要实时抓取的新鲜度设置，例如 `maxAgeHours: 0` 或正数的 `maxAgeHours`
* 未指定 `type` 的搜索请求，或使用 `instant`、`fast` 以外类型的请求

## 示例 {#example}

<CodeGroup>
  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/contents" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "urls": ["https://example.com/article"],
      "compliance": "hipaa",
      "highlights": true,
      "maxAgeHours": -1
    }'
  ```
</CodeGroup>
