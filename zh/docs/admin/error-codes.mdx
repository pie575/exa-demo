Exa API 使用标准 HTTP 状态码和 JSON 错误响应体来表示请求失败。

<div id="http-status-codes">
  ## HTTP 状态码
</div>

| 状态码                         | 含义                                                  | 处理方式                                          |
| --------------------------- | --------------------------------------------------- | --------------------------------------------- |
| `400` Bad Request           | 请求体、查询参数、header 或选项组合无效。                            | 根据返回的消息更正请求。                                  |
| `401` Unauthorized          | API 密钥缺失或无效。                                        | 检查认证 header 和 API 密钥。                         |
| `402` Payment Required      | 积分已耗尽或超出支出预算。                                       | [充值积分](https://dashboard.exa.ai)或联系你的团队管理员。   |
| `403` Forbidden             | 该 API 密钥无权访问所请求的功能，或请求被策略拦截。                        | 查看返回的消息以及你所在 plan 的功能权限。                      |
| `404` Not Found             | 路由或所请求的资源不存在。                                       | 检查端点和资源 ID。                                   |
| `409` Conflict              | 请求与现有状态冲突 — 例如，已存在使用相同 `externalId` 的 Webset。       | 获取已有资源，或改用其他标识符。                              |
| `422` Unprocessable Entity  | Websets 预览 query 无法拆解为有效的实体和 criteria。              | 重新表述预览 query。                                 |
| `429` Too Many Requests     | 你的 API 密钥、团队或网络超出了速率或并发限制。                          | 降低请求速率；若返回中包含 `Retry-After`，请等待相应秒数，否则使用指数退避。 |
| `500` Internal Server Error | 发生了意外的服务器错误。                                        | 稍作延迟后重试。若持续出现，请联系支持团队。                        |
| `503` Service Unavailable   | Exa 暂时超载 (`SERVICE_OVERLOADED`) 或不可用。该请求未被处理，也不会计费。 | 使用指数退避重试。这与你的请求速率无关，因此降低速率并无帮助 — 重试才有效。       |
| `504` Gateway Timeout       | 请求超出了处理时限。                                          | 重试请求，或缩小其范围。                                  |

<Note>
  来自 `/contents` 的 URL 级失败会在成功的 `200` 响应的 `statuses` field 中报告，而不是作为请求级错误返回。参见[内容抓取状态标签](#content-fetch-status-tags)。
</Note>

<div id="error-response-structure">
  ## 错误响应结构
</div>

错误响应会返回 `requestId`、人类可读的 `error` 消息以及机器可读的 `tag`：

```json theme={null}
{
  "requestId": "67207943fab9832d162b5317f4cca830",
  "error": "Invalid request body | Validation error: Invalid value for type",
  "tag": "INVALID_REQUEST_BODY"
}
```

<Note>
  联系支持团队时请附上 `requestId`，以便更快排查问题。
</Note>

tag 集合是开放式的，tag 名称本身即可说明含义。请先根据 HTTP 状态码进行分支处理，并将无法识别的 tag 视为附加细节，而不是解析失败。

<div id="common-error-tags">
  ## 常见错误 tag
</div>

<div id="account-billing-and-access">
  ### 账户、计费与访问权限
</div>

| Tag                       | HTTP 状态码 | 说明                                                              |
| ------------------------- | -------- | --------------------------------------------------------------- |
| `INVALID_API_KEY`         | `401`    | API 密钥缺失、为空或无效。                                                 |
| `NO_MORE_CREDITS`         | `402`    | 账户已无剩余积分 — 请前往 [dashboard.exa.ai](https://dashboard.exa.ai) 充值。 |
| `API_KEY_BUDGET_EXCEEDED` | `402`    | 该 API 密钥已超出其支出预算 — 请联系团队管理员。                                    |
| `TEAM_BUDGET_EXCEEDED`    | `402`    | 团队已超出当前计费周期的支出预算。                                               |
| `FEATURE_DISABLED`        | `403`    | 所请求的端点、搜索类型或选项未在你的 plan 中启用。                                    |
| `PROHIBITED_CONTENT`      | `403`    | 请求被内容安全审核拒绝。                                                    |
| `CONTENT_FILTER_ERROR`    | `403`    | 处理过程中内容被安全策略拒绝。                                                 |
| `RATE_LIMIT_EXCEEDED`     | `429`    | 你的 API 密钥、团队或网络已超出各自的速率限制 — 请降低请求速率。                            |
| `SERVICE_OVERLOADED`      | `503`    | Exa 暂时超载，已在处理前丢弃该请求 — 请使用指数退避重试。                                |

<div id="request-validation">
  ### 请求校验
</div>

| Tag                       | HTTP 状态码 | 描述                                           |
| ------------------------- | -------- | -------------------------------------------- |
| `INVALID_REQUEST_BODY`    | `400`    | JSON 请求体未通过 schema 校验。                       |
| `INVALID_REQUEST`         | `400`    | 选项之间相互冲突，或使用了 beta 功能但未附带 `Exa-Beta` header。 |
| `INVALID_NUM_RESULTS`     | `400`    | 请求 highlights 时，`numResults` 必须 ≤ 100。       |
| `NUM_RESULTS_EXCEEDED`    | `400`    | 请求的结果数量超出了你所在 plan 的上限。                      |
| `INVALID_JSON_SCHEMA`     | `400`    | 提供的输出 schema 无效。                             |
| `SUBPAGES_LIMIT_EXCEEDED` | `400`    | `/contents` 每个请求最多支持 100 个子页面。               |

<div id="payment-protocols">
  ### 支付协议
</div>

通过 x402 或 MPP 支付的请求还可能返回：

| Tag                        | HTTP 状态码 | 说明                      |
| -------------------------- | -------- | ----------------------- |
| `X402_PAYMENT_REQUIRED`    | `402`    | 需要支付。                   |
| `X402_INVALID_SIGNATURE`   | `400`    | x402 支付签名无效。            |
| `X402_VERIFICATION_FAILED` | `402`    | 无法验证该 x402 支付。          |
| `MPP_VERIFICATION_FAILED`  | `402`    | 无法验证该 MPP 支付。           |
| `X402_TOO_MANY_UNPAID`     | `429`    | 待支付的 x402 请求过多。         |
| `X402_WALLET_RATE_LIMITED` | `429`    | 该 x402 wallet 已超出其速率限制。 |
| `X402_INTERNAL_ERROR`      | `500`    | Exa 无法创建 x402 支付要求。     |

<div id="content-fetch-status-tags">
  ## 内容抓取状态标签
</div>

当 `/contents` 接收多个 URL 时,可能出现部分 URL 失败、其余 URL 成功的情况。URL 级别的失败会通过 `statuses` field 返回,并不会导致整个请求失败:

```json theme={null}
{
  "results": [],
  "statuses": [
    {
      "id": "https://example.com",
      "status": "error",
      "error": {
        "tag": "CRAWL_NOT_FOUND",
        "httpStatusCode": 404
      }
    }
  ]
}
```

`httpStatusCode` 描述的是目标页面，而非 `/contents` 的响应。

| Tag                       | 说明                                       | 处理方式                                     |
| ------------------------- | ---------------------------------------- | ---------------------------------------- |
| `CRAWL_NOT_FOUND`         | 未找到目标页面。                                 | 确认 URL 正确且可访问。                           |
| `CRAWL_HTTP_{status}`     | 目标返回了 HTTP 错误，例如 `CRAWL_HTTP_403`。       | 按其中包含的目标状态码进行处理。                         |
| `CRAWL_TIMEOUT`           | 抓取目标页面时超时。                               | 重试请求或稍后再试。                               |
| `CRAWL_LIVECRAWL_TIMEOUT` | 实时 retrieval 超出了你设置的 `livecrawlTimeout`。 | 增大 `livecrawlTimeout` 或调整 `maxAgeHours`。 |
| `SOURCE_NOT_AVAILABLE`    | 来源禁止访问，或该来源不可用。                          | 检查该来源是否需要认证或存在访问限制。                      |
| `UNSUPPORTED_URL`         | 该 URL 协议不支持内容抓取。                         | 请使用标准的 HTTP 或 HTTPS URL。                 |
| `CRAWL_UNKNOWN_ERROR`     | 抓取因其他原因失败。                               | 重试请求；若持续失败，请联系支持团队。                      |

这些状态标签仅适用于 `/contents`；`/search` 不会返回 `statuses` field。

<div id="getting-help">
  ## 获取帮助
</div>

* 当 `500`、`503` 或 `504` 错误持续出现时，请查看 [Exa 状态](/zh/docs/admin/status)。
* 查看[速率限制](/zh/docs/admin/billing#rate-limits)了解当前的限制。
* 查阅该端点的 [API 参考](/zh/docs/reference/search)，了解请求要求。
* 联系 [hello@exa.ai](mailto:hello@exa.ai)，并提供响应状态、错误响应体和 `requestId`。
