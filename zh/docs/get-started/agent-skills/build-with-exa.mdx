使用此 skill，让你的 agent 学会按照最佳实践，基于 Exa 的 API 构建应用和 agent。

<Card title="获取你的 Exa API key" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">
  在控制台中创建 key。新账户可获得免费额度。
</Card>

<Note>
  在你的 agent 环境中将 key 设置为 `EXA_API_KEY`。
</Note>

<div id="setup">
  ## 设置
</div>

**方式 A：直接安装此 skill：**

```bash theme={null}
npx skills add exa-labs/agent-skills --skill "build-with-exa"
```

**方式 B：将以下提示词复制到你的编码 Agent 中。**

下面的提示词会安装该 skill，并在不打印 API key 的前提下验证它：

```text Copy this setup prompt into your agent theme={null}
在本机上配置 Exa 的 build-with-exa agent skill。

目标：
- 安装 build-with-exa skill，使我的编码 agent 能够借助 Exa 的完整 API 平台构建应用与 agent。
- 让 Exa API key 可正常使用，且全程不得在本对话中暴露、打印或粘贴该 key。

所选 agent：
- Claude Code、Codex、Cursor，或任何兼容 Agent Skills 的 agent
- 全局安装目录：~/.claude/skills（Claude Code）、~/.codex/skills（Codex）、~/.agents/skills（Cursor / 其他）
- 项目本地安装目录：.claude/skills（Claude Code）、.agents/skills（Codex / Cursor / 其他）

Skill 来源：
- SKILL.md 地址：https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/build-with-exa/SKILL.md

操作步骤：
1. 先安装 skill，再进行任何 key 配置。在仓库内工作时优先采用项目本地安装；否则使用上面列出的对应全局目录。创建所选的 skills 目录并下载 skill：
   mkdir -p <skills-dir>/build-with-exa && curl -fsSL "https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/build-with-exa/SKILL.md" -o <skills-dir>/build-with-exa/SKILL.md
   然后确认 <skills-dir>/build-with-exa/SKILL.md 已存在。
2. 在你自己运行命令的环境中检查是否已有可用的 Exa API key——请使用你后续运行该 skill 所用的同一工具/shell，而不是让我把它 echo 出来。该 skill 会先从 EXA_API_KEY 解析 key，再从文件 ~/.config/exa/key 解析，因此两处都要检查，且不得打印任何值：
   printf '%s\n' "${EXA_API_KEY:+env-set}"; [ -s ~/.config/exa/key ] && printf 'file-set\n'
   你的 shell 很可能是非交互式的，不会自动 source ~/.zshrc 或 ~/.bashrc 这类交互式配置文件，因此我在那里设置的 key 在我看来是存在的，对你却是空的。如果两处都没有结果，key 可能仍存放在你的 shell 跳过的交互式配置文件里：用 `grep -l EXA_API_KEY ~/.zshrc ~/.zshenv ~/.bashrc ~/.profile ~/.config/fish/config.fish 2>/dev/null` 找出是哪个文件，且不要打印其内容（该命令仅列出文件名——绝不要对配置文件直接运行 `grep`/`cat`/`echo`，因为 `export EXA_API_KEY=...` 这样的行会把密钥泄露到我们的对话中）。随后在你的命令中 `source` 该文件，并重新运行上面的存在性检查；若显示已设置，则之后每条需要该 key 的命令都要加上同样的 `source ...;` 前缀。
3. 只有在任何位置都解析不到 key 时，才去配置一个，且不得手工编辑任何 shell 配置文件，也不得把 key 粘贴到本对话中。请告诉我到 https://dashboard.exa.ai/api-keys 创建或复制 key，然后由我在自己的终端里自行 export EXA_API_KEY，或以 600 权限写入 ~/.config/exa/key——绝不要让我把 key 粘贴到对话里。然后等我确认完成后再继续。
4. 在你自己的 shell 中对该 key 做冒烟测试——从环境变量或文件中解析它，并且只打印状态码：
   KEY="${EXA_API_KEY:-$(cat ~/.config/exa/key 2>/dev/null)}"
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.exa.ai/search \
     -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"query":"exa.ai","numResults":1}'
   请严格保持上述 endpoint、header 和请求体不变（不要猜测 schema）。它必须返回 200，而不是 401/429。如果第 2 步中需要加 `source ...;` 前缀才能读到环境变量里的 key，这里同样要加上。
5. 告诉我如何重启或重新扫描我的 agent，使其能够发现该 skill。

全程必须遵守的硬性规则：key 是机密。只能通过存在性/长度检查（`${EXA_API_KEY:+set}`、`[ -s ~/.config/exa/key ]`）或 HTTP 状态码来查看它——绝不要对任何可能包含它的文件或变量执行打印、`echo`、`cat` 或带输出的 `grep`，也绝不要尝试用正则去"脱敏"key 文件。一旦 key 被泄露，请告诉我到 https://dashboard.exa.ai/api-keys 轮换它。
```
