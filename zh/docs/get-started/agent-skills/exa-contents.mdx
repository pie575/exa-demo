使用此技能，让你的 Agent 学会按最佳实践，通过 cURL 或原始 HTTP 调用 Exa Contents。

<Card title="获取你的 Exa API key" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">
  在控制台中创建一个 key。新账户可获得免费额度。
</Card>

<Note>
  在你的 Agent 环境中将 key 设置为 `EXA_API_KEY`。
</Note>

<div id="setup">
  ## 设置
</div>

**方案 A：直接安装此技能：**

```bash theme={null}
npx skills add exa-labs/agent-skills --skill "exa-contents"
```

**方式 B：将以下提示词复制到你的编码 agent 中。**

该提示词会安装此技能并验证你的 API key，且不会将其打印出来：

```text Copy this setup prompt into your agent theme={null}
在这台机器上配置 Exa 的 exa-contents agent 技能。

目标：
- 安装 exa-contents 技能，让我的编码 agent 能用它通过 cURL 或原始 HTTP 直接调用 Exa Contents。
- 让 Exa API key 正常可用，且全程不得暴露、打印该 key，也不得将其粘贴到本对话中。

所选 agent：
- Claude Code、Codex、Cursor，或任何兼容 Agent Skills 的 agent
- 全局安装目录：~/.claude/skills（Claude Code）、~/.codex/skills（Codex）、~/.agents/skills（Cursor / 其他）
- 项目本地安装目录：.claude/skills（Claude Code）、.agents/skills（Codex / Cursor / 其他）

技能 来源：
- SKILL.md 地址：https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md

操作步骤：
1. 先安装技能，然后再做任何 key 配置。在仓库内工作时优先采用项目本地安装；否则使用上面列出的对应全局目录。创建所选的 skills 目录并下载技能：
   mkdir -p <skills-dir>/exa-contents && curl -fsSL "https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md" -o <skills-dir>/exa-contents/SKILL.md
   然后确认 <skills-dir>/exa-contents/SKILL.md 确实存在。
2. 在你自己执行命令的环境中检查是否已有可用的 Exa API key —— 要用你运行该技能时所用的同一工具/shell 来检查，而不是让我把它 echo 出来。该技能会先从 EXA_API_KEY 解析 key，再从文件 ~/.config/exa/key 解析，因此两处都要检查，且始终不得打印其值：
   printf '%s\n' "${EXA_API_KEY:+env-set}"; [ -s ~/.config/exa/key ] && printf 'file-set\n'
   你的 shell 很可能是非交互式的，不会自动 source ~/.zshrc、~/.bashrc 这类交互式配置文件，所以我在那里设置的 key 在我看来存在，在你那边却是空的。如果两处都查不到，key 可能仍放在你的 shell 跳过的某个交互式配置文件里：用 `grep -l EXA_API_KEY ~/.zshrc ~/.zshenv ~/.bashrc ~/.profile ~/.config/fish/config.fish 2>/dev/null` 找出是哪个文件，同时不要打印其值（该命令只列出文件名 —— 绝不要对配置文件直接运行 `grep`/`cat`/`echo`，因为 `export EXA_API_KEY=...` 这样的行会把机密泄露到我们的对话中）。随后在你的命令里 `source` 该文件，并重新运行上面的存在性检测；如果显示存在，就给之后每条需要该 key 的命令都加上同样的 `source ...;` 前缀。
3. 只有在任何地方都解析不到 key 时，才去配置一个，并且不得手工编辑任何 shell 配置文件，也不得把 key 粘贴到本对话中。请告诉我到 https://dashboard.exa.ai/api-keys 创建或复制一个 key，然后由我在自己的终端里自行 export EXA_API_KEY，或将其写入 ~/.config/exa/key 并设置权限为 600 —— 绝不要让我把 key 粘贴到对话里。然后等我确认完成后再继续。
4. 在你自己的 shell 中对该 key 做冒烟测试 —— 从环境变量或文件中解析它，并只打印状态码：
   KEY="${EXA_API_KEY:-$(cat ~/.config/exa/key 2>/dev/null)}"
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.exa.ai/contents \
     -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"urls":["https://exa.ai"],"text":true}'
   端点、header 和请求体必须与上面写的完全一致（不要臆测 schema）。它必须返回 200，而不是 401/429。如果第 2 步中你需要加 `source ...;` 前缀才能读到环境变量里的 key，这里同样要加上。
5. 告诉我如何重启或重新扫描我的 agent，使其能发现该技能。

全程必须遵守的硬性规则：key 是机密。只能通过存在性/长度检查（`${EXA_API_KEY:+set}`、`[ -s ~/.config/exa/key ]`）或 HTTP 状态码来查验它 —— 绝不要打印、`echo`、`cat`，或以输出方式 `grep` 任何可能包含它的文件或变量，也绝不要试图用正则去“脱敏”key 文件。一旦 key 被暴露，请告诉我到 https://dashboard.exa.ai/api-keys 轮换它。
```
