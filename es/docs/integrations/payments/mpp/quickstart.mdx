<div id="what-is-mpp">
  ## ¿Qué es MPP?
</div>

MPP (Machine Payments Protocol) es un estándar de pago abierto y nativo de HTTP basado en el código de estado `402 Payment Required`. Permite que los clientes paguen el acceso a la API por solicitud mediante varios métodos de pago, incluidas stablecoins en [Tempo](https://tempo.xyz), sin necesidad de cuentas, API keys ni suscripciones. Los ejemplos de esta página usan Tempo; actualmente Exa liquida los pagos MPP en USDC.e en la red principal de Tempo.

Exa admite MPP en dos endpoints: **`/search`** y **`/contents`**. Cuando envías una solicitud sin una API key o una credencial de pago, Exa responde con `402` y un desafío `WWW-Authenticate: Payment` que indica el precio y la forma de pago. Tu cliente firma un pago, reintenta la solicitud con una credencial `Authorization: Payment` y recibe los resultados una vez que el pago se liquida on-chain.

Esto resulta ideal para **agentes de IA** que necesitan pagar de forma autónoma por la búsqueda web sin credenciales aprovisionadas de antemano.

<Info>
  El acceso mediante MPP y mediante API key son independientes. Si tu solicitud incluye un encabezado `x-api-key`, se usa el flujo normal de facturación por API key y se omite MPP por completo.
</Info>

<div id="supported-endpoints">
  ## Endpoints compatibles
</div>

| Endpoint    | Método | Descripción                                                                                                     |
| ----------- | ------ | --------------------------------------------------------------------------------------------------------------- |
| `/search`   | POST   | Búsqueda web con todos los tipos de búsqueda (`instant`, `auto`, `fast`, `deep`, `deep-lite`, `deep-reasoning`) |
| `/contents` | POST   | Recuperación de contenido por URL o ID de documento                                                             |

Los demás endpoints de Exa *aún* no aceptan pagos MPP.

<div id="get-started">
  ## Primeros pasos
</div>

Necesitas un wallet compatible con Tempo y con fondos en USDC.e. Exporta la key privada de tu wallet antes de ejecutar un ejemplo:

```bash theme={null}
export WALLET_PRIVATE_KEY="0x..."
```

<div id="install-the-client">
  ### Instala el cliente
</div>

<CodeGroup>
  ```bash TypeScript theme={null}
  npm install mppx viem
  ```

  ```bash Python theme={null}
  pip install "pympp[tempo]"
  ```
</CodeGroup>

<div id="make-a-paid-search-request">
  ### Realiza una solicitud de búsqueda de pago
</div>

Usa el cliente MPP para firmar y enviar un pago por una solicitud de búsqueda:

<CodeGroup>
  ```typescript TypeScript theme={null}
  import { Mppx, tempo } from "mppx/client";
  import { privateKeyToAccount } from "viem/accounts";

  const account = privateKeyToAccount(process.env.WALLET_PRIVATE_KEY as `0x${string}`);
  const mppx = Mppx.create({
    methods: [tempo.charge({ account })],
  });

  const response = await mppx.fetch("https://api.exa.ai/search", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      query: "best machine learning frameworks",
      numResults: 5,
    }),
  });

  const data = await response.json();
  console.log(data.results);
  console.log("Payment receipt:", response.headers.get("Payment-Receipt"));
  ```

  ```python Python theme={null}
  import asyncio
  import os

  from mpp.client import Client
  from mpp.methods.tempo import ChargeIntent, TempoAccount, tempo


  async def main() -> None:
      account = TempoAccount.from_key(os.environ["WALLET_PRIVATE_KEY"])
      method = tempo(
          account=account,
          chain_id=4217,
          intents={"charge": ChargeIntent()},
      )

      async with Client(methods=[method]) as client:
          response = await client.post(
              "https://api.exa.ai/search",
              json={"query": "best machine learning frameworks", "numResults": 5},
          )

      data = response.json()
      for result in data["results"]:
          print(result["url"], result["title"])
      print("Payment receipt:", response.headers.get("Payment-Receipt"))


  asyncio.run(main())
  ```
</CodeGroup>

Si la ejecución es correcta, se imprimen los resultados de la búsqueda y el encabezado `Payment-Receipt` con el hash de la transacción on-chain.

<div id="pay-from-the-command-line">
  ## Paga desde la línea de comandos
</div>

Si prefieres no gestionar directamente una key privada, usa la CLI de Tempo Wallet. `tempo wallet login` crea o conecta una wallet de Tempo, autoriza una key de acceso local y puede incluir créditos MPP gratuitos para los nuevos registros.

<div id="install-and-authenticate">
  ### Instalación y autenticación
</div>

```bash theme={null}
curl -fsSL https://tempo.xyz/install | bash
tempo add wallet
tempo add request
tempo wallet login
```

En un host remoto sin navegador local, usa `tempo wallet login --no-browser` y abre en tu dispositivo la URL que se muestra para autorizar la CLI.

<div id="check-balances-and-credits">
  ### Consultar saldos y créditos
</div>

```bash theme={null}
tempo wallet whoami
tempo wallet whoami --credits
```

<div id="make-a-paid-request">
  ### Realiza una solicitud de pago
</div>

```bash theme={null}
tempo request --max-spend 1.00 https://api.exa.ai/search \
  --json '{"query": "Series A fintech companies", "numResults": 5}'
```

`tempo request` intercepta el desafío `402 Payment Required`, paga y reintenta automáticamente.

Para consultar la referencia completa de la CLI, revisa la [documentación de la CLI de Tempo Wallet](https://tempo.xyz/developers/docs/cli/wallet) y la [documentación de `tempo request`](https://tempo.xyz/developers/docs/cli/request).

<div id="gas-fees">
  ## Comisiones de gas
</div>

Exa patrocina la comisión de red de Tempo y la paga en USDC.e. Tu wallet solo necesita el USDC.e suficiente para cubrir el cargo de la API; no necesita pathUSD ni saldo en ningún otro token de gas. No tienes que configurar un pagador de comisiones: el desafío de pago de Exa y el SDK de MPP gestionan el patrocinio automáticamente.

<div id="pricing">
  ## Precios
</div>

MPP utiliza el mismo precio agrupado que la facturación con API key. Exa calcula el precio a partir de los parámetros de la solicitud antes de procesarla.

<div id="search">
  ### Search
</div>

| Tipo de búsqueda          | Precio para hasta 10 resultados |
| ------------------------- | ------------------------------- |
| `instant`, `auto`, `fast` | $0.007 por solicitud            |
| `deep-lite`, `deep`       | $0.012 por solicitud            |
| `deep-reasoning`          | $0.015 por solicitud            |

Añadir `contents.summary` cuesta **$0.001 adicionales por resultado**.

<Warning>
  Las solicitudes de búsqueda por MPP están limitadas a 10 resultados. Si `numResults` es mayor que 10, Exa usa 10 y cobra la solicitud como si fueran 10 resultados. Si necesitas más, usa la [facturación con API key](/es/docs/search/quickstart).
</Warning>

<div id="contents">
  ### Contents
</div>

Cada tipo de contenido solicitado cuesta $0.001 por URL:

| Tipo de contenido | Precio por URL |
| ----------------- | -------------- |
| `text`            | $0.001         |
| `highlights`      | $0.001         |
| `summary`         | $0.001         |

Si no solicitas `text`, `highlights` ni `summary`, Exa activa `text` de forma predeterminada.

<div id="pricing-examples">
  ### Ejemplos de precios
</div>

| Solicitud                                       | Precio |
| ----------------------------------------------- | ------ |
| `/search` con `type: "auto"`                    | $0.007 |
| `/search` con 3 resultados y `contents.summary` | $0.010 |
| `/search` con `type: "deep"`                    | $0.012 |
| `/contents` para 2 URL con `text: true`         | $0.002 |
| `/contents` para 1 URL con `text` y `summary`   | $0.002 |

<div id="how-the-payment-flow-works">
  ## Cómo funciona el flujo de pago
</div>

El SDK automatiza este flujo, pero puedes inspeccionarlo directamente por HTTP:

1. Envía una solicitud sin API key ni credencial de pago. Exa devuelve `402` con un desafío `WWW-Authenticate: Payment` que incluye el precio, el token, el destinatario, la red y los detalles del patrocinio.
2. Firma el desafío y reintenta con `Authorization: Payment <credential>`.
3. Exa procesa la solicitud mientras liquida el pago. Una vez confirmada la liquidación, Exa devuelve los resultados con un encabezado `Payment-Receipt`. Si la liquidación falla, Exa devuelve `402` con un nuevo desafío y sin resultados.

<div id="inspect-a-payment-challenge">
  ### Inspeccionar un desafío de pago
</div>

Puedes consultar el precio y los detalles del pago sin una wallet:

```bash theme={null}
curl -s -D - -X POST "https://api.exa.ai/search" \
  -H "Content-Type: application/json" \
  -d '{"query": "test query", "numResults": 3}'
```

Busca el encabezado `WWW-Authenticate: Payment` en la respuesta `402`. Las solicitudes de descubrimiento sin pago están sujetas a límites de frecuencia, así que úsalas para depurar y no para sondear.

<div id="payment-reference">
  ## Referencia de pagos
</div>

Exa acepta pagos MPP en USDC.e en la red principal de Tempo.

| Red                    | Identificador | Token  | Activo                                       |
| ---------------------- | ------------- | ------ | -------------------------------------------- |
| Red principal de Tempo | `eip155:4217` | USDC.e | `0x20c000000000000000000000b9537d11c60e8b50` |

USDC.e tiene 6 decimales. El desafío expresa los precios en unidades atómicas, por lo que `7000` equivale a $0.007 y `1000000` a $1.00.

<Note>
  Exa admite MPP y [x402](/es/docs/integrations/payments/x402/quickstart) en los mismos endpoints. Una respuesta `402` sin autenticar puede incluir tanto el desafío MPP `WWW-Authenticate: Payment` como el encabezado x402 `PAYMENT-REQUIRED`. Usa los encabezados del protocolo de pago que admita tu cliente.
</Note>

<div id="headers">
  ### Encabezados
</div>

| Encabezado                            | Dirección         | Descripción                                                             |
| ------------------------------------- | ----------------- | ----------------------------------------------------------------------- |
| `Authorization: Payment <credential>` | Solicitud         | Credencial de pago MPP                                                  |
| `WWW-Authenticate: Payment`           | Respuesta `402`   | Precio e instrucciones de pago para la solicitud                        |
| `Payment-Receipt`                     | Respuesta exitosa | Comprobante de liquidación, incluido el hash de la transacción on-chain |

<div id="errors">
  ### Errores
</div>

| Estado | Descripción                                                                           |
| ------ | ------------------------------------------------------------------------------------- |
| `402`  | Falta la credencial de pago o no es válida; la respuesta incluye un nuevo desafío     |
| `402`  | El importe del pago no coincide con el precio de la solicitud, o falló la liquidación |
| `429`  | Esta IP envió demasiadas solicitudes de descubrimiento sin pago                       |
| `429`  | Esta wallet superó el límite de tasa de solicitudes pagadas                           |

<div id="rate-limits">
  ### Límites de tasa
</div>

Los límites de tasa de MPP se comparten con x402 y son independientes de los límites de la API key:

| Límite                                          | Umbral         | Ventana     |
| ----------------------------------------------- | -------------- | ----------- |
| Solicitudes de descubrimiento no pagadas por IP | 5 solicitudes  | 60 segundos |
| Solicitudes pagadas por wallet                  | 10 solicitudes | 1 segundo   |

<div id="faq">
  ## Preguntas frecuentes
</div>

<AccordionGroup>
  <Accordion title="¿Puedo usar MPP y una API key a la vez?">
    Si tu solicitud incluye un encabezado `x-api-key`, el flujo de API key tiene prioridad y se omite MPP. No se combinan: es uno u otro en cada solicitud.
  </Accordion>

  <Accordion title="¿Qué ocurre si la liquidación falla después de procesarse mi solicitud?">
    Tu respuesta queda bloqueada. Recibes un `402` con un nuevo desafío `WWW-Authenticate: Payment` para que tu cliente pueda reintentar. No se devuelve ningún resultado hasta que la liquidación se complete correctamente.
  </Accordion>

  <Accordion title="¿Qué wallets son compatibles?">
    Cualquier wallet EVM compatible con Tempo con la que el SDK del cliente pueda firmar: una cuenta `viem` con `mppx` (TypeScript) o una key de `eth-account` con `pympp` (Python). Para agentes de IA, usa una wallet con saldo en USDC.e en Tempo para cubrir el precio de las solicitudes.
  </Accordion>
</AccordionGroup>
