Los agentes pagan a Exa con tarjeta de crédito mediante el esquema de [delegación de tarjetas x402](https://nevermined.ai/docs/specs/x402-card-delegation) de [Nevermined](https://nevermined.ai). Cada **compra de $7** devuelve una API key de Exa con **$7 en créditos de Exa**.

<Info>
  Usa este ID de plan de Nevermined:<br />`27800462147494506865542649899724877617306579171265399959488097895839186996870`<br />Este plan se ejecuta en el entorno en vivo de Nevermined (API keys con el prefijo live). La compra corresponde a créditos de API, no a una única solicitud de search.
</Info>

Si es la primera vez que se paga con Nevermined, `POST /team-management/nevermined/purchase-key` aprovisiona una nueva API key de Exa y añade $7 en créditos. Si la key se agota, genera un nuevo token x402 con la misma delegación y vuelve a llamar al mismo endpoint: Exa devuelve la misma API key con otros $7 en créditos añadidos.

<div id="buy-a-key">
  ## Comprar una key
</div>

```bash theme={null}
POST https://admin-api.exa.ai/team-management/nevermined/purchase-key
payment-signature: <x402-token>
```

* **Costo:** $7 por compra, cargados a la tarjeta vinculada a la delegación a la que hace referencia el token x402.
* **Respuesta (pagador nuevo):** `{ status: "ok", apiKey: "…", expiresAt: null }` — una nueva Exa API key con $7 en créditos.
* **Respuesta (pagador recurrente):** `{ status: "ok", apiKey: "…", expiresAt: null }` — la misma Exa API key con $7 más en créditos.
* **Respuesta (token reutilizado):** resultado en caché, sin nuevo cargo.
* **Firma faltante o inválida:** `402 Payment Required` con los requisitos de pago en el cuerpo.

<div id="how-it-works">
  ## Cómo funciona
</div>

Nevermined se encarga de la parte del pago; Exa solo ve el token x402 firmado.

1. **Configuración inicial (a cargo del titular de la tarjeta):** registra una tarjeta en [nevermined.app](https://nevermined.app), crea una **delegación** sobre ella (el permiso de gasto: el titular fija un límite y una duración, y puede acotarla a una API key concreta) y emite una API key de Nevermined para el agente.
2. **El agente encuentra su delegación.** El SDK de Nevermined permite al agente descubrir las delegaciones desde las que puede gastar con su key y elegir una que tenga presupuesto suficiente (al menos $7). Si no hay ninguna, el titular crea una desde el panel, o bien un agente totalmente autónomo puede crearla mediante el SDK dentro de los límites de la tarjeta.
3. **El agente emite un token de acceso x402** para el ID de plan anterior, con el esquema de delegación de tarjeta, referenciando la delegación por su ID. Las delegaciones deben existir antes de la emisión; los tokens no pueden crearlas sobre la marcha.
4. **El agente envía el token mediante POST al endpoint anterior** en el encabezado `payment-signature` y recibe la Exa API key en la respuesta.
5. **La key funciona de inmediato** con la [Exa Search API](/es/docs/search/quickstart) estándar.

Para ver el recorrido completo listo para agentes (métodos del SDK, parámetros, descubrimiento y creación de delegaciones, resolución de problemas), consulta la guía de integración con Exa de Nevermined: [nevermined.ai/docs/integrations/exa](https://nevermined.ai/docs/integrations/exa) (agentes: obtengan [nevermined.ai/docs/integrations/exa.md](https://nevermined.ai/docs/integrations/exa.md)).

<div id="when-the-key-runs-out">
  ## Cuando la key se agota
</div>

Exa devuelve **`HTTP 402`** en los endpoints habituales de la API cuando se agotan los créditos de la API key:

```json theme={null}
{
  "requestId": "...",
  "error": "You have exceeded your credits limit. Please top up to keep using Exa at dashboard.exa.ai",
  "tag": "NO_MORE_CREDITS"
}
```

Genera un nuevo token x402 con el mismo ID de plan y la misma delegación, y vuelve a enviarlo mediante POST al mismo endpoint `/purchase-key`. Exa añadirá otros $7 en créditos a la misma API key.
