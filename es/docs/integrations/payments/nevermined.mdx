Los agentes pagan a Exa con una tarjeta de crédito mediante el esquema de [card-delegation x402](https://nevermined.ai/docs/specs/x402-card-delegation) de [Nevermined](https://nevermined.ai). Cada **compra de $7** devuelve una API key de Exa con **$7 en créditos de Exa**.

<Info>
  Usa este plan ID de Nevermined:<br />`27800462147494506865542649899724877617306579171265399959488097895839186996870`<br />Este plan se ejecuta en el entorno en vivo de Nevermined (API keys con prefijo live). La compra corresponde a créditos de API, no a una única solicitud de búsqueda.
</Info>

Si es la primera compra de un pagador de Nevermined, `POST /team-management/nevermined/purchase-key` aprovisiona una nueva API key de Exa y añade $7 en créditos. Si la key se agota, genera un nuevo token x402 con la misma delegation y llama otra vez al mismo endpoint. Exa devuelve la misma API key con $7 adicionales en créditos.

## Compra una key {#buy-a-key}

```bash theme={null}
POST https://admin-api.exa.ai/team-management/nevermined/purchase-key
payment-signature: <x402-token>
```

* **Costo:** $7 por compra, cargados a la tarjeta vinculada a la delegation referenciada por el x402 token.
* **Respuesta (pagador nuevo):** `{ status: "ok", apiKey: "…", expiresAt: null }` — una nueva API key de Exa con $7 en créditos.
* **Respuesta (pagador recurrente):** `{ status: "ok", apiKey: "…", expiresAt: null }` — la misma API key de Exa con $7 más en créditos.
* **Respuesta (token reproducido):** resultado en caché, sin cargo nuevo.
* **Firma faltante o inválida:** `402 Payment Required` con los requisitos de pago en el cuerpo.

## Cómo funciona {#how-it-works}

Nevermined se encarga de la parte del pago; Exa solo ve el x402 token firmado.

1. **Configuración inicial (a cargo del propietario de la tarjeta):** registra una tarjeta en [nevermined.app](https://nevermined.app), crea una **delegation** sobre ella (el permiso de gasto: el propietario define un límite y una duración, y puede acotarla a una API key específica) y emite una API key de Nevermined para el agente.
2. **El agente localiza su delegation.** El SDK de Nevermined permite que el agente descubra las delegations desde las que puede gastar su key y elija una con presupuesto restante suficiente (al menos $7). Si no hay ninguna, el propietario crea una en el panel, o un agente totalmente autónomo puede crearla mediante el SDK dentro de los límites de la tarjeta.
3. **El agente genera un x402 access token** para el plan ID anterior, con el esquema card-delegation, haciendo referencia a la delegation por su ID. Las delegations deben existir antes de generar el token; los tokens no pueden crearlas sobre la marcha.
4. **El agente envía el token por POST al endpoint anterior** en el encabezado `payment-signature` y recibe la API key de Exa en la respuesta.
5. **La key funciona de inmediato** con la [Exa Search API](/es/docs/search/quickstart) estándar.

Para ver el recorrido completo listo para agentes (métodos del SDK, parámetros, descubrimiento y creación de delegations, resolución de problemas), consulta la guía de integración de Exa de Nevermined: [nevermined.ai/docs/integrations/exa](https://nevermined.ai/docs/integrations/exa) (agentes: obtengan [nevermined.ai/docs/integrations/exa.md](https://nevermined.ai/docs/integrations/exa.md)).

## Cuando la key se agota {#when-the-key-runs-out}

Exa devuelve **`HTTP 402`** en los endpoints habituales de la API cuando se agotan los créditos de la API key:

```json theme={null}
{
  "requestId": "...",
  "error": "You have exceeded your credits limit. Please top up to keep using Exa at dashboard.exa.ai",
  "tag": "NO_MORE_CREDITS"
}
```

Genera un nuevo x402 token con el mismo plan ID y la misma delegation, y vuelve a enviarlo mediante POST al mismo endpoint `/purchase-key`. Exa añade otros $7 en créditos a la misma API key.
