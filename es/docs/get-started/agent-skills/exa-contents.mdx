Usa esta skill para enseñarle a tu agente a llamar a Exa Contents con cURL o HTTP sin procesar, aplicando las mejores prácticas.

<Card title="Obtén tu API key de Exa" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">
  Crea una key en el panel. Las cuentas nuevas comienzan con créditos gratuitos.
</Card>

<Note>
  Define tu key como `EXA_API_KEY` en el entorno de tu agente.
</Note>

<div id="setup">
  ## Configuración
</div>

**Opción A: instala esta skill directamente:**

```bash theme={null}
npx skills add exa-labs/agent-skills --skill "exa-contents"
```

**Opción B: copia este prompt en tu agente de programación.**

El siguiente prompt instala la skill y verifica tu API key sin mostrarla:

```text Copy this setup prompt into your agent theme={null}
Configura el skill de agente exa-contents de Exa en esta máquina.

Objetivo:
- Instalar el skill exa-contents para que mi agente de programación pueda usarlo para llamar a Exa Contents directamente con cURL o HTTP sin procesar.
- Conseguir que funcione una API key de Exa SIN exponer, imprimir ni pegar nunca la key en este chat.

Agente seleccionado:
- Claude Code, Codex, Cursor o cualquier agente compatible con Agent Skills
- Directorios de instalación global: ~/.claude/skills (Claude Code), ~/.codex/skills (Codex), ~/.agents/skills (Cursor / otros)
- Directorios de instalación local del proyecto: .claude/skills (Claude Code), .agents/skills (Codex / Cursor / otros)

Origen del skill:
- URL de SKILL.md: https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md

Qué hacer:
1. Instala el skill PRIMERO, antes de configurar cualquier key. Prefiere una instalación local del proyecto cuando trabajes dentro de un repo; si no, usa el directorio global correspondiente de la lista anterior. Crea el directorio de skills elegido y descarga el skill:
   mkdir -p <skills-dir>/exa-contents && curl -fsSL "https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md" -o <skills-dir>/exa-contents/SKILL.md
   Luego verifica que <skills-dir>/exa-contents/SKILL.md exista.
2. Comprueba si ya hay una API key de Exa disponible DESDE TU PROPIO ENTORNO DE EJECUCIÓN DE COMANDOS: usa la misma herramienta o shell con la que ejecutarás el skill, en lugar de pedirme que la muestre con echo. El skill resuelve la key primero desde EXA_API_KEY y luego desde el archivo ~/.config/exa/key, así que comprueba ambos sin imprimir nunca un valor:
   printf '%s\n' "${EXA_API_KEY:+env-set}"; [ -s ~/.config/exa/key ] && printf 'file-set\n'
   Es probable que tu shell sea no interactivo y NO cargue automáticamente perfiles interactivos como ~/.zshrc o ~/.bashrc, así que una key que yo haya definido ahí puede parecer presente para mí pero estar vacía para ti. Si no aparece ninguna de las dos, puede que la key esté en un perfil interactivo que tu shell omite: averigua en qué archivo está SIN imprimir su valor con `grep -l EXA_API_KEY ~/.zshrc ~/.zshenv ~/.bashrc ~/.profile ~/.config/fish/config.fish 2>/dev/null` (solo lista nombres; NUNCA ejecutes un `grep`/`cat`/`echo` simple sobre un perfil, ya que una línea `export EXA_API_KEY=...` filtraría el secreto a nuestro chat). Después haz `source` de ese archivo dentro de tu comando y vuelve a ejecutar la prueba de presencia anterior; si aparece, antepón ese mismo `source ...;` a todos los comandos posteriores que necesiten la key.
3. Solo si la key no se puede resolver por ningún lado, configura una SIN editar a mano ningún perfil de shell y SIN pegar la key en este chat. Dime que cree o copie una key en https://dashboard.exa.ai/api-keys y luego, en mi propia terminal, yo mismo exportaré EXA_API_KEY o la escribiré en ~/.config/exa/key con permisos 600; nunca me pidas que pegue la key en el chat. Después espera a que te confirme que está hecho antes de continuar.
4. Haz una prueba rápida de la key desde tu propio shell: resuélvela desde la variable de entorno o el archivo e imprime solo el código de estado:
   KEY="${EXA_API_KEY:-$(cat ~/.config/exa/key 2>/dev/null)}"
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.exa.ai/contents \
     -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"urls":["https://exa.ai"],"text":true}'
   Mantén el endpoint, los encabezados y el cuerpo exactamente como están escritos (no adivines el esquema). Debe devolver 200, no 401/429. Si en el paso 2 necesitaste un prefijo `source ...;` para ver una key del entorno, anteponlo también aquí.
5. Dime cómo reiniciar o volver a escanear mi agente para que descubra el skill.

Regla estricta en todo momento: la key es un secreto. Inspecciónala únicamente mediante una comprobación de presencia o longitud (`${EXA_API_KEY:+set}`, `[ -s ~/.config/exa/key ]`) o un código de estado HTTP; nunca imprimas, hagas `echo`, `cat` ni `grep` con salida sobre ningún archivo o variable que pueda contenerla, y nunca intentes "censurar" un archivo de key con una expresión regular. Si alguna vez se expone una key, dime que la rote en https://dashboard.exa.ai/api-keys.
```
