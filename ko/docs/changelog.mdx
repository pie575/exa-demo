<Update label="August 28, 2026" rss={{ title: "Dynamic Highlights (research preview)" }}>
  ## Dynamic Highlights (리서치 프리뷰) {#dynamic-highlights-research-preview}

  Dynamic Highlights는 각 페이지를 개별적으로 처리하지 않고 전체 결과 집합을 아울러 발췌문을 선택합니다. 유용한 소스에는 공유 컨텍스트 예산을 더 많이 배분하고, 이미 반환된 정보를 반복하기만 하는 소스에는 적게 배분합니다.

  * **단일 턴 RAG**: 코딩 및 일반 QA 평가 전반에서 Exa Auto 기준 토큰 효율이 약 49% 개선되고 후속 품질이 2.4% 향상되었습니다.
  * **Agents**: 전체 agent 궤적에 걸쳐 토큰 사용량이 약 30% 줄었고, BrowseComp, WideSearch 및 내부 기업·인물 평가 전반에서 품질이 1% 향상되었습니다.

  `dynamic: true`를 설정한 요청에는 `Exa-Beta: dynamic-highlights-2026-08-28` header가 필요합니다.

  [Dynamic Highlights 가이드 보기 →](/ko/docs/contents/quickstart)
</Update>

<Update label="July 23, 2026" rss={{ title: "Publication research" }}>
  ## 출판물 리서치 {#publication-research}

  학술 출판물에 대한 리서치를 대폭 확장하고 개선했습니다.

  * **3억 5천만 건의 출판물**: 3억 5천만 건 규모의 출판물 인덱스를 검색할 수 있습니다.
  * **더 풍부한 조직 및 인물 결과**: 이제 search는 조직과 소속 인물을 함께 반환하며, 각각 출판물, 주요 공동 연구자, 연구 분야, 연구비를 아우르는 상세하고 enrich된 프로필로 제공됩니다.
  * **에이전틱 인물 및 조직 search**: 이제 agent가 인물과 조직을 대상으로 검색할 수 있습니다.
  * **공개 검색 벤치마크**: 출판물 검색용 공개 벤치마크를 공개했습니다.
  * **새로운 `publication` search 카테고리**: `category: "publication"`으로 학술 결과를 질의할 수 있으며, 이 카테고리가 `research paper` 카테고리를 대체합니다.
  * **지원 중단 카테고리**: `pdf`, `github`, `tweet` search 카테고리는 지원 중단될 예정입니다.
  * **`startCrawlDate` / `endCrawlDate`**: 지원 중단된 parameters는 이제 모든 team에서 무시되지만, 호환성을 위해 계속 허용됩니다.

  `publication` [search 카테고리](/ko/docs/search/quickstart)로 API에서 질의하거나, [dashboard에서 사용해 보세요 →](https://dashboard.exa.ai/playground/search?type=instant).
</Update>

<Update label="July 1, 2026" rss={{ title: "Exa Agent and Exa Connect in MCP" }}>
  ## MCP의 Exa Agent 및 Exa Connect {#exa-agent-and-exa-connect-in-mcp}

  이제 Exa MCP에서 Exa Agent를 사용할 수 있습니다. 단일 search 호출만으로 해결되지 않는 작업이라면 Claude, Cursor 등 어떤 MCP 클라이언트에서든 활용하세요.

  `https://mcp.exa.ai/mcp?tools=agent_run`으로 Agent 도구를 활성화한 다음, `agent_run`을 call하면 agent가 완료될 때까지 실행되고 그 output이 반환됩니다.

  Exa Connect 데이터 소스는 Agent flow를 통해 사용할 수 있어, 실행에 web search만으로 부족할 때 프리미엄 data partners를 attach할 수 있습니다.

  [Exa MCP 가이드 보기 →](/ko/docs/get-started/exa-mcp) · [Exa Agent 가이드 보기 →](/ko/docs/agent/quickstart) · [발표 트윗 →](https://x.com/ExaAILabs/status/2072389192458592672)
</Update>

<Update label="April 1, 2026" rss={{ title: "API 지원 중단 안내" }}>
  ## API 지원 중단 안내 {#api-deprecation-notice}

  Exa API에서 일부 레거시 항목을 제거했습니다:

  * **`/research` 엔드포인트**: `type: "deep-reasoning"`을 사용하는 `/search`로 대체되었습니다.
  * **`resolvedSearchType` 및 `highlightScores` (response field)**: 4월 15일부터 `null`을 반환하며, 5월 1일에 제거되었습니다.
  * **`startCrawlDate` / `endCrawlDate` (지원 중단된 요청 parameters)**: 4월 15일부터 별도 알림 없이 무시됩니다.

  [Deep search로 마이그레이션하기 →](/ko/docs/reference/search)
</Update>

<Update label="March 30, 2026" rss={{ title: "Exa Monitors 소개" }}>
  ## Exa Monitors 소개 {#introducing-exa-monitors}

  Monitors는 일정에 따라 Exa search를 실행해 결과를 웹훅으로 전달합니다. 이전 실행과 중복된 결과는 제거되므로 새로운 콘텐츠만 받아볼 수 있습니다.

  * **시간 흐름에 따른 주제 추적**: competitor 소식, 투자 라운드, 규제 변화, 연구 논문.
  * **구조화된 결과**: `outputSchema`를 통해 일반 텍스트 또는 타입이 지정된 JSON을 반환합니다.
  * **유연한 일정 설정**: 실행 주기를 지정해 실행하거나(최소 1시간) 수동으로 트리거할 수 있습니다.

  [Monitors API 가이드 읽기 →](/ko/docs/monitors/quickstart)
</Update>

<Update label="March 4, 2026" rss={{ title: "Exa Deep 개편" }}>
  ## Exa Deep 개편 {#exa-deep-revamp}

  Exa Deep이 더 빠르고 저렴해졌으며, 이제 field 수준 grounding을 갖춘 structured output을 지원합니다.

  * 더 높은 effort가 필요한 작업을 위한 **새로운 `deep-reasoning` 타입** (12~~50초); `deep`은 4~~12초에 실행됩니다.
  * 일반 `deep` search의 **가격 20% 인하**.
  * `outputSchema`를 통한 **structured output** 지원. response에 `output.content`와 `output.grounding`(field 수준 citations 및 confidence)이 포함됩니다.

  전체 가격은 아래 [Exa 가격 업데이트](#exa-pricing-update)를 참고하세요.

  [Search API reference 읽기 →](/ko/docs/reference/search)
</Update>

<Update label="February 2, 2026" rss={{ title: "Highlights, 콘텐츠 최신성, MCP 업데이트" }}>
  ## Highlights, 콘텐츠 최신성, MCP 업데이트 {#highlights-content-freshness-and-mcp-updates}

  content extraction과 접근 방식이 다음 세 가지로 개선되었습니다:

  * **highlights용 `maxCharacters`**: 이제 highlight 길이를 제어하는 권장 방식입니다. `numSentences`와 `highlightsPerUrl`은 지원 중단되었습니다.
  * **콘텐츠 최신성을 위한 `maxAgeHours`**: 불리언 `livecrawl`을 대체하는 경과 시간 기반 제어입니다 (`0`은 항상 크롤링, `-1`은 캐시 전용, `24`는 24시간보다 오래된 경우 크롤링).
  * **Exa MCP 무료 티어**: 3 QPS, 하루 150 call까지 unauthenticated 상태로 사용해 보세요. 전체 기능을 사용하려면 API 키를 추가하세요.

  [콘텐츠 최신성 문서 →](/ko/docs/contents/quickstart#content-freshness) · [Exa MCP →](/ko/docs/get-started/exa-mcp)
</Update>

<Update label="July 21, 2025" rss={{ title: "Score Deprecation in Auto Search" }}>
  ## Auto search의 Score 지원 중단 {#score-deprecation-in-auto-search}

  새로운 Auto search 아키텍처에서는 더 이상 의미 있는 관련성 점수를 산출할 수 없어, Auto search 결과에서 `score` field가 제거됩니다.

  * **Auto search**: 더 이상 `score`를 반환하지 않습니다. 결과는 이미 관련성 순으로 정렬되어 있습니다.
  * **Neural search**: 점수는 그대로 유지됩니다. 점수가 필요하다면 `type="neural"`을 설정하세요.

  [Search API reference 보기 →](/ko/docs/reference/search)
</Update>

<Update label="June 23, 2025" rss={{ title: "Markdown Contents as Default" }}>
  ## 기본값이 된 마크다운 contents {#markdown-contents-as-default}

  이제 모든 엔드포인트가 기본적으로 깔끔한 마크다운을 반환합니다. 마크다운은 LLM, RAG, 일반적인 텍스트 처리에 더 적합합니다. 별도의 조치는 필요하지 않습니다.

  * **`includeHtmlTags=false` (기본값)**: 콘텐츠가 깔끔한 마크다운으로 처리됩니다.
  * **`includeHtmlTags=true`**: 마크다운 처리 없이 원본 HTML을 반환합니다.

  어느 경우든 광고나 내비게이션 같은 불필요한 요소는 제거됩니다.

  [Contents 문서 보기 →](/ko/docs/contents/quickstart)
</Update>

<Update label="June 7, 2025" rss={{ title: "New Livecrawl Option: Preferred" }}>
  ## 새로운 Livecrawl 옵션: Preferred {#new-livecrawl-option-preferred}

  <Warning>
    과거 항목: `livecrawl` 문자열 매개변수는 현재 지원 중단되었습니다. 새로 연동할 때는 `maxAgeHours`와 `livecrawlTimeout`을 사용하세요. [콘텐츠 최신성](/ko/docs/contents/quickstart#content-freshness)를 참고하세요.
  </Warning>

  지원 중단된 `livecrawl: "preferred"` 옵션은 새로 크롤링을 시도하되, 크롤링에 실패하면 캐시된 콘텐츠로 대체합니다(오류를 반환하는 `"always"`와는 다릅니다). 일시적으로 접근할 수 없는 사이트 때문에 실패하지 않으면서도 최신 콘텐츠를 얻고자 하는 프로덕션 앱에 적합합니다.

  [콘텐츠 최신성 문서 보기 →](/ko/docs/contents/quickstart#content-freshness)
</Update>

<Update label="May 22, 2025" rss={{ title: "Contents Endpoint Status Changes" }}>
  ## Contents 엔드포인트 상태 변경 {#contents-endpoint-status-changes}

  이제 `/contents`는 단일 HTTP 오류 대신 URL별 `statuses` field를 반환하므로, 각 URL의 결과를 개별적으로 처리할 수 있습니다. 이 엔드포인트는 내부 이슈가 발생한 경우에만 오류를 반환합니다.

  * **`status`**: URL별로 `"success"` 또는 `"error"`.
  * **`error.tag`**: 예를 들어 `CRAWL_NOT_FOUND`, `CRAWL_TIMEOUT`, `SOURCE_NOT_AVAILABLE` 등이며, `httpStatusCode`가 함께 제공됩니다.

  [오류 코드 reference 보기 →](/ko/docs/admin/error-codes)
</Update>

<Update label="December 11, 2024" rss={{ title: "Auto search as Default" }}>
  ## 기본값이 된 Auto search {#auto-search-as-default}

  이제 Auto search가 기본값이며, 각 질의를 가장 적합한 검색 방식으로 자동 라우팅합니다. 별도의 조치는 필요하지 않으며, 이전 동작을 유지하려면 `type="neural"`을 설정하세요.

  [Exa의 search types 알아보기 →](/ko/docs/search/quickstart)
</Update>
