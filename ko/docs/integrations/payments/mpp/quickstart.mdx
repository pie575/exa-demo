<div id="what-is-mpp">
  ## MPP란?
</div>

MPP(Machine Payments Protocol)는 `402 Payment Required` 상태 코드를 기반으로 하는 개방형 HTTP 네이티브 결제 표준입니다. client는 계정, API 키, 구독 없이도 [Tempo](https://tempo.xyz) 기반 스테이블코인을 비롯한 여러 결제 수단으로 요청 단위로 API 사용료를 지불할 수 있습니다. 이 페이지의 예제는 Tempo를 사용하며, Exa는 현재 MPP payments를 Tempo mainnet의 USDC.e로 정산합니다.

Exa는 **`/search`**와 **`/contents`** 두 엔드포인트에서 MPP를 지원합니다. API 키나 payment credential 없이 요청을 보내면, Exa는 `402` 응답과 함께 가격 및 결제 방법을 설명하는 `WWW-Authenticate: Payment` challenge를 반환합니다. client는 결제에 서명한 뒤 `Authorization: Payment` credential을 포함해 요청을 재시도하고, 결제가 on-chain에서 정산되면 결과를 받습니다.

따라서 미리 프로비저닝된 credential 없이 자율적으로 web search 비용을 지불해야 하는 **AI agents**에 특히 적합합니다.

<Info>
  MPP와 API 키 접근 방식은 서로 독립적입니다. 요청에 `x-api-key` header가 포함되어 있으면 일반적인 API 키 청구 흐름이 적용되고 MPP는 완전히 우회됩니다.
</Info>

<div id="supported-endpoints">
  ## 지원되는 엔드포인트
</div>

| 엔드포인트       | 메서드  | 설명                                                                                                |
| ----------- | ---- | ------------------------------------------------------------------------------------------------- |
| `/search`   | POST | 모든 search type(`instant`, `auto`, `fast`, `deep`, `deep-lite`, `deep-reasoning`)을 지원하는 web search |
| `/contents` | POST | URL 또는 문서 ID를 통한 콘텐츠 검색                                                                           |

다른 Exa 엔드포인트는 *아직* MPP payments를 지원하지 않습니다.

<div id="get-started">
  ## 시작하기
</div>

USDC.e가 입금된 Tempo 호환 wallet이 필요합니다. 예제를 실행하기 전에 wallet의 private key를 내보내세요:

```bash theme={null}
export WALLET_PRIVATE_KEY="0x..."
```

<div id="install-the-client">
  ### client 설치
</div>

<CodeGroup>
  ```bash TypeScript theme={null}
  npm install mppx viem
  ```

  ```bash Python theme={null}
  pip install "pympp[tempo]"
  ```
</CodeGroup>

<div id="make-a-paid-search-request">
  ### 유료 search 요청 보내기
</div>

MPP client로 search 요청에 대한 payment에 서명하고 제출합니다:

<CodeGroup>
  ```typescript TypeScript theme={null}
  import { Mppx, tempo } from "mppx/client";
  import { privateKeyToAccount } from "viem/accounts";

  const account = privateKeyToAccount(process.env.WALLET_PRIVATE_KEY as `0x${string}`);
  const mppx = Mppx.create({
    methods: [tempo.charge({ account })],
  });

  const response = await mppx.fetch("https://api.exa.ai/search", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      query: "best machine learning frameworks",
      numResults: 5,
    }),
  });

  const data = await response.json();
  console.log(data.results);
  console.log("Payment receipt:", response.headers.get("Payment-Receipt"));
  ```

  ```python Python theme={null}
  import asyncio
  import os

  from mpp.client import Client
  from mpp.methods.tempo import ChargeIntent, TempoAccount, tempo


  async def main() -> None:
      account = TempoAccount.from_key(os.environ["WALLET_PRIVATE_KEY"])
      method = tempo(
          account=account,
          chain_id=4217,
          intents={"charge": ChargeIntent()},
      )

      async with Client(methods=[method]) as client:
          response = await client.post(
              "https://api.exa.ai/search",
              json={"query": "best machine learning frameworks", "numResults": 5},
          )

      data = response.json()
      for result in data["results"]:
          print(result["url"], result["title"])
      print("Payment receipt:", response.headers.get("Payment-Receipt"))


  asyncio.run(main())
  ```
</CodeGroup>

정상적으로 실행되면 search 결과와 함께 on-chain 트랜잭션 해시가 담긴 `Payment-Receipt` header가 출력됩니다.

<div id="pay-from-the-command-line">
  ## 명령줄에서 결제하기
</div>

private key를 직접 관리하고 싶지 않다면 Tempo Wallet CLI를 사용하세요. `tempo wallet login`은 Tempo wallet을 생성하거나 연결하고 로컬 액세스 키를 승인하며, 신규 가입자의 경우 무료 MPP Credits가 함께 제공될 수 있습니다.

<div id="install-and-authenticate">
  ### 설치 및 인증
</div>

```bash theme={null}
curl -fsSL https://tempo.xyz/install | bash
tempo add wallet
tempo add request
tempo wallet login
```

로컬 브라우저가 없는 원격 호스트에서는 `tempo wallet login --no-browser`를 사용하고, 출력된 URL을 사용 중인 기기에서 열어 CLI에 권한을 부여하세요.

<div id="check-balances-and-credits">
  ### 잔액 및 credits 확인
</div>

```bash theme={null}
tempo wallet whoami
tempo wallet whoami --credits
```

<div id="make-a-paid-request">
  ### 유료 요청 보내기
</div>

```bash theme={null}
tempo request --max-spend 1.00 https://api.exa.ai/search \
  --json '{"query": "Series A fintech companies", "numResults": 5}'
```

`tempo request`는 `402 Payment Required` challenge를 가로채 결제를 처리한 뒤 자동으로 재시도합니다.

전체 CLI reference는 [Tempo Wallet CLI 문서](https://tempo.xyz/developers/docs/cli/wallet)와 [`tempo request` 문서](https://tempo.xyz/developers/docs/cli/request)를 참고하세요.

<div id="gas-fees">
  ## 가스비
</div>

Exa가 Tempo 네트워크 수수료를 대신 부담하며 USDC.e로 결제합니다. wallet에는 API 요금에 해당하는 USDC.e만 있으면 되고, pathUSD나 다른 가스 토큰 잔액은 필요하지 않습니다. 수수료 지불자를 따로 설정할 필요도 없습니다. Exa의 payment challenge와 MPP SDK가 sponsorship을 자동으로 처리합니다.

<div id="pricing">
  ## Pricing
</div>

MPP는 API 키 청구와 동일한 번들 가격을 사용합니다. Exa는 요청을 처리하기 전에 요청 parameters를 기반으로 가격을 계산합니다.

<div id="search">
  ### search
</div>

| Search type               | 최대 10개 결과 기준 가격 |
| ------------------------- | --------------- |
| `instant`, `auto`, `fast` | 요청당 $0.007      |
| `deep-lite`, `deep`       | 요청당 $0.012      |
| `deep-reasoning`          | 요청당 $0.015      |

`contents.summary`를 추가하면 **결과당 $0.001**의 비용이 추가됩니다.

<Warning>
  MPP search 요청은 결과가 최대 10개로 제한됩니다. `numResults`가 10보다 크면 Exa는 10을 적용하고 결과 10개 기준으로 요청 비용을 책정합니다. 더 많은 결과가 필요하다면 [API 키 청구](/ko/docs/search/quickstart)를 사용하세요.
</Warning>

<div id="contents">
  ### Contents
</div>

요청하는 content type마다 URL당 $0.001의 비용이 발생합니다:

| Content type | URL당 가격 |
| ------------ | ------- |
| `text`       | $0.001  |
| `highlights` | $0.001  |
| `summary`    | $0.001  |

`text`, `highlights`, `summary`를 요청하지 않으면 Exa는 기본적으로 `text`를 활성화합니다.

<div id="pricing-examples">
  ### Pricing 예시
</div>

| 요청                                            | 가격     |
| --------------------------------------------- | ------ |
| `type: "auto"`로 호출한 `/search`                 | $0.007 |
| 결과 3개와 `contents.summary`를 포함한 `/search`      | $0.010 |
| `type: "deep"`으로 호출한 `/search`                | $0.012 |
| URL 2개에 대해 `text: true`로 호출한 `/contents`      | $0.002 |
| URL 1개에 대해 `text`와 `summary`를 포함한 `/contents` | $0.002 |

<div id="how-the-payment-flow-works">
  ## 결제 흐름 작동 방식
</div>

SDK가 이 흐름을 자동으로 처리하지만, HTTP 수준에서 직접 확인할 수도 있습니다:

1. API 키나 payment credential 없이 요청을 보냅니다. Exa는 가격, 토큰, 수신자, 네트워크, sponsorship 정보가 담긴 `WWW-Authenticate: Payment` challenge와 함께 `402`를 반환합니다.
2. challenge에 서명한 뒤 `Authorization: Payment <credential>`을 포함해 다시 요청합니다.
3. Exa는 settlement를 진행하면서 요청을 처리합니다. settlement가 확인되면 Exa는 `Payment-Receipt` header와 함께 결과를 반환합니다. settlement가 실패하면 Exa는 새로운 challenge와 함께 `402`를 반환하며 결과는 반환하지 않습니다.

<div id="inspect-a-payment-challenge">
  ### payment challenge 확인하기
</div>

wallet 없이도 가격과 결제 세부 정보를 확인할 수 있습니다:

```bash theme={null}
curl -s -D - -X POST "https://api.exa.ai/search" \
  -H "Content-Type: application/json" \
  -d '{"query": "test query", "numResults": 3}'
```

`402` response에서 `WWW-Authenticate: Payment` header를 확인하세요. unpaid discovery requests에는 속도 제한이 적용되므로, 폴링 용도로는 사용하지 말고 디버깅 용도로만 사용하세요.

<div id="payment-reference">
  ## Payment reference
</div>

Exa는 Tempo mainnet에서 USDC.e로 MPP payments를 받습니다.

| 네트워크          | Identifier    | 토큰     | 자산                                           |
| ------------- | ------------- | ------ | -------------------------------------------- |
| Tempo mainnet | `eip155:4217` | USDC.e | `0x20c000000000000000000000b9537d11c60e8b50` |

USDC.e는 소수점 6자리를 사용합니다. challenge는 가격을 원자 단위(atomic unit)로 표현하므로 `7000`은 $0.007, `1000000`은 $1.00입니다.

<Note>
  Exa는 동일한 엔드포인트에서 MPP와 [x402](/ko/docs/integrations/payments/x402/quickstart)를 지원합니다. unauthenticated `402` response에는 MPP의 `WWW-Authenticate: Payment` challenge와 x402의 `PAYMENT-REQUIRED` header가 함께 포함될 수 있습니다. client가 지원하는 payment 프로토콜에 맞는 header를 사용하세요.
</Note>

<div id="headers">
  ### Headers
</div>

| Header                                | 방향             | 설명                                       |
| ------------------------------------- | -------------- | ---------------------------------------- |
| `Authorization: Payment <credential>` | 요청             | MPP payment credential                   |
| `WWW-Authenticate: Payment`           | `402` response | 요청에 대한 가격 및 결제 안내                        |
| `Payment-Receipt`                     | 성공 response    | on-chain 트랜잭션 해시를 포함한 settlement receipt |

<div id="errors">
  ### 오류
</div>

| 상태    | 설명                                                                |
| ----- | ----------------------------------------------------------------- |
| `402` | payment credential이 없거나 유효하지 않습니다. response에 새로운 challenge가 포함됩니다 |
| `402` | 결제 금액이 요청 가격과 일치하지 않거나 settlement에 실패했습니다                         |
| `429` | 이 IP에서 unpaid discovery requests를 너무 많이 보냈습니다                     |
| `429` | 이 wallet이 유료 요청 속도 제한을 초과했습니다                                     |

<div id="rate-limits">
  ### 속도 제한
</div>

MPP 속도 제한은 x402와 공유되며, API 키 limits와는 별개입니다:

| Limit                         | 임계값    | 기간  |
| ----------------------------- | ------ | --- |
| IP당 unpaid discovery requests | 5회 요청  | 60초 |
| wallet당 유료 요청                 | 10회 요청 | 1초  |

<div id="faq">
  ## FAQ
</div>

<AccordionGroup>
  <Accordion title="MPP와 API 키를 함께 사용할 수 있나요?">
    요청에 `x-api-key` header가 포함되어 있으면 API 키 flow가 우선 적용되고 MPP는 건너뜁니다. 두 방식은 중첩되지 않으며, 요청당 둘 중 하나만 사용됩니다.
  </Accordion>

  <Accordion title="요청이 처리된 후 settlement가 실패하면 어떻게 되나요?">
    response가 차단됩니다. client가 재시도할 수 있도록 새로운 `WWW-Authenticate: Payment` challenge와 함께 `402`를 받게 됩니다. settlement가 성공하기 전까지는 결과가 반환되지 않습니다.
  </Accordion>

  <Accordion title="어떤 wallet이 지원되나요?">
    client SDK로 서명할 수 있는 Tempo 호환 EVM wallet이라면 모두 지원됩니다. `mppx`(TypeScript)를 사용하는 `viem` 계정이나 `pympp`(Python)를 사용하는 `eth-account` 키가 여기에 해당합니다. AI agent의 경우, 요청 비용을 충당할 수 있도록 Tempo에서 USDC.e 잔액이 있는 wallet을 사용하세요.
  </Accordion>
</AccordionGroup>
