TinyHumans가 만든 [OpenHuman](https://tinyhumans.gitbook.io/openhuman)은 agent가 스스로 call하는 네이티브 web search 도구를 갖춘 데스크톱 AI 어시스턴트입니다. 이 도구의 search를 담당하는 제공업체가 바로 Exa입니다.

| 방식                    | 설정               | 실행 위치                                              |
| --------------------- | ---------------- | -------------------------------------------------- |
| **OpenHuman Managed** | 없음               | Exa 기반의 OpenHuman 백엔드. API 키 불필요.                  |
| **Exa 제공업체**      | Exa API key 붙여넣기 | 사용자 컴퓨터에서 본인 Exa 계정으로 `https://api.exa.ai`에 직접 연결. |

## OpenHuman Managed {#openhuman-managed}

managed search가 기본값입니다. 온보딩 중에 **Simple**을 선택하면 agent가 곧바로 웹을 검색할 수 있습니다.

<Frame caption="Exa-powered managed search를 사용하려면 온보딩 중 Simple 선택">
  <img src="/docs/images/integrations/openhuman/onboarding-runtime-choice.png" alt="OpenHuman onboarding asking how to run OpenHuman, with the Simple option selected" style={{width: "700px", height: "auto", margin: "0 auto"}} width="1180" height="700" data-path="images/integrations/openhuman/onboarding-runtime-choice.png" />
</Frame>

<Tip>
  **Managed는 Exa 결과를 가장 빠르게 받아보는 방법입니다.** 키를 생성하거나 저장하거나 교체할 필요가 없고, 머신에 credential을 둘 필요도 없으며, search 요금은 OpenHuman 구독으로 청구됩니다.
</Tip>

## Exa 제공업체 {#exa-provider}

Exa를 직접 구성하여 본인의 Exa 계정에서 search를 실행하고, agent에 Exa의 search 및 페이지 contents 도구를 제공하세요.

<Card title="Exa API key 발급받기" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">

</Card>

### 구성 {#configuration}

이 패널은 OpenHuman의 `config.toml`에 값을 기록합니다. 패널 대신 파일이나 환경 변수에 동일한 값을 직접 설정해도 됩니다:

<Tabs>
  <Tab title="config.toml">
    ```toml config.toml theme={null}
    [search]
    engine = "exa"        # 필수
    max_results = 5       # 선택, 1-20
    timeout_secs = 15     # 선택

    [search.exa]
    api_key = "your-exa-api-key"   # 필수
    ```
  </Tab>

  <Tab title="환경 변수">
    ```bash theme={null}
    OPENHUMAN_SEARCH_ENGINE=exa
    EXA_API_KEY=your-exa-api-key
    ```

    <Note>
      `EXA_API_KEY`와 `OPENHUMAN_EXA_API_KEY`는 모두 `search.exa.api_key`를 재정의합니다. 둘 다 설정된 경우 `OPENHUMAN_EXA_API_KEY`가 우선합니다.
    </Note>
  </Tab>
</Tabs>

### agent가 사용할 수 있는 도구 {#tools-the-agent-gets}

| 도구                 | 반환값                                                   |
| ------------------ | ----------------------------------------------------- |
| `web_search_tool`  | Exa가 제공하는 web search.                                 |
| `exa_search`       | 제목, URL, 게시일, 선택적 텍스트가 포함된 순위별 페이지.                   |
| `exa_get_contents` | 지정한 URL의 전체 contents. 선택적으로 summary 또는 highlights 포함. |

agent는 call할 때마다 Exa의 [search parameters](/ko/docs/search/quickstart)를 설정하므로, 간단한 지시만으로도 search mode, 도메인, 날짜, 카테고리를 제어할 수 있습니다.

## 문제 해결 {#troubleshooting}

<AccordionGroup>
  <Accordion title="Exa search를 사용할 수 없음: 설정된 API 키 없음">
    OpenHuman이 **Search engine** 패널, `EXA_API_KEY` 및 `OPENHUMAN_EXA_API_KEY` 변수, `search.exa.api_key` 중 어디에서도 키를 찾지 못했습니다. 이 중 한 곳에 키를 설정하고, OpenHuman 실행 중에 `config.toml`을 수정했다면 OpenHuman을 재시작하세요.
  </Accordion>

  <Accordion title="Exa가 설정된 API 키를 거부함 (HTTP 401)">
    키가 유효하지 않거나 취소되었습니다. [Exa dashboard](https://dashboard.exa.ai/api-keys)에서 키를 확인한 다음, 저장된 키를 **Clear**하고 올바른 키를 저장하세요. 붙여넣기 과정에서 들어간 공백에 주의하세요.
  </Accordion>

  <Accordion title="Exa가 2xx가 아닌 상태를 반환함">
    `429`는 속도 제한 또는 할당량 소진을 의미합니다. [dashboard](https://dashboard.exa.ai)에서 사용량을 확인하세요. `5xx`의 경우 재시도한 뒤 [오류 코드](/ko/docs/admin/error-codes)를 참고하세요.
  </Accordion>

  <Accordion title="엔진 목록에 OpenHuman Managed가 없음">
    로컬 전용 세션에서는 managed search를 사용할 수 없습니다. 직접 발급한 키로 Exa 제공업체를 설정하세요.
  </Accordion>
</AccordionGroup>
