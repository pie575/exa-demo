<div id="billing-basics">
  ## Billing 기본 사항
</div>

요청 비용은 [Pricing](/ko/docs/admin/pricing)에 명시된 요율 또는 Enterprise 계약 조건에 따라 선불 credits에서 차감됩니다. Team 소유자는 [Billing dashboard](https://dashboard.exa.ai/billing)에서 credits를 추가할 수 있으며, 결제는 Stripe를 통해 처리됩니다.

team의 credits가 모두 소진되면 요청은 `402 Payment Required`를 반환합니다. 할당된 예산에 도달한 API key도 마찬가지로 `402`를 반환합니다. 이 경우 credits를 추가하거나 team 관리자에게 해당 key의 예산 조정을 요청하세요. 자세한 내용은 [Error codes](/ko/docs/admin/error-codes)를 참고하세요.

API key별 과거 usage를 확인하려면 [Get API key usage](/ko/docs/reference/team-management/get-api-key-usage)를 사용하세요.

<div id="rate-limits">
  ## Rate limits
</div>

Rate limit은 초당 쿼리 수(QPS)로 측정되며, team의 모든 API key를 통틀어 team 전체에 적용됩니다. [API Keys](https://dashboard.exa.ai/api-keys) 페이지에서 개별 key에 더 낮은 limit을 설정할 수 있지만, 해당 key의 트래픽도 team limit에 함께 집계됩니다.

| Endpoint                                                 | 기본 limit          |
| -------------------------------------------------------- | ----------------- |
| `/search`, `/answer`, `/chat/completions`                | 10 QPS            |
| `type`이 `deep-lite`, `deep`, `deep-reasoning`인 `/search` | 5 QPS             |
| `/contents`                                              | 100 QPS           |
| `/agent/runs`, `/responses`                              | 5 QPS 및 활성 실행 50개 |
| `/websets/*`                                             | 20 QPS            |

일부 endpoint는 rate limit 용량을 공유합니다. Limit은 변경될 수 있고 요금제에 따라 달라질 수 있습니다. Websets의 search에는 요금제 기반 concurrency limits도 적용되며, [Get Team Info](/ko/docs/websets/api/teams/get-team-info)에서 확인할 수 있습니다.

Limit을 초과하면 요청이 `429 Too Many Requests`를 반환합니다. `Retry-After` header가 있으면 그만큼 기다리고, 없으면 지수 백오프로 재시도하세요. [Error codes](/ko/docs/admin/error-codes)를 참고하세요.

<div id="agent-limits">
  ### Agent limits
</div>

Agent limits는 두 가지 별개의 제어로 구성됩니다. 하나는 동시에 진행할 수 있는 실행 수, 다른 하나는 새 실행을 시작할 수 있는 속도입니다.

* **Concurrency**: Agent 실행은 동시에 최대 50개까지 진행할 수 있습니다. 이 limit은 QPS와 별개이며, QPS를 상향해도 함께 늘어나지 않습니다. limit을 초과해 실행을 시작하면 `CONCURRENCY_LIMIT_REACHED` 오류 코드와 함께 `429`가 반환됩니다. 실행이 끝날 때까지 기다리거나, concurrency limit 상향이 필요하면 문의해 주세요.
* **실행 시작**: `POST /agent/runs`는 계정 QPS를 소모하며, 실행 1건을 시작할 때 요청 2건으로 계산됩니다. 따라서 QPS의 절반 속도로 실행을 시작할 수 있으며, 기본값인 10 QPS 계정은 초당 5건, 25 QPS 계정은 초당 12건을 시작할 수 있습니다.
* **폴링**: 실행 상태, 이벤트, 실행 목록 조회용 `GET` 요청은 QPS에 포함되지 않고 디스패치를 차단하지도 않습니다. 따라서 새 실행을 시작하는 속도와 관계없이 실행 중인 Agent를 자유롭게 poll할 수 있습니다.

<div id="25-qps-on-pay-as-you-go">
  ### Pay as you go에서 25 QPS
</div>

임의의 30일 기간 내에 $1,000 상당의 credits를 충전하면 team의 rate limit이 자동으로 **90일간 25 QPS**로 상향됩니다. 이 기준은 사용한 credits가 아니라 구매한 credits를 기준으로 계산되며, 조건을 다시 충족하면 90일이 새로 시작됩니다. 진행 상황은 [Billing dashboard](https://dashboard.exa.ai/billing)에서 확인하세요.

25 QPS 이상이 필요하신가요? [영업팀에 문의하세요](https://exa.ai/contact/sales).

<div id="auto-recharge">
  ## 자동 충전
</div>

자동 충전은 잔액이 지정한 임계값에 도달하면 credits를 구매합니다. [Billing dashboard](https://dashboard.exa.ai/billing)에서 설정할 수 있습니다.

| 설정          | 설명                                                                             |
| ----------- | ------------------------------------------------------------------------------ |
| **충전 금액**   | 자동 충전이 실행될 때마다 구매하는 credits로, $5에서 $10,000까지 설정할 수 있습니다.                       |
| **충전 임계값**  | 충전이 실행되는 기준 잔액입니다.                                                             |
| **월 최대 한도** | 해당 billing 주기 동안 자동 충전 구매에 적용되는 상한으로, 선택 사항입니다. 한도를 두지 않으려면 $0으로 설정하거나 비워 두세요. |

예를 들어 충전 금액 $100, 임계값 $10, 월 최대 한도 $500으로 설정하면 잔액이 $10에 도달할 때마다 $100을 구매하며, 해당 주기 동안 자동 구매는 최대 $500까지 이루어집니다.

출시를 앞두고 있거나 대용량 워크로드가 예상된다면 미리 충분한 credits를 충전하고, 소액 payment 시도가 여러 번 발생하지 않도록 자동 충전 금액을 넉넉히 설정하세요.
