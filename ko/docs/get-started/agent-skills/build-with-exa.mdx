이 skill을 사용해 agent가 모범 사례에 따라 Exa의 API로 애플리케이션과 agent를 구축하도록 학습시키세요.

<Card title="Exa API key 발급받기" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">
  dashboard에서 key를 생성하세요. 신규 계정에는 무료 credits이 제공됩니다.
</Card>

<Note>
  agent 환경에서 key를 `EXA_API_KEY`로 설정하세요.
</Note>

<div id="setup">
  ## 설정
</div>

**옵션 A: 이 skill 바로 설치하기:**

```bash theme={null}
npx skills add exa-labs/agent-skills --skill "build-with-exa"
```

**옵션 B: 아래 prompt를 coding agent에 복사해 붙여넣으세요.**

다음 prompt는 skill을 설치하고, API key를 출력하지 않은 채로 검증합니다:

```text Copy this setup prompt into your agent theme={null}
이 머신에 Exa build-with-exa agent skill을 설정하세요.

목표:
- build-with-exa skill을 설치해서 내 coding agent가 Exa의 전체 API 플랫폼으로 애플리케이션과 agent를 만들 수 있게 할 것.
- key를 이 대화창에 노출하거나 출력하거나 붙여넣는 일 없이 Exa API key가 동작하도록 할 것.

선택한 agent:
- Claude Code, Codex, Cursor 또는 Agent-Skills 호환 agent 전부
- 전역 설치 디렉터리: ~/.claude/skills (Claude Code), ~/.codex/skills (Codex), ~/.agents/skills (Cursor / 기타)
- 프로젝트 로컬 설치 디렉터리: .claude/skills (Claude Code), .agents/skills (Codex / Cursor / 기타)

Skill 소스:
- SKILL.md URL: https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/build-with-exa/SKILL.md

수행할 작업:
1. key 설정보다 먼저 skill을 설치하세요. 리포지토리 안에서 작업 중이라면 프로젝트 로컬 설치를 우선하고, 그렇지 않으면 위에 나열된 해당 전역 디렉터리를 사용하세요. 선택한 skills 디렉터리를 만들고 skill을 내려받으세요:
   mkdir -p <skills-dir>/build-with-exa && curl -fsSL "https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/build-with-exa/SKILL.md" -o <skills-dir>/build-with-exa/SKILL.md
   그런 다음 <skills-dir>/build-with-exa/SKILL.md 파일이 존재하는지 확인하세요.
2. Exa API key를 이미 사용할 수 있는지, 명령을 직접 실행하는 당신의 환경에서 확인하세요 — 나에게 echo 해달라고 요청하지 말고, skill을 실행할 때 쓸 도구/셸을 그대로 사용하세요. skill은 먼저 EXA_API_KEY에서, 그다음 ~/.config/exa/key 파일에서 key를 찾으므로, 값을 절대 출력하지 말고 두 곳을 모두 확인하세요:
   printf '%s\n' "${EXA_API_KEY:+env-set}"; [ -s ~/.config/exa/key ] && printf 'file-set\n'
   당신의 셸은 비대화형일 가능성이 높아 ~/.zshrc나 ~/.bashrc 같은 대화형 프로필을 자동으로 source 하지 않습니다. 그래서 내가 거기에 설정한 key가 나에게는 있어 보여도 당신에게는 비어 있을 수 있습니다. 둘 다 확인되지 않으면, key가 당신의 셸이 건너뛰는 대화형 프로필에 들어 있을 수 있습니다. 값을 출력하지 말고 `grep -l EXA_API_KEY ~/.zshrc ~/.zshenv ~/.bashrc ~/.profile ~/.config/fish/config.fish 2>/dev/null`로 어느 파일인지만 찾으세요(파일 이름만 나열됩니다 — 프로필에 대해 일반 `grep`/`cat`/`echo`는 절대 실행하지 마세요. `export EXA_API_KEY=...` 줄이 secret을 대화창으로 유출할 수 있습니다). 그런 다음 명령 안에서 그 파일을 `source` 하고 위의 존재 여부 테스트를 다시 실행하세요. 값이 확인되면 이후 key가 필요한 모든 명령 앞에 동일한 `source ...;`를 붙이세요.
3. 어디에서도 key를 찾을 수 없을 때만, 셸 프로필을 직접 편집하지 않고 key를 이 대화창에 붙여넣지도 않는 방식으로 key를 설정하세요. https://dashboard.exa.ai/api-keys 에서 key를 만들거나 복사하라고 나에게 알려주고, 내가 직접 터미널에서 EXA_API_KEY를 export 하거나 권한 600으로 ~/.config/exa/key 에 기록하게 하세요 — key를 대화창에 붙여넣으라고 절대 요청하지 마세요. 그런 다음 내가 완료했다고 확인할 때까지 기다린 뒤 진행하세요.
4. 당신의 셸에서 key를 스모크 테스트하세요 — 환경 변수나 파일에서 key를 가져오고, 상태 코드만 출력하세요:
   KEY="${EXA_API_KEY:-$(cat ~/.config/exa/key 2>/dev/null)}"
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.exa.ai/search \
     -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"query":"exa.ai","numResults":1}'
   endpoint, header, 본문은 적힌 그대로 유지하세요(schema를 추측하지 마세요). 401/429가 아니라 200이 반환되어야 합니다. 2단계에서 환경 변수 key를 확인하는 데 `source ...;` 접두사가 필요했다면 여기에도 붙이세요.
5. skill이 인식되도록 내 agent를 재시작하거나 다시 스캔하는 방법을 알려주세요.

전 과정에 적용되는 엄격한 규칙: key는 secret입니다. 존재/길이 확인(`${EXA_API_KEY:+set}`, `[ -s ~/.config/exa/key ]`)이나 HTTP 상태 코드로만 확인하세요 — key가 들어 있을 수 있는 파일이나 변수를 절대 출력하거나 `echo`, `cat`, 출력이 있는 `grep`으로 다루지 말고, 정규식으로 key 파일을 "가리려는" 시도도 하지 마세요. key가 노출된 적이 있다면 https://dashboard.exa.ai/api-keys 에서 교체하라고 나에게 알려주세요.
```
