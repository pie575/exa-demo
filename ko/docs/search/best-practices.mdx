이 가이드는 이미 동작하는 [Search API 요청](/ko/docs/search/quickstart)이 있다고 가정합니다. 여기서는 Exa가 권장하는 모범 사례에 따라 그 요청을 개선하는 방법을 다룹니다.

<div id="start-with-the-smallest-useful-request">
  ## 가장 작고 유용한 요청부터 시작하기
</div>

가장 좋은 출발점은 `highlights: true`를 함께 쓰는 자연어 질의입니다. Exa는 각 결과의 excerpt 길이를 관련성에 맞춰 조절하므로, 따로 조정할 character budget이 없습니다:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      contents={"highlights": True},
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search(
    "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
    { contents: { highlights: true } }
  );
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      "contents": { "highlights": true }
    }'
  ```
</CodeGroup>

이렇게 하면 순위가 매겨진 페이지와 함께, 질의에 관련된 페이지별 토큰 효율적인 컨텍스트를 얻을 수 있습니다.

추가 매개변수는 필요할 때만 더하세요:

| 매개변수                       | 추가하는 경우                                  |
| -------------------------- | ---------------------------------------- |
| `type`                     | 지연 시간 예산이나 탐색 깊이 요구사항에 맞춰 조정할 때          |
| `numResults`               | 컨텍스트 창을 줄이려고 페이지 수를 줄이거나, 재현율을 넓히려고 늘릴 때 |
| `outputSchema`             | 결과를 종합하거나 JSON으로 구조화할 때                  |
| `maxAgeHours`              | 캐시된 page content가 너무 오래되었을 수 있을 때        |
| `highlights.maxCharacters` | 애플리케이션에 페이지당 고정된 excerpt limit이 필요할 때    |
| 도메인 또는 날짜 필터               | 제약을 벗어난 결과는 쓸 수 없을 때                     |

<div id="search-vs-deep-search">
  ## Search와 Deep Search 비교
</div>

표준 search는 질의에 해당하는 페이지를 찾아 순위를 매깁니다. Deep Search는 반복적으로 검색하고, 찾은 내용을 살펴보고, 검색을 다듬은 뒤, 근거에 기반한 결과를 종합하는 리서치 과정을 실행합니다.

| 필요한 작업                                                                    | 시작점                                 |
| ------------------------------------------------------------------------- | ----------------------------------- |
| 잘 정리된 질의에 대한 순위가 매겨진 페이지                                                  | `auto` 또는 `fast`                    |
| 까다로운 검색, 여러 결과에 걸친 종합, 또는 단일 search로는 채울 수 없는 structured output(3개 이상 필드) | `deep`                              |
| 장시간 실행되는 리서치, list building, 또는 다단계 enrichment                            | [Exa Agent](/ko/docs/agent/quickstart) |

`outputSchema`를 사용할 때는 기본적으로 deep 모드를 권장합니다. 전체 사용법과 예시는 [Deep Search 가이드](/ko/docs/search/deep-search)를 참고하세요.

<div id="improve-retrieval-quality">
  ## retrieval 품질 개선하기
</div>

결과를 개선해야 할 때는 요청을 한 번에 한 부분씩만 변경하세요.

<Steps>
  <Step title="질의를 명확히 하기">
    키워드를 나열하지 말고 원하는 페이지를 설명하세요. 주제와 함께 출처 유형, 기간 등 무엇이 적합한
    결과인지를 좌우하는 세부 정보를 포함하세요.

    ```text theme={null}
    Benchmark papers evaluating long-context retrieval methods on legal documents
    ```
  </Step>

  <Step title="응답을 층층이 살펴보기">
    요청을 변경하기 전에 제목, URL, 게시 날짜, highlights를 살펴보세요.

    ```json theme={null}
    {
      "results": [
        {
          "title": "Long-Context Retrieval Methods on Legal Documents",
          "url": "https://arxiv.org/abs/2608.00000",
          "publishedDate": "2026-08-26T00:00:00.000Z",
          "highlights": [
            "We compare long-context retrieval methods across legal document benchmarks..."
          ]
        }
      ]
    }
    ```

    제목과 URL은 Exa가 retrieval한 출처의 종류를, `publishedDate`는 최신성을,
    highlight는 질의에 부합한 evidence를 보여줍니다. 다른 페이지를 retrieval하려면 질의를 다듬고,
    기간을 좁히려면 날짜 필터를 추가하고, 유용한 결과에서 더 많은 맥락이 필요하면 전체 본문을
    가져오세요.
  </Step>

  <Step title="반드시 필요한 제약만 추가하기">
    `includeDomains`, `excludeDomains`, publication-date filters는 해당 제약을 위반하는 결과를
    아예 쓸 수 없는 경우에만 사용하세요. retrieval 관련 선호 사항은 질의에 담고, 합성할 때는
    응답 지침을 `systemPrompt`에 넣으세요.
  </Step>

  <Step title="search mode는 마지막에 변경하기">
    지연 시간 요건이 있으면 더 빠른 모드를, retrieval 과정 자체에 반복과 추론이 필요하면
    deep 모드를 사용하세요. 모드를 바꾼다고 해서 불충분하게 정의된 질의가 보완되지는 않습니다.
  </Step>
</Steps>

튜닝하는 동안에는 대표적인 질의를 소규모 집합으로 유지하세요. 하나의 예시에 최적화하지 말고, 이 집합 전반에서 결과 관련성과 후속 작업의 성공률을 비교하세요. 회귀를 재현할 수 있도록 `requestId`, `searchTime`, `costDollars`를 기록해 두세요.

<div id="budget-latency-and-context">
  ## 지연 시간과 컨텍스트 예산 관리
</div>

각 제어 요소는 서로 다른 자원을 소모합니다:

| 제어 요소                     | 추가로 드는 비용                   |
| ------------------------- | --------------------------- |
| 결과 수 증가                   | 더 많은 페이지, 응답 데이터, 후속 컨텍스트   |
| 전체 텍스트                    | 더 넓은 페이지 컨텍스트와 더 커진 payload |
| `summary`                 | 결과당 언어 모델 호출 1회 추가          |
| `outputSchema`            | 검색된 결과 전반에 대한 synthesis     |
| `contents.maxAgeHours: 0` | 캐시된 콘텐츠 대신 페이지를 새로 가져오는 작업  |
| deep search type          | 반복적인 search, synthesis, 추론  |

캐시된 콘텐츠를 써도 무방한 실시간 경로라면, 지연 시간이 가장 짧은 모드를 highlights 및 캐시 전용 콘텐츠와 조합하세요:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent product updates from major AI labs",
      type="instant",
      contents={
          "highlights": True,
          "max_age_hours": -1,
      },
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search("Recent product updates from major AI labs", {
    type: "instant",
    contents: {
      highlights: true,
      maxAgeHours: -1
    }
  });
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent product updates from major AI labs",
      "type": "instant",
      "contents": {
        "highlights": true,
        "maxAgeHours": -1
      }
    }'
  ```
</CodeGroup>

페이지 freshness가 정확성을 좌우하는 경우에는 이 방식을 쓰지 마세요. 제품에 측정된 지연 시간 목표가 없다면 `auto`와 기본 freshness로 시작하세요.

Exa가 전체 결과 집합에 하나의 컨텍스트 예산을 배분하도록 — 신뢰도 높은 출처에는 더 많이, 중복된 출처에는 더 적게 — 하려면 [Dynamic Highlights 리서치 프리뷰](/ko/docs/search/highlights#dynamic-highlights)를 참고하세요.

<div id="tips-for-common-use-cases">
  ## 일반적인 사용 사례별 팁
</div>

| 필요한 경우                   | 사용할 것                                                          | 피할 것                              |
| ------------------------ | -------------------------------------------------------------- | --------------------------------- |
| 더 최근에 발행된 자료             | 질의에 기간을 명시하거나 publication-date filters 사용                      | `maxAgeHours`                     |
| 자주 바뀌는 페이지의 최신 콘텐츠       | `contents.maxAgeHours`                                         | publication-date filters          |
| 특정 유형의 출처 선호             | 질의 표현 방식, 합성 시에는 `systemPrompt`                                | 엄격한 도메인 허용 목록                     |
| 승인된 출처에서만 얻은 결과          | `includeDomains`                                               | 질의에서 `site:` 반복 사용                |
| 작은 규모의 structured output | 표준 search에 `outputSchema` 사용                                   | 출력이 JSON이라는 이유만으로 Deep 선택         |
| 여러 item을 조사한 출력          | `deep`와 `outputSchema`, 또는 [Exa Agent](/ko/docs/agent/quickstart) | 한 번의 retrieval로 모든 item이 수집되리라 기대 |
| 소수 페이지에서 더 많은 맥락         | highlights를 포함한 search 후 Contents 호출                           | 모든 결과의 전체 텍스트 가져오기                    |
| 더 낮은 지연 시간               | 간결한 콘텐츠로 `fast` 또는 `instant` 측정                                | 기본적으로 freshness나 synthesis 제어 추가  |

| 작업                                      | 사용할 endpoint                          |
| --------------------------------------- | ------------------------------------- |
