Exa Agent는 리스트 구축, enrichment, 딥 리서치처럼 연산량이 많은 작업을 위한 비동기 사용량 기반 엔드포인트입니다. 복잡한 추론을 처리하며 다수의 structured output field를 반환할 수 있습니다.

컨텍스트 agent라고 생각하면 됩니다. 원하는 데이터와 그 데이터를 받을 형태를 설명하면, Exa Agent가 그에 필요한 도구 call을 알아서 조율합니다. 한 번의 실행으로 여러 관점에서 search를 병렬로 펼치고, 그 결과 페이지를 읽어 요약하고, 리스트 구축을 병렬 실행되는 하위 작업으로 나누고, 각 후보를 criteria에 비추어 검증하고, 연락처를 enrich하고, attach한 [Exa Connect](/ko/docs/agent/connect/overview) data partners에 질의할 수 있습니다. `/search`와 `/contents` call을 하나하나 직접 조율할 필요 없이, 취합된 컨텍스트를 하나의 근거 기반 구조화된 결과로 받게 됩니다.

각 실행은 자연어 답변, schema 검증을 거친 JSON, field 수준 grounding, metadata, 비용 내역을 반환할 수 있습니다. 완료된 실행을 나중에 조회하거나, 과거 실행 목록을 확인하거나, 이벤트를 replay하거나, 이전 실행에서 이어서 진행할 수 있습니다.

<Tip>
  MCP를 선호하시나요? Exa Agent와 [Exa Connect](/ko/docs/agent/connect/overview)는 [Exa MCP](/ko/docs/get-started/exa-mcp#exa-agent)에서 사용할 수 있습니다. `tools=agent_run`을 활성화하면 Claude, Cursor 등 MCP clients에서 다단계 리서치, 리스트 빌딩, enrichment, structured output을 실행할 수 있습니다.
</Tip>

<div id="when-to-use-exa-agent">
  ## Exa Agent를 사용해야 할 때
</div>

단일 search나 extraction call만으로는 부족한 워크플로우, 또는 데이터를 모으기 위해 searches, 페이지 읽기, verification 단계를 직접 loop로 작성해야 하는 상황이라면 Exa Agent를 사용하세요.

* 개방형 criteria로 목록을 구성한 뒤 각 result를 enrich
* citations와 함께 여러 fields에 걸쳐 엔티티를 리서치
* &quot;기업을 찾은 다음 그 기업의 의사결정권자 찾기&quot;와 같은 멀티홉 작업 실행
* 장시간 실행되는 웹 리서치 작업에서 구조화된 JSON 생성
* 웹 리서치와 프리미엄 data partners를 하나의 근거 기반 답변으로 결합
* &quot;결과 10개 더 찾기&quot;와 같은 follow-up 요청으로 이전 실행에 이어서 진행

Exa Agent는 설계상 latency가 높고 비동기로 동작합니다. call을 직접 조율하면서 낮은 latency로 단일 search만 수행하면 되는 경우에는 [Search API](/ko/docs/search/quickstart)부터 시작하세요.

실행을 생성할 때 `Accept: text/event-stream`을 추가하면 실행이 queued, started, completed 상태가 될 때마다 server-sent events를 받을 수 있습니다. 자세한 내용은 [Stream events](#stream-events)를 참고하세요.

<div id="4-poll-for-completion">
  ### 4. 완료 폴링
</div>

이벤트를 스트리밍하지 않는 경우, 반환된 `id`를 저장한 뒤 실행이 최종 상태에 도달할 때까지 폴링하세요.

<CodeGroup>
  ```python Python theme={null}
  import json
  from exa_py import Exa

  exa = Exa()
  run_id = "agent_run_01j..."
  run = exa.agent.runs.poll_until_finished(
      run_id,
      poll_interval=4000,
  )

  print(json.dumps(run.model_dump(), indent=2))
  ```

  ```javascript JavaScript theme={null}
  import Exa from "exa-js";

  const exa = new Exa();
  const runId = "agent_run_01j...";
  const run = await exa.agent.runs.pollUntilFinished(runId, {
    pollInterval: 4000
  });

  console.log(JSON.stringify(run, null, 2));
  ```

  ```bash cURL theme={null}
  RUN_ID="agent_run_01j..."

  while true; do
    RUN_JSON="$(curl -s "https://api.exa.ai/agent/runs/$RUN_ID" \
      -H "Authorization: Bearer $EXA_API_KEY")"

    STATUS="$(echo "$RUN_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["status"])')"
    echo "status=$STATUS"

    if [ "$STATUS" = "completed" ] || [ "$STATUS" = "failed" ] || [ "$STATUS" = "cancelled" ]; then
      echo "$RUN_JSON"
      break
    fi

    sleep 4
  done
  ```
</CodeGroup>

완료된 실행에는 다음이 포함됩니다:

* `output.text`: 자연어 답변
* `output.structured`: `outputSchema`를 제공한 경우 검증된 JSON
* `output.grounding`: 텍스트 또는 구조화된 field에 대한 citations(생성된 경우)
* `costDollars`: 해당 실행의 비용 내역

<Note>
  Exa Agent는 OpenAI 호환 Responses API를 통해서도 사용할 수 있습니다. OpenAI SDK의
  엔드포인트를 `https://api.exa.ai`로 지정하고 `model: "exa-agent"`를 사용한 뒤,
  동기, 스트리밍, 백그라운드 실행 중 하나를 선택하세요. 자세한 내용은 [OpenAI SDK
  호환성](/ko/docs/integrations/openai-sdk#agent-via-responses-api) 문서를 참고하세요.
</Note>

<div id="stream-events">
  ## Stream events
</div>

스트리밍은 생성 요청을 열어 둔 상태로 유지하면서 실행이 완료될 때까지 Server-Sent Events(SSE)를 전송합니다. 이벤트 유형과 payload는 [Event format](#event-format)을 참고하세요.

Python에서는 `stream=True`, JavaScript에서는 `stream: true`를 설정하거나, HTTP에서는 `Accept: text/event-stream` 헤더를 전송하세요:

<CodeGroup>
  ```python Python theme={null}
  from exa_py import Exa

  exa = Exa()
  events = exa.agent.runs.create(
      query="Find five recently launched developer tools for evaluating AI agents.",
      stream=True,
  )

  for event in events:
      print(event.event, event.data)
  ```

  ```javascript JavaScript theme={null}
  import Exa from "exa-js";

  const exa = new Exa();
  const events = await exa.agent.runs.create({
    query: "Find five recently launched developer tools for evaluating AI agents.",
    stream: true
  });

  for await (const event of events) {
    console.log(event.event, event.data);
  }
  ```

  ```bash cURL theme={null}
  curl -N -X POST "https://api.exa.ai/agent/runs" \
    -H "Content-Type: application/json" \
    -H "Accept: text/event-stream" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Find five recently launched developer tools for evaluating AI agents."
    }'
  ```
</CodeGroup>

<div id="event-format">
  ### 이벤트 형식
</div>

각 SSE 프레임에는 이벤트 ID, 이벤트 이름, JSON payload가 포함됩니다:

```text theme={null}
id: 1
event: agent_run.created
data: {"id":"agent_run_01j...","status":"queued","createdAt":"2026-05-07T21:21:52.051Z"}
```

스트리밍에는 `: keep-alive`와 같은 주석 줄이 포함될 수도 있습니다. SSE client는 주석을 자동으로 무시하며, 직접 구현한 파서도 동일하게 처리해야 합니다.

<div id="event-types">
  ### Event types
</div>

| 이벤트                   | `data` payload                        | 사용 방법                                                                                               |
| --------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `agent_run.created`   | `{ id, status: "queued", createdAt }` | 요청이 수락되는 즉시 실행 ID를 저장하세요.                                                                           |
| `agent_run.started`   | `{ id, status: "running" }`           | 실행이 처리 중임을 표시하세요.                                                                                   |
| `agent_run.completed` | 완료된 Agent 실행 객체                       | `data.output.text` 또는 `data.output.structured`에서 최종 답변을, `data.output.grounding`에서 citations를 읽으세요. |
| `agent_run.failed`    | `{ id, status: "failed", error }`     | `error.code`와 `error.message`를 노출하세요. 완료된 output은 제공되지 않습니다.                                        |
| `agent_run.cancelled` | `{ id, status: "cancelled", ... }`    | 스트리밍 수신을 중단하고 해당 실행을 취소된 것으로 처리하세요.                                                                 |

동일한 리서치 단계에 속한 이벤트에는 `callId`가 포함됩니다. 이는 도구 진행 이벤트의 `item.call_id`에 해당합니다. 이 값을 사용해 search 추적, 소스, 도구 진행 상황을 그룹화하세요. 일부 search 추적 설명은 비동기적으로 생성되므로 해당 설명이 가리키는 소스나 도구 이벤트보다 늦게 도착할 수 있습니다. 따라서 도착 순서만으로 연관 짓지 마세요.

`agent_run.source.added`는 완전한 citation 목록이 아니라 실시간 미리보기로 취급하세요. 최종 상태 실행의 `output.grounding`이 신뢰할 수 있는 기준이 되는 grounding output입니다.

<div id="replay-stored-events">
  ### 저장된 이벤트 replay
</div>

ZDR이 아닌 실행의 경우 [`GET /agent/runs/{id}/events`](/ko/docs/reference/agent-api/list-run-events)는 저장된 이벤트를 페이지네이션된 JSON으로 반환합니다. 저장된 이벤트를 SSE로 replay하려면 `Accept: text/event-stream`을, client가 이미 처리한 이벤트를 건너뛰려면 `Last-Event-ID`를 함께 보내세요:

```bash cURL theme={null}
curl -N "https://api.exa.ai/agent/runs/agent_run_01j.../events" \
  -H "Accept: text/event-stream" \
  -H "Last-Event-ID: 12" \
  -H "Authorization: Bearer $EXA_API_KEY"
```

리플레이 엔드포인트는 요청 시점에 저장되어 있던 이벤트를 전송한 뒤 연결을 종료하며, 진행 중인 실행을 계속 따라가지는 않습니다. ZDR 실행은 이벤트를 보관하지 않으므로 리플레이할 수 없습니다.

향후 호환성을 위해, 애플리케이션이 인식하지 못하는 이벤트 이름은 무시하고 종료 이벤트가 도착할 때까지 계속 처리하세요.

<div id="pricing">
  ## Pricing
</div>

비용은 사용량 기반이며 구성 요소별로 가격이 책정됩니다:

| 구성 요소               | 가격                |
| ------------------- | ----------------- |
| Agent Compute Units | `1 ACU = $0.10`   |
| search 도구 호출        | `$0.005 / search` |

<Note>
  Contact enrichment은 위의 핵심 가격 구성 요소와 별개입니다. 이메일 contact enrichment는 `$0.02 / email`, 전화번호 contact enrichment는 `$0.07 / phone number`입니다.
</Note>

`usage.agentComputeUnits`는 실행 전체에 걸친 모델 연산량을 측정합니다. 복잡한 쿼리, 특히 `input.data` field가 큰 쿼리는 더 많은 추론 단계와 도구 호출이 필요해 ACU를 더 많이 소비합니다.

concurrency 및 속도 제한은 [Agent limits](/ko/docs/admin/billing#agent-limits)를 참고하세요.

<div id="effort">
  ### Effort
</div>

`effort`로 각 실행의 비용과 추론 수준을 선택할 수 있습니다. 지원되는 값은 `minimal`, `low`, `medium`, `high`, `xhigh`, `auto`, `max`이며 기본값은 `auto`입니다. 고정 effort는 요청당 가격이 일정하게 정해져 있고, `auto`와 베타 단계인 `max`는 사용량에 따라 과금됩니다:

| Effort    | 가격                            |
| --------- | ----------------------------- |
| `minimal` | `$0.012 / request`            |
| `low`     | `$0.025 / request`            |
| `medium`  | `$0.10 / request`             |
| `high`    | `$0.50 / request`             |
| `xhigh`   | `$1.00 / request`             |
| `auto`    | 사용량 과금; 기본 상한 `$5`까지          |
| `max`     | **베타**, 사용량 과금; 기본 상한 `$20`까지 |

<Info>
  Agent Max는 대규모 리스트 구축, 여러 소스를 아우르는 deep 리서치, 검증하기 어려운
  criteria처럼 latency나 비용보다 완결성과 철저함이 더 중요한 작업을 위한 최고 effort
  등급입니다. 현재 퍼블릭 베타 단계이며, `effort: "max"`를 사용하는 요청에는
  `Exa-Beta: agent-max-effort-2026-07-27`을 포함해야 합니다. 이 header에는 쉼표로 구분된
  베타 토큰 목록을 지정할 수 있습니다.
</Info>

`budget.maxCostDollars`는 `auto`와 `max`에 적용되는 선택적 실행당 상한입니다. `$1`–`$100` 범위를 허용하며, 제공되는 최대값은 `$100`이지만 서버에서 더 낮은 최대값을 설정할 수도 있습니다. 기본 상한은 `auto`가 `$5`, `max`가 `$20`입니다. 이는 고정 가격이 아니라 상한이므로, 일찍 끝난 실행은 비용이 그만큼 적게 듭니다. 고정 effort에는 budget을 지정할 수 없습니다.

<div id="choosing-an-effort-mode">
  ### effort 모드 선택하기
</div>

고정 effort 모드는 표준 리서치에서 요청당 비용을 예측 가능하게 유지하고 싶을 때 적합합니다. 요청마다 entity 수가 달라질 수 있는 리스트 구축처럼 범위가 가변적인 작업에는 `auto`를 사용하세요.

| Effort    | 적합한 용도                               | 권장 schema 복잡도                          | 예상 실행 시간          |
| --------- | ------------------------------------ | -------------------------------------- | ----------------- |
| `minimal` | 최저 비용 조회, 매우 좁은 범위의 사실 확인 작업, 짧은 답변  | field 한두 개, 얕은 schema                  | 가장 저렴하고 가장 덜 철저함  |
| `low`     | 단순 조회, 좁은 범위의 사실 확인 작업, 짧은 답변        | 소수의 field, 얕은 schema                   | 빠르고 가벼운 리서치       |
| `medium`  | 대부분의 표준 리서치 작업의 기본 출발점               | 중간 정도의 field 수, 단순한 중첩 객체              | 품질과 실행 시간의 균형     |
| `high`    | 더 어려운 리서치, 더 많은 citations, 더 엄격한 완결성 | 더 큰 schema 또는 더 섬세한 field              | 더 느리고 더 철저함       |
| `xhigh`   | 비용이나 latency보다 완결성이 중요한 고가치 작업       | 복잡한 schema, 많은 field, 어려운 verification | 고정 effort 중 가장 느림 |
| `auto`    | 범위가 가변적인 작업, 리스트 구축, 난이도를 알 수 없는 작업  | 유연함. entity 수나 필요한 작업량을 알 수 없을 때 유용    | 가변적               |
| `max`     | 최고 수준의 effort 리서치 (베타)               | 복잡한 schema, 많은 field, 어려운 verification | 가장 오래 실행됨         |

표준적인 단일 entity 리서치는 `medium`으로 시작하세요. 완결성보다 비용과 latency가 더 중요하다면 `low`나 `minimal`로 낮추세요. output schema가 더 크거나, field에 verification이 필요하거나, 작업에 더 깊은 추론이 필요하다면 `high`나 `xhigh`로 올리세요. 리스트 구축이나 많은 entity를 반환할 수 있는 워크플로우처럼 범위를 미리 알 수 없는 경우에는 `auto`를 사용하세요.

실행 시간은 질의 난이도, schema 복잡도, 외부 소스의 가용성에 따라 달라집니다. effort 모드는 엄격한 latency 보장이 아니라 품질과 비용, 실행 시간 사이의 절충으로 이해하세요.

<div id="zero-data-retention">
  ## Zero Data Retention
</div>

Exa Agent는 [Zero Data Retention](/ko/docs/admin/security/zero-data-retention)(ZDR)을 지원합니다. ZDR은 team 단위로 활성화됩니다. 계정에 적용하려면 [문의해 주세요](mailto:sales@exa.ai).

team에 ZDR이 활성화되면:

* 스트리밍(`Accept: text/event-stream`)으로 실행을 생성해 output을 실시간으로 받아보거나, 보존 기간 내에 비동기 실행을 폴링하세요.
* 실행 데이터는 실행이 진행되는 동안, 그리고 종료 상태에 도달한 후 최대 10분 동안 이용할 수 있습니다. 이 기간이 지나면 해당 실행은 조회할 수 없습니다.
* `previousRunId`는 사용할 수 없습니다.
* Exa Connect `dataSources`는 사용할 수 없으며, 이를 포함한 요청은 `400` 오류를 반환합니다.
