# エラーコード {#error-codes}

> Exa API で使用される主なエラーコードのリファレンス

Exa API は、リクエストが失敗した場合、標準の HTTP ステータスコードと JSON 形式のエラーボディを返します。

## HTTP ステータスコード {#http-status-codes}

| コード                         | 意味                                                                                  | 対処方法                                                                   |
| --------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `400` Bad Request           | ボディ、クエリパラメータ、ヘッダー、またはオプションの組み合わせが無効です。                                              | 返されたメッセージを参考にリクエストを修正してください。                                           |
| `401` Unauthorized          | API キーが指定されていないか、無効です。                                                              | 認証ヘッダーと API キーを確認してください。                                               |
| `402` Payment Required      | クレジットを使い切ったか、利用予算を超過しました。                                                           | [クレジットをチャージする](https://dashboard.exa.ai)か、チームの管理者にお問い合わせください。          |
| `403` Forbidden             | API キーに要求された機能へのアクセス権がないか、ポリシーによってリクエストがブロックされました。                                  | 返されたメッセージと、ご利用のプランで利用可能な機能を確認してください。                                   |
| `404` Not Found             | ルートまたは要求されたリソースが存在しません。                                                             | エンドポイントとリソース ID を確認してください。                                             |
| `409` Conflict              | リクエストが既存の状態と競合しています。たとえば、同じ `externalId` を持つ Webset がすでに存在する場合などです。                 | 既存のリソースを取得するか、別の識別子を使用してください。                                          |
| `422` Unprocessable Entity  | Websets のプレビュークエリを有効なエンティティと条件に分解できませんでした。                                          | プレビュークエリの表現を変えてください。                                                   |
| `429` Too Many Requests     | API キー、チーム、またはネットワークがレート上限または同時実行数の上限を超えました。                                        | リクエストレートを下げてください。`Retry-After` がある場合はその秒数だけ待機し、ない場合は指数バックオフを使用してください。  |
| `500` Internal Server Error | 予期しないサーバーエラーが発生しました。                                                                | 少し時間をおいてから再試行してください。問題が解決しない場合はサポートにお問い合わせください。                        |
| `503` Service Unavailable   | Exa が一時的に処理能力の上限に達している (`SERVICE_OVERLOADED`) か、利用できない状態です。リクエストは処理されておらず、課金もされません。 | 指数バックオフを使用して再試行してください。このエラーはリクエストレートとは無関係なため、レートを下げても解消しません。再試行してください。 |
| `504` Gateway Timeout       | リクエストが処理期限を超過しました。                                                                  | リクエストを再試行するか、スコープを絞り込んでください。                                           |

<Note>
  `/contents` の URL 単位の失敗は、リクエストレベルのエラーではなく、成功した `200` レスポンスの `statuses` フィールドで報告されます。詳しくは[コンテンツ取得ステータスタグ](#content-fetch-status-tags)を参照してください。
</Note>

## エラーレスポンスの構造 {#error-response-structure}

エラーレスポンスには、`requestId`、人が読める形式の `error` メッセージ、機械可読な `tag` が含まれます。

```json theme={null}
{
  "requestId": "67207943fab9832d162b5317f4cca830",
  "error": "Invalid request body | Validation error: Invalid value for type",
  "tag": "INVALID_REQUEST_BODY"
}
```

<Note>
  サポートへのお問い合わせ時に `requestId` を添えていただくと、トラブルシューティングをより迅速に行えます。
</Note>

タグの種類は固定されておらず、今後追加される可能性があります。また、タグ名を見ればその意味がわかるようになっています。まず HTTP ステータスコードで分岐し、未知のタグは解析エラーではなく補足情報として扱ってください。

## 主なエラータグ {#common-error-tags}

### アカウント、課金、アクセス {#account-billing-and-access}

| タグ                        | HTTP コード | 説明                                                                            |
| ------------------------- | -------- | ----------------------------------------------------------------------------- |
| `INVALID_API_KEY`         | `401`    | API キーが指定されていないか、空か、無効です。                                                     |
| `NO_MORE_CREDITS`         | `402`    | アカウントのクレジット残高がありません。[dashboard.exa.ai](https://dashboard.exa.ai) でチャージしてください。 |
| `API_KEY_BUDGET_EXCEEDED` | `402`    | API キーが利用予算を超過しました。チーム管理者にお問い合わせください。                                         |
| `TEAM_BUDGET_EXCEEDED`    | `402`    | チームが現在の課金期間の利用予算を超過しました。                                                      |
| `FEATURE_DISABLED`        | `403`    | リクエストされたエンドポイント、検索タイプ、またはオプションは、ご利用のプランでは有効になっていません。                          |
| `PROHIBITED_CONTENT`      | `403`    | コンテンツ安全性モデレーションによりリクエストが拒否されました。                                              |
| `CONTENT_FILTER_ERROR`    | `403`    | 処理中にコンテンツが安全性ポリシーにより拒否されました。                                                  |
| `RATE_LIMIT_EXCEEDED`     | `429`    | API キー、チーム、またはネットワークに設定されたレート制限を超過しました。リクエストレートを下げてください。                      |
| `SERVICE_OVERLOADED`      | `503`    | Exa が一時的に処理能力の上限に達しているため、リクエストは処理前に破棄されました。指数バックオフで再試行してください。                 |

### リクエストの検証 {#request-validation}

| タグ                        | HTTP コード | 説明                                                  |
| ------------------------- | -------- | --------------------------------------------------- |
| `INVALID_REQUEST_BODY`    | `400`    | JSON ボディがスキーマ検証に失敗しました。                             |
| `INVALID_REQUEST`         | `400`    | オプション同士が競合しているか、`Exa-Beta` ヘッダーを指定せずにベータ機能が使用されました。 |
| `INVALID_NUM_RESULTS`     | `400`    | ハイライトをリクエストする場合、`numResults` は 100 以下にする必要があります。    |
| `NUM_RESULTS_EXCEEDED`    | `400`    | リクエストされた結果数がプランの上限を超えています。                          |
| `INVALID_JSON_SCHEMA`     | `400`    | 指定された出力スキーマが無効です。                                   |
| `SUBPAGES_LIMIT_EXCEEDED` | `400`    | `/contents` で取得できるサブページは、1 リクエストあたり最大 100 件です。      |

### 決済プロトコル {#payment-protocols}

x402 または MPP で支払うリクエストでは、次のエラーも返される場合があります。

| タグ                         | HTTP コード | 説明                            |
| -------------------------- | -------- | ----------------------------- |
| `X402_PAYMENT_REQUIRED`    | `402`    | 支払いが必要です。                     |
| `X402_INVALID_SIGNATURE`   | `400`    | x402 の支払い署名が無効です。             |
| `X402_VERIFICATION_FAILED` | `402`    | x402 の支払いを検証できませんでした。         |
| `MPP_VERIFICATION_FAILED`  | `402`    | MPP の支払いを検証できませんでした。          |
| `X402_TOO_MANY_UNPAID`     | `429`    | 支払い待ちの x402 リクエストが多すぎます。      |
| `X402_WALLET_RATE_LIMITED` | `429`    | x402 ウォレットがレート制限を超えました。       |
| `X402_INTERNAL_ERROR`      | `500`    | Exa が x402 の支払い要件を作成できませんでした。 |

## コンテンツ取得のステータスタグ {#content-fetch-status-tags}

`/contents` に複数の URL を渡した場合、一部の URL だけが失敗し、他の URL は成功することがあります。URL 単位の失敗は `statuses` フィールドで返され、リクエスト全体が失敗することはありません。

```json theme={null}
{
  "results": [],
  "statuses": [
    {
      "id": "https://example.com",
      "status": "error",
      "error": {
        "tag": "CRAWL_NOT_FOUND",
        "httpStatusCode": 404
      }
    }
  ]
}
```

`httpStatusCode` は対象ページのステータスを示すもので、`/contents` のレスポンスのステータスではありません。

| タグ                        | 説明                                            | 対処方法                                               |
| ------------------------- | --------------------------------------------- | -------------------------------------------------- |
| `CRAWL_NOT_FOUND`         | 対象ページが見つかりませんでした。                             | URL が正しく、アクセス可能であることを確認してください。                     |
| `CRAWL_HTTP_{status}`     | 対象ページが HTTP エラーを返しました (例: `CRAWL_HTTP_403`) 。 | タグに含まれる対象ページのステータスに応じて対処してください。                    |
| `CRAWL_TIMEOUT`           | 対象ページの取得中にクロールがタイムアウトしました。                    | リクエストを再試行するか、しばらくしてから再度お試しください。                    |
| `CRAWL_LIVECRAWL_TIMEOUT` | ライブ取得が、指定した `livecrawlTimeout` を超えました。        | `livecrawlTimeout` を延長するか、`maxAgeHours` を調整してください。 |
| `SOURCE_NOT_AVAILABLE`    | ソースへのアクセスが禁止されているか、ソースを利用できません。               | ソースで認証が必要でないか、アクセスが制限されていないかを確認してください。             |
| `UNSUPPORTED_URL`         | この URL スキームはコンテンツ取得に対応していません。                 | 標準的な HTTP または HTTPS の URL を使用してください。               |
| `CRAWL_UNKNOWN_ERROR`     | その他の理由でクロールに失敗しました。                           | リクエストを再試行してください。問題が解決しない場合はサポートにお問い合わせください。        |

これらのステータスタグは `/contents` 固有のものです。`/search` は `statuses` フィールドを返しません。

## サポートを受ける {#getting-help}

* `500`、`503`、`504` エラーが続く場合は、[Exa Status](/ja/docs/admin/status) を確認してください。
* 現在の上限値は [レート制限](/ja/docs/admin/billing#rate-limits) で確認できます。
* リクエストの要件については、各エンドポイントの [API リファレンス](/ja/docs/reference/search) を参照してください。
* レスポンスのステータス、エラーボディ、`requestId` を添えて、[hello@exa.ai](mailto:hello@exa.ai) までお問い合わせください。
