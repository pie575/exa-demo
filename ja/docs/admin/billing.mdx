<div id="billing-basics">
  ## 課金の基本
</div>

リクエストの料金は、[料金](/ja/docs/admin/pricing)に記載の単価またはEnterprise契約の条件に基づき、前払いのクレジットから差し引かれます。チームのオーナーは[請求ダッシュボード](https://dashboard.exa.ai/billing)からクレジットを追加できます。支払いはStripeで処理されます。

チームのクレジットを使い切ると、リクエストは`402 Payment Required`を返します。割り当てられた予算の上限に達したAPIキーでも`402`が返されます。クレジットを追加するか、チームの管理者にキーの予算を調整するよう依頼してください。詳しくは[エラーコード](/ja/docs/admin/error-codes)を参照してください。

APIキーごとの過去の使用量を確認するには、[Get API key usage](/ja/docs/reference/team-management/get-api-key-usage)を使用します。

<div id="rate-limits">
  ## レート制限
</div>

レート制限は1秒あたりのクエリ数 (QPS) で計測され、個々のAPIキー単位ではなく、チームのすべてのAPIキーを合算したチーム全体に適用されます。[API Keys](https://dashboard.exa.ai/api-keys)ページでは個々のキーにより低い制限を設定できますが、そのキーのトラフィックもチームの制限に含まれます。

| エンドポイント                                                  | デフォルトの制限          |
| -------------------------------------------------------- | ----------------- |
| `/search`、`/answer`、`/chat/completions`                  | 10 QPS            |
| `type` が `deep-lite`、`deep`、`deep-reasoning` の `/search` | 5 QPS             |
| `/contents`                                              | 100 QPS           |
| `/agent/runs`、`/responses`                               | 5 QPS、アクティブな実行50件 |
| `/websets/*`                                             | 20 QPS            |

一部のエンドポイントは、レート制限の枠を共有しています。制限は予告なく変更される場合があり、プランによって異なることもあります。また、Websetsの検索にはプランごとの同時実行数の制限もあります。この制限は[Get Team Info](/ja/docs/websets/api/teams/get-team-info)で確認できます。

制限を超えると、リクエストは`429 Too Many Requests`を返します。`Retry-After`ヘッダーがある場合は指定された時間待機し、ない場合は指数バックオフで再試行してください。詳しくは[エラーコード](/ja/docs/admin/error-codes)を参照してください。

<div id="agent-limits">
  ### Agent の制限
</div>

Agent の制限は、同時に進行できる実行の数と、新しい実行を開始できる速度という 2 つの独立した制御で構成されています。

* **同時実行数**: 同時に進行できる Agent の実行は 50 件までです。この制限は QPS とは別に管理されており、QPS を引き上げても変わりません。上限を超えて実行を開始しようとすると、エラーコード `CONCURRENCY_LIMIT_REACHED` とともに `429` が返されます。実行の完了を待つか、同時実行数の上限引き上げについてお問い合わせください。
* **実行の開始**: `POST /agent/runs` はアカウントの QPS を消費し、実行の開始 1 回につき 2 リクエストとしてカウントされます。実行は QPS の半分の速度で開始できるため、デフォルトの 10 QPS のアカウントでは 1 秒あたり 5 件、25 QPS では 1 秒あたり 12 件の実行を開始できます。
* **ポーリング**: 実行のステータス、イベント、実行一覧を取得する `GET` リクエストは QPS にカウントされず、ディスパッチをブロックすることもありません。そのため、新しい実行の開始速度とは関係なく、実行中の Agent をポーリングできます。

<div id="25-qps-on-pay-as-you-go">
  ### 従量課金で25 QPS
</div>

任意の30日間に$1,000分のクレジットを追加すると、チームのレート制限が自動的に**90日間25 QPS**に引き上げられます。この基準額の対象は、消費したクレジットではなく購入したクレジットです。再度条件を満たすと、90日間の期間はリセットされます。進捗状況は[請求ダッシュボード](https://dashboard.exa.ai/billing)で確認できます。

25 QPSを超える処理能力が必要な場合は、[営業チームにお問い合わせください](https://exa.ai/contact/sales)。

<div id="auto-recharge">
  ## 自動チャージ
</div>

自動チャージは、残高が指定したしきい値に達したときにクレジットを自動で購入する機能です。[請求ダッシュボード](https://dashboard.exa.ai/billing)から設定できます。

| 設定           | 説明                                                                |
| ------------ | ----------------------------------------------------------------- |
| **チャージ額**    | 自動チャージが実行されるたびに購入するクレジット額です。$5 から $10,000 まで設定できます。               |
| **チャージしきい値** | チャージが実行される残高です。                                                   |
| **月間上限**     | 請求サイクル中に自動チャージで購入できる金額の上限です (任意) 。上限を設けない場合は $0 に設定するか、空欄のままにします。 |

たとえば、チャージ額を $100、しきい値を $10、月間上限を $500 に設定すると、残高が $10 に達するたびに $100 分が購入されます。サイクル中の自動購入額は最大 $500 です。

ローンチを控えている場合など、大量の処理が見込まれるときは、事前に十分なクレジットを追加しておきましょう。また、少額の支払いが何度も発生しないよう、自動チャージ額を適切に設定してください。

<div id="receipts-and-invoices">
  ## 領収書と請求書
</div>

Exa は、クレジット購入および自動チャージの領収書を [billing@exa.ai](mailto:billing@exa.ai) からメールでお送りします。必要に応じて、このアドレスを許可リストに追加してください。請求書の履歴はすべて [請求ダッシュボード](https://dashboard.exa.ai/billing)で確認できます。

請求書による後払いは、Enterprise プランでご利用いただけます。
