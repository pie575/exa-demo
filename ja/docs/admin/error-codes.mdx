Exa API は、標準的な HTTP ステータスコードと JSON 形式のエラーボディでエラーを通知します。

## HTTP ステータスコード {#http-status-codes}

| コード                         | 意味                                                                                  | 対処方法                                                                  |
| --------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `400` Bad Request           | ボディ、クエリパラメーター、ヘッダー、またはオプションの組み合わせが無効です。                                             | 返されたメッセージに従ってリクエストを修正してください。                                          |
| `401` Unauthorized          | API キーが指定されていないか、無効です。                                                              | 認証ヘッダーと API キーを確認してください。                                              |
| `402` Payment Required      | クレジットを使い切ったか、利用上限額を超過しました。                                                           | [クレジットをチャージ](https://dashboard.exa.ai)するか、チーム管理者にお問い合わせください。          |
| `403` Forbidden             | API キーに要求された機能へのアクセス権がないか、ポリシーによってリクエストがブロックされました。                                  | 返されたメッセージと、ご利用のプランで利用可能な機能を確認してください。                                  |
| `404` Not Found             | ルートまたは要求されたリソースが存在しません。                                                             | エンドポイントとリソース ID を確認してください。                                            |
| `409` Conflict              | リクエストが既存の状態と競合しています。たとえば、同じ `externalId` を持つ Webset がすでに存在する場合などです。                 | 既存のリソースを取得するか、別の識別子を使用してください。                                         |
| `422` Unprocessable Entity  | Websets のプレビュークエリを、有効なエンティティと基準に分解できませんでした。                                         | プレビュークエリの表現を変えてください。                                                  |
| `429` Too Many Requests     | API キー、チーム、またはネットワークがレート制限または同時実行数の制限を超えました。                                        | リクエストレートを下げてください。`Retry-After` がある場合はその秒数だけ待機し、ない場合は指数バックオフを使用してください。 |
| `500` Internal Server Error | 予期しないサーバーエラーが発生しました。                                                                | 少し時間をおいてから再試行してください。問題が解決しない場合はサポートにお問い合わせください。                       |
| `503` Service Unavailable   | Exa が一時的に処理能力の上限に達している (`SERVICE_OVERLOADED`) か、利用できない状態です。リクエストは処理されておらず、課金もされません。 | 指数バックオフで再試行してください。これはリクエストレートとは無関係なため、レートを下げても解決しません。再試行が有効です。        |
| `504` Gateway Timeout       | リクエストが処理期限を超えました。                                                                   | リクエストを再試行するか、スコープを絞り込んでください。                                          |

<Note>
  `/contents` における URL 単位の失敗は、リクエスト単位のエラーとしてではなく、成功した `200` レスポンスの `statuses` フィールドで報告されます。[コンテンツ取得ステータスタグ](#content-fetch-status-tags)を参照してください。
</Note>

## エラーレスポンスの構造 {#error-response-structure}

エラーレスポンスには、`requestId`、人が読める形式の `error` メッセージ、機械可読な `tag` が含まれます。

```json theme={null}
{
  "requestId": "67207943fab9832d162b5317f4cca830",
  "error": "Invalid request body | Validation error: Invalid value for type",
  "tag": "INVALID_REQUEST_BODY"
}
```

<Note>
  サポートに問い合わせる際は、`requestId` を添えていただくとトラブルシューティングが迅速に進みます。
</Note>

タグの種類は今後追加される可能性があり、タグ名は見ただけで意味がわかるように命名されています。まず HTTP ステータスコードで分岐し、未知のタグは解析エラーとして扱わず、補足情報として扱ってください。

## 主なエラータグ {#common-error-tags}

### アカウント、請求、アクセス {#account-billing-and-access}

| タグ                        | HTTPコード | 説明                                                                            |
| ------------------------- | ------- | ----------------------------------------------------------------------------- |
| `INVALID_API_KEY`         | `401`   | APIキーが指定されていない、空である、または無効です。                                                  |
| `NO_MORE_CREDITS`         | `402`   | アカウントのクレジット残高がありません。[dashboard.exa.ai](https://dashboard.exa.ai) でチャージしてください。 |
| `API_KEY_BUDGET_EXCEEDED` | `402`   | APIキーの利用上限額を超えました。チーム管理者にお問い合わせください。                                          |
| `TEAM_BUDGET_EXCEEDED`    | `402`   | 現在の請求期間におけるチームの利用上限額を超えました。                                                   |
| `FEATURE_DISABLED`        | `403`   | リクエストされたエンドポイント、検索タイプ、またはオプションは、ご利用のプランでは有効になっていません。                          |
| `PROHIBITED_CONTENT`      | `403`   | コンテンツの安全性モデレーションにより、リクエストが拒否されました。                                            |
| `CONTENT_FILTER_ERROR`    | `403`   | 処理中に、安全性ポリシーによってコンテンツが拒否されました。                                                |
| `RATE_LIMIT_EXCEEDED`     | `429`   | APIキー、チーム、またはネットワークに設定されたレート制限を超えました。リクエストレートを下げてください。                        |
| `SERVICE_OVERLOADED`      | `503`   | Exa が一時的に処理能力の上限に達しているため、リクエストは処理前に破棄されました。指数バックオフを用いて再試行してください。              |

### リクエストの検証 {#request-validation}

| タグ                        | HTTP コード | 説明                                                 |
| ------------------------- | -------- | -------------------------------------------------- |
| `INVALID_REQUEST_BODY`    | `400`    | JSON ボディがスキーマ検証に失敗しました。                            |
| `INVALID_REQUEST`         | `400`    | オプション同士が競合しているか、`Exa-Beta` ヘッダーを指定せずにベータ機能を使用しました。 |
| `INVALID_NUM_RESULTS`     | `400`    | ハイライトをリクエストする場合、`numResults` は 100 以下にする必要があります。   |
| `NUM_RESULTS_EXCEEDED`    | `400`    | リクエストした結果数が、ご利用のプランの上限を超えています。                     |
| `INVALID_JSON_SCHEMA`     | `400`    | 指定された出力スキーマが無効です。                                  |
| `SUBPAGES_LIMIT_EXCEEDED` | `400`    | `/contents` で指定できるサブページは、1 リクエストあたり最大 100 件です。     |

### 支払いプロトコル {#payment-protocols}

x402 または MPP で支払われたリクエストでは、次のタグが返されることもあります。

| タグ                         | HTTP コード | 説明                            |
| -------------------------- | -------- | ----------------------------- |
| `X402_PAYMENT_REQUIRED`    | `402`    | 支払いが必要です。                     |
| `X402_INVALID_SIGNATURE`   | `400`    | x402 の支払い署名が無効です。             |
| `X402_VERIFICATION_FAILED` | `402`    | x402 の支払いを検証できませんでした。         |
| `MPP_VERIFICATION_FAILED`  | `402`    | MPP の支払いを検証できませんでした。          |
| `X402_TOO_MANY_UNPAID`     | `429`    | 支払い待ちの x402 リクエストが多すぎます。      |
| `X402_WALLET_RATE_LIMITED` | `429`    | x402 ウォレットがレート制限を超過しました。      |
| `X402_INTERNAL_ERROR`      | `500`    | Exa が x402 の支払い要件を作成できませんでした。 |

## コンテンツ取得ステータスタグ {#content-fetch-status-tags}

`/contents` が複数の URL を受け取った場合、一部の URL が失敗しても他の URL は成功することがあります。URL 単位の失敗は `statuses` フィールドで返され、リクエスト全体が失敗することはありません：

```json theme={null}
{
  "results": [],
  "statuses": [
    {
      "id": "https://example.com",
      "status": "error",
      "error": {
        "tag": "CRAWL_NOT_FOUND",
        "httpStatusCode": 404
      }
    }
  ]
}
```

`httpStatusCode` は対象ページのステータスを表すもので、`/contents` のレスポンスのステータスではありません。

| タグ                        | 説明                                            | 対処方法                                                  |
| ------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| `CRAWL_NOT_FOUND`         | 対象ページが見つかりませんでした。                             | URL が正しく、アクセス可能であることを確認してください。                        |
| `CRAWL_HTTP_{status}`     | 対象ページが HTTP エラーを返しました (例: `CRAWL_HTTP_403`) 。 | タグに含まれる対象ページのステータスコードに応じて対処してください。                    |
| `CRAWL_TIMEOUT`           | 対象ページの取得中にクロールがタイムアウトしました。                    | リクエストを再試行するか、しばらくしてから再度お試しください。                       |
| `CRAWL_LIVECRAWL_TIMEOUT` | ライブ取得の所要時間が、指定した `livecrawlTimeout` を超えました。   | `livecrawlTimeout` の値を大きくするか、`maxAgeHours` を調整してください。 |
| `SOURCE_NOT_AVAILABLE`    | ソースへのアクセスが拒否されたか、ソースを利用できません。                 | ソースで認証が必要か、アクセスが制限されていないかを確認してください。                   |
| `UNSUPPORTED_URL`         | この URL スキームはコンテンツ取得に対応していません。                 | 標準的な HTTP または HTTPS の URL を使用してください。                  |
| `CRAWL_UNKNOWN_ERROR`     | その他の理由でクロールに失敗しました。                           | リクエストを再試行してください。問題が解決しない場合はサポートにお問い合わせください。           |

これらのステータスタグは `/contents` 固有のものです。`/search` は `statuses` フィールドを返しません。

## サポートを受ける {#getting-help}

* `500`、`503`、`504` エラーが続く場合は、[Exa Status](/ja/docs/admin/status) を確認してください。
* 現在の上限については、[レート制限](/ja/docs/admin/billing#rate-limits) を確認してください。
* リクエストの要件については、該当するエンドポイントの [API リファレンス](/ja/docs/reference/search) を参照してください。
* レスポンスのステータス、エラーボディ、`requestId` を添えて、[hello@exa.ai](mailto:hello@exa.ai) までお問い合わせください。
