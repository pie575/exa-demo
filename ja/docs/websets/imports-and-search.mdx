URLのリスト(企業、人物、製品など)をすでにお持ちの場合は、それらをWebsetに**インポート**できます。Websetの設定次第で、インポートしたItemを補完したり、条件に照らして評価したり、Web Discoveryの結果と組み合わせたりできます。

このガイドでは、各構成について、そのままコピー&amp;ペーストできるAPIリクエストを使って順を追って説明します。`$EXA_API_KEY` をご自身のAPIキーに置き換えるだけで利用できます。

## 例: IT コンサルティングのサプライヤー 5 社 {#our-example-5-it-consulting-suppliers}

このガイドでは、全体を通して同じ 5 社のリストをインポートとして使用します。

| 会社           | URL                              | 備考                         |
| ------------ | -------------------------------- | -------------------------- |
| Accenture    | `https://www.accenture.com`      | グローバルな IT コンサルティング、米国に本社   |
| Infosys      | `https://www.infosys.com`        | IT サービス、米国で大規模に事業展開        |
| Wipro        | `https://www.wipro.com`          | IT サービス、米国にオフィスあり          |
| EPAM Systems | `https://www.epam.com`           | ソフトウェアエンジニアリング、米国上場        |
| Persol Group | `https://www.persol-group.co.jp` | 人材派遣会社、日本中心、米国での事業展開はごくわずか |

この 5 社を選んだのは、うち 4 社が一般的な IT コンサルティングの条件 (米国オフィス、IT サービス) に明らかに合致するためです。**Persol Group** は例外です。米国での事業展開がごくわずかな日本の人材派遣会社であるため、米国を対象とした条件には合致しないはずです。

以下の例で使用する条件:

1. 「The company has an office in the United States」
2. 「The company provides IT consulting or staff augmentation services」

## Config 1: Import Only -- フィルタリングなしで補完する {#config-1-import-only-enrich-without-filtering}

<Note>
  **実例:** [ダッシュボードでこの Webset を表示](https://websets.exa.ai/websets/webset_01kmnrshyh3bdart13q1ehdtdj)
</Note>

**適したケース:** URL のリストがあり、それを補完するだけでよい場合。スコアリングやフィルタリングは行わず、すべてのItemがそのまま保持されます。

### API 呼び出し {#api-calls}

```bash theme={null}
# ステップ1: サプライヤーのURLを含むCSVインポートを作成する
curl -s -X POST "https://api.exa.ai/websets/v0/imports" \
  -H "Authorization: Bearer $EXA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "format": "csv",
    "count": 5,
    "size": 128,
    "entity": { "type": "company" },
    "title": "IT Consulting Suppliers"
  }'
# レスポンスには `uploadUrl` とインポートの `id` が含まれます

# ステップ2: ステップ1で取得した署名付きURLにCSVをアップロードする
curl -X PUT "<UPLOAD_URL>" \
  -H "Content-Type: text/csv" \
  --data-binary @suppliers.csv
# suppliers.csv の内容: url\nhttps://www.accenture.com\nhttps://www.infosys.com\n...

# ステップ3: このインポートを使用するWebsetを作成する(エンリッチメントのみ。検索・条件は指定しない)
# Webset を作成すると、インポートの処理が自動的にスケジュールされます。
curl -s -X POST "https://api.exa.ai/websets/v0/websets" \
  -H "Authorization: Bearer $EXA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "import": [
      { "source": "import", "id": "<IMPORT_ID>" }
    ],
    "enrichments": [
      { "description": "What services does this company provide?", "format": "text" },
      { "description": "Number of employees", "format": "number" }
    ]
  }'
```

### 実際の Webset で確認できる内容 {#what-we-see-in-the-live-webset}

**5 件の Item** がすべて Webset に表示されます。条件が設定されていないため、フィルタリングは行われません。

| サプライヤー       | Webset に含まれるか | Source   | Evaluations | エンリッチメント | 理由                |
| ------------ | ------------- | -------- | ----------- | -------- | ----------------- |
| Accenture    | **はい**        | `import` | 0           | 2        | インポート済み。評価に使う条件なし |
| Infosys      | **はい**        | `import` | 0           | 2        | インポート済み。評価に使う条件なし |
| Wipro        | **はい**        | `import` | 0           | 2        | インポート済み。評価に使う条件なし |
| EPAM Systems | **はい**        | `import` | 0           | 2        | インポート済み。評価に使う条件なし |
| Persol Group | **はい**        | `import` | 0           | 2        | インポート済み。評価に使う条件なし |

すべての Item が `source: "import"` と `evaluations: []` を持ちます。この Config には条件がないため、何らかの条件を満たすかどうかに関係なく、5 件すべてが保持され、補完されます。

<Note>
  Persol Group の URL (`persol-group.co.jp`) は、エンティティデータ上で「PERSOL Vietnam Japan Desk」に解決されました。解決先が地域子会社のページになっただけで、システムは問題なくインポートと補完を行います。
</Note>

## Config 4: Scoped Search + Web Discovery -- リストをスコアリングしつつ新たな一致も見つける {#config-4-scoped-search-web-discovery-score-your-list-and-find-new-matches}

<Note>

**使用する場面:** サプライヤーリストを条件に照らしてスコアリングしつつ、同じ条件に一致する企業をウェブから新たに見つけたい場合に使用します。手順は 2 段階です。まず Scoped Search で Webset を作成し、次にその Webset に通常のウェブ検索を追加します。

  webset_response = requests.post(

| Wipro              | **はい**        | `search` | あり (2)          | Scoped Search を通過: 米国拠点あり、IT サービスを提供      |
| EPAM Systems       | **はい**        | `search` | あり (2)          | Scoped Search を通過: 米国上場、ソフトウェアエンジニアリングを提供 |
| Persol Group       | **いいえ -- 除外** | --       | --              | Scoped Search で不合格: 米国拠点なし                |
| *(ウェブで見つかった 25 社)* | **はい**        | `search` | あり (各 2)        | ウェブ検索で見つかり、両方の条件を満たした                     |

Scoped Search がインポートしたリストを条件に基づいて評価し (Persol Group は除外) 、追加のウェブ検索が新たに 25 社を見つけます。その結果、評価済みのインポートとウェブで新たに見つかった企業の両方が、1 つの webset にまとまります。

<Note>
  ウェブ検索では `"behavior": "append"` を指定しているため、既存の結果は置き換えられず、そこに追加されます。Scoped Search の結果にすでに含まれている企業 (例: Accenture) がウェブ検索で見つかった場合も、重複は自動的に処理されます。
</Note>

## クイックリファレンス {#quick-reference}

| 構成                                   | 機能                            | すべての Item が保持されるか               | Item はスコアリングされるか                         |
| ------------------------------------ | ----------------------------- | ------------------------------- | ---------------------------------------- |
| **1. Import Only**                   | リストを補完する                      | はい -- すべて保持                     | いいえ                                      |
| **2. Search Only**                   | Web から条件に一致する新しい Item を発見する   | 該当なし (インポートなし)                  | はい -- 条件を満たした Item のみ返される                |
| **3. Scoped Search**                 | リストを条件に照らしてスコアリングする           | いいえ -- 条件を満たさない Item は除外        | はい                                       |
| **4. Scoped Search + Web Discovery** | リストをスコアリング + 一致する新しい Item を発見 | いいえ -- 条件を満たさないインポート済み Item は除外 | はい -- インポートした Item と発見した Item の両方をスコアリング |

## どの Config を使えばよいか {#which-config-should-i-use}

* **「リストを補完したいだけで、フィルタリングは不要」** -- Config 1
* **「リストはないので、企業を探してほしい」** -- Config 2
* **「リストをスコアリングして、条件に合わないものを除外したい」** -- Config 3
* **「リストをスコアリングし、さらに条件に合う新しい企業も見つけたい」** -- Config 4
