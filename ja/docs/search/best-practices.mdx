このガイドは、正常に動作する [Search API リクエスト](/ja/docs/search/quickstart)がすでにあることを前提としています。Exa が推奨するベストプラクティスに沿って、そのリクエストを改善する方法を説明します。

## 必要最小限のリクエストから始める {#start-with-the-smallest-useful-request}

最適なベースラインは、`highlights: true` を指定した自然言語のクエリです。Exa は各結果の抜粋の長さを関連度に応じて自動で調整するため、文字数上限を調整する必要はありません。

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      contents={"highlights": True},
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search(
    "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
    { contents: { highlights: true } }
  );
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      "contents": { "highlights": true }
    }'
  ```
</CodeGroup>

これにより、ランク付けされたページと、各ページについてクエリに関連するトークン効率の高いコンテキストが得られます。

その他のパラメータは、必要に応じて追加してください。

| パラメータ                      | 追加する場面                                          |
| -------------------------- | ----------------------------------------------- |
| `type`                     | レイテンシの許容範囲や探索の深さの要件に合わせる場合                      |
| `numResults`               | コンテキストウィンドウに収めるためにページ数を減らす場合、または網羅性を高めるために増やす場合 |
| `outputSchema`             | 結果を統合する場合、または JSON に構造化する場合                     |
| `maxAgeHours`              | キャッシュされたページコンテンツが古すぎる可能性がある場合                   |
| `highlights.maxCharacters` | アプリケーションでページごとに抜粋の上限を固定する必要がある場合                |
| ドメインまたは日付のフィルター             | 条件を満たさない結果が使えない場合                               |

## Search と Deep Search の比較 {#search-vs-deep-search}

標準の検索は、クエリに対してページを取得し、ランク付けします。Deep Search はリサーチプロセスを実行します。反復的に検索し、見つかった内容を精査して検索を絞り込み、根拠に基づいた結果を統合して生成します。

| 目的                                                           | 推奨モード                               |
| ------------------------------------------------------------ | ----------------------------------- |
| 明確なクエリに対してランク付けされたページを取得する                                   | `auto` または `fast`                   |
| 難易度の高い検索、多数の結果にまたがる統合、または 1 回の検索では埋められない構造化出力 (3 つ以上のフィールド)  | `deep`                              |
| 長時間にわたるリサーチ、リスト作成、またはマルチホップのエンリッチメント                         | [Exa Agent](/ja/docs/agent/quickstart) |

`outputSchema` を使用する場合は、基本的に Deep モードをおすすめします。詳しい手順と例については、[Deep Search ガイド](/ja/docs/search/deep-search)をご覧ください。

## 検索品質を改善する {#improve-retrieval-quality}

結果を改善したい場合は、リクエストの要素を1つずつ変更してください。

<Steps>
  <Step title="クエリを明確にする">
    キーワードを羅列するのではなく、求めるページを具体的に説明してください。主題に加え、ソースタイプや
    期間など、どのような結果が関連性が高いかを左右する条件を含めます。

    ```text theme={null}
    Benchmark papers evaluating long-context retrieval methods on legal documents
    ```
  </Step>

  <Step title="レスポンスを段階的に読み解く">
    リクエストを変更する前に、タイトル、URL、公開日、ハイライトを確認してください。

    ```json theme={null}
    {
      "results": [
        {
          "title": "Long-Context Retrieval Methods on Legal Documents",
          "url": "https://arxiv.org/abs/2608.00000",
          "publishedDate": "2026-08-26T00:00:00.000Z",
          "highlights": [
            "We compare long-context retrieval methods across legal document benchmarks..."
          ]
        }
      ]
    }
    ```

    タイトルと URL からは Exa が取得したソースの種類が、`publishedDate` からは
    その新しさが、ハイライトからはクエリに一致した根拠がわかります。別のページを取得したい場合はクエリを見直し、
    期間を絞り込みたい場合は日付フィルターを追加し、有用な結果からさらにコンテキストが必要な場合は
    全文を取得してください。
  </Step>

  <Step title="必須の制約のみを追加する">
    `includeDomains`、`excludeDomains`、公開日フィルターは、制約を満たさない結果が
    使えない場合にのみ使用してください。検索に関する希望はクエリに記述し、
    回答を生成する場合は、レスポンスに関する指示を `systemPrompt` に記述します。
  </Step>

  <Step title="検索モードの変更は最後に行う">
    レイテンシ要件がある場合は高速なモードを、検索プロセス自体に反復と推論が必要な場合は
    deep モードを使用してください。モードを変えても、指定が不十分なクエリを補うことはできません。
  </Step>
</Steps>

調整中は、代表的なクエリを少数用意しておいてください。1つの例に合わせて最適化するのではなく、セット全体で結果の関連性と後続タスクの成功率を比較します。リグレッションを再現できるよう、`requestId`、`searchTime`、`costDollars` を記録してください。

## レイテンシとコンテキストの予算配分 {#budget-latency-and-context}

各コントロールは、それぞれ異なるリソースを消費します。

| コントロール                    | 増加するもの                    |
| ------------------------- | ------------------------- |
| 結果数を増やす                   | ページ数、レスポンスデータ、下流で使うコンテキスト |
| 全文                        | より広いページコンテキストと、より大きなペイロード |
| `summary`                 | 結果ごとに言語モデルの呼び出しが 1 回追加    |
| `outputSchema`            | 取得した結果全体の合成処理             |
| `contents.maxAgeHours: 0` | キャッシュを使わず、ページを新たに取得       |
| ディープ検索タイプ                 | 反復的な検索、合成、推論              |

キャッシュされたコンテンツでも問題ないリアルタイム処理では、最もレイテンシの低いモードに、ハイライトとキャッシュのみのコンテンツを組み合わせます。

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent product updates from major AI labs",
      type="instant",
      contents={
          "highlights": True,
          "max_age_hours": -1,
      },
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search("Recent product updates from major AI labs", {
    type: "instant",
    contents: {
      highlights: true,
      maxAgeHours: -1
    }
  });
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent product updates from major AI labs",
      "type": "instant",
      "contents": {
        "highlights": true,
        "maxAgeHours": -1
      }
    }'
  ```
</CodeGroup>

ページの鮮度が結果の正確性を左右する場合は、この構成を使用しないでください。プロダクトに計測済みのレイテンシ目標がない限り、まずは `auto` とデフォルトの鮮度設定から始めてください。

結果セット全体に対して 1 つのコンテキスト予算を Exa に配分させる方法 (有力なソースには多く、重複するソースには少なく割り当てる) については、[Dynamic Highlights リサーチプレビュー](/ja/docs/search/highlights#dynamic-highlights)を参照してください。

## よくあるユースケースのヒント {#tips-for-common-use-cases}

| 目的                       | 推奨                                                                          | 避けるべきこと                       |
| ------------------------ | --------------------------------------------------------------------------- | ----------------------------- |
| より新しい出版物を見つけたい           | クエリに期間を含めるか、公開日フィルターを使用する                                                   | `maxAgeHours`                 |
| 更新されるページから最新のコンテンツを取得したい | `contents.maxAgeHours`                                                      | 公開日フィルター                      |
| 特定の種類のソースを優先したい          | クエリの表現を工夫する。合成時は `systemPrompt` を使用する                                       | 厳格なドメイン許可リスト                  |
| 承認済みのソースからのみ結果を取得したい     | `includeDomains`                                                            | クエリ内で `site:` を繰り返す           |
| 小規模な構造化出力が欲しい            | 標準の Search で `outputSchema` を使用する                                           | 出力が JSON だからという理由だけで Deep を選ぶ |
| リサーチに基づく複数項目の出力が欲しい      | `deep` と `outputSchema` を併用する、または [Exa Agent](/ja/docs/agent/quickstart) を使用する | 1 回の検索ですべての項目が集まると期待する        |
| 少数のページからより多くのコンテキストを得たい  | ハイライト付きで Search を実行してから Contents を呼び出す                                      | すべての結果で全文を取得する                |
| レイテンシを抑えたい               | コンパクトなコンテンツで `fast` または `instant` を試して計測する                                  | 鮮度や合成の制御をデフォルトで追加する           |

## 別のエンドポイントを使うべきケース {#when-to-use-another-endpoint}

タスクの性質が異なる場合は、別の Exa エンドポイントを使用してください。

| タスク                     | 使用するエンドポイント                           |
| ----------------------- | ------------------------------------- |
| 長時間のリサーチ、リスト作成、エンリッチメント | [Exa Agent](/ja/docs/agent/quickstart)   |
| URL がすでにわかっている          | [Contents](/ja/docs/contents/quickstart) |
| スケジュールに沿って検索を定期実行する     | [Monitors](/ja/docs/monitors/quickstart) |
