<Update label="August 28, 2026" rss={{ title: "Dynamic Highlights（リサーチプレビュー）" }}>
  ## Dynamic Highlights (リサーチプレビュー)

  Dynamic Highlights は、各ページを個別に扱うのではなく、結果セット全体を見渡して抜粋を選択します。共有のコンテキスト予算を有用なソースに多く割り当て、すでに返された情報を繰り返すだけのソースには少なく割り当てます。

  * **シングルターン RAG**: コーディングおよび一般 QA の評価において、Exa Auto でトークン効率が約 49% 向上し、下流タスクの品質が 2.4% 向上しました。
  * **エージェント**: エージェントの軌跡全体でトークン数が約 30% 削減され、BrowseComp、WideSearch、および社内の企業・人物評価において品質が 1% 向上しました。

  `dynamic: true` を設定するリクエストには、`Exa-Beta: dynamic-highlights-2026-08-28` ヘッダーが必要です。

  [Dynamic Highlights ガイドを読む →](/ja/docs/contents/quickstart)
</Update>

<Update label="July 23, 2026" rss={{ title: "学術出版物のリサーチ" }}>
  ## 学術出版物のリサーチ

  学術出版物を対象としたリサーチ機能を大幅に拡張・改善しました。

  * **3 億 5,000 万件の出版物**: 3 億 5,000 万件の出版物を収録したインデックスを検索できます。
  * **組織と人物の結果を充実**: 検索で組織とその所属人物の両方が返されるようになりました。いずれも出版物、主な共同研究者、研究分野、研究資金を網羅した、補完済みの詳細なプロフィールとして返されます。
  * **エージェントによる人物・組織検索**: エージェントが人物と組織を検索できるようになりました。
  * **公開検索ベンチマーク**: 出版物検索のための公開ベンチマークをリリースしました。
  * **新しい `publication` 検索カテゴリ**: `category: "publication"` で学術的な結果を検索できます。これは `research paper` カテゴリに代わるものです。
  * **非推奨のカテゴリ**: `pdf`、`github`、`tweet` の検索カテゴリは非推奨になります。
  * **`startCrawlDate` / `endCrawlDate`**: これらの非推奨パラメーターは、互換性のため引き続き受け付けられますが、すべてのチームで無視されるようになりました。

  API では `publication` [検索カテゴリ](/ja/docs/search/quickstart)を指定して検索できます。[ダッシュボードで試すこともできます →](https://dashboard.exa.ai/playground/search?type=instant)
</Update>

  Exa MCP で Exa Agent が利用可能になりました。1 回の検索呼び出しでは足りないタスクには、Claude、Cursor、その他の MCP クライアントから利用できます。

<Update label="February 2, 2026" rss={{ title: "ハイライト、コンテンツの鮮度、MCP のアップデート" }}>
  ## ハイライト、コンテンツの鮮度、MCP のアップデート

  コンテンツの抽出とアクセスに関する 3 つの改善を行いました。

  * **ハイライト向けの `maxCharacters`**: ハイライトの長さを制御する方法として、今後はこちらを推奨します。`numSentences` と `highlightsPerUrl` は非推奨になりました。
  * **コンテンツの鮮度向けの `maxAgeHours`**: 真偽値の `livecrawl` に代わり、経過時間で制御できます(`0` は常にクロール、`-1` はキャッシュのみ、`24` は 24 時間より古い場合にクロール)。
  * **Exa MCP の無料枠**: 認証なしで 3 QPS、1 日 150 回の呼び出しまで試せます。API キーを追加すると、すべての機能を利用できます。

  [コンテンツの鮮度のドキュメント →](/ja/docs/contents/quickstart#content-freshness) · [Exa MCP →](/ja/docs/get-started/exa-mcp)

  ## Auto 検索におけるスコアの非推奨化

  新しい Auto 検索のアーキテクチャでは意味のある関連性スコアを算出できなくなったため、Auto 検索の結果から `score` フィールドを削除します。

  * **ニューラル検索**: スコアに変更はありません。スコアを利用している場合は `type="neural"` を指定してください。

<Update label="June 23, 2025" rss={{ title: "Markdown 形式のコンテンツがデフォルトに" }}>
  ## Markdown 形式のコンテンツがデフォルトに

  すべてのエンドポイントが、デフォルトでクリーンな Markdown を返すようになりました。LLM や RAG、一般的なテキスト処理に適した形式です。特に対応は必要ありません。

  * **`includeHtmlTags=false`(デフォルト)**: コンテンツはクリーンな Markdown に変換されます。
  * **`includeHtmlTags=true`**: Markdown に変換せず、生の HTML を返します。

  いずれの場合も、広告やナビゲーションなどの定型部分は除去されます。

  [Contents のドキュメントを読む →](/ja/docs/contents/quickstart)
</Update>

<Update label="June 7, 2025" rss={{ title: "新しい Livecrawl オプション: Preferred" }}>
  ## 新しい Livecrawl オプション: Preferred

  <Warning>
    過去の記録: 文字列型の `livecrawl` パラメータは現在非推奨です。新規の統合では、`maxAgeHours` と `livecrawlTimeout` を使用してください。詳しくは [コンテンツの鮮度](/ja/docs/contents/quickstart#content-freshness) を参照してください。
  </Warning>

  非推奨の `livecrawl: "preferred"` オプションは、新たにクロールを試み、失敗した場合はキャッシュされたコンテンツにフォールバックします(エラーを返す `"always"` とは異なります)。一時的にアクセスできないサイトがあっても失敗させずに、新しいコンテンツを取得したい本番アプリに最適です。

  [コンテンツの鮮度のドキュメントを読む →](/ja/docs/contents/quickstart#content-freshness)
</Update>

<Update label="May 22, 2025" rss={{ title: "Contents エンドポイントのステータスの変更" }}>
  ## Contents エンドポイントのステータスの変更

  `/contents` は単一の HTTP エラーではなく、URL ごとの `statuses` フィールドを返すようになりました。これにより、URL ごとの結果を個別に処理できます。エンドポイント自体がエラーを返すのは、内部的な問題が発生した場合のみです。

  * **`status`**: URL ごとに `"success"` または `"error"`。
  * **`error.tag`**: `CRAWL_NOT_FOUND`、`CRAWL_TIMEOUT`、`SOURCE_NOT_AVAILABLE` など。`httpStatusCode` も含まれます。

  [エラーコードのリファレンスを読む →](/ja/docs/admin/error-codes)
</Update>
