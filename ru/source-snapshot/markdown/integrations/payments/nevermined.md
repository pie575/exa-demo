<div id="nevermined">
  # Nevermined
</div>

> Автономные платежи агентов за Exa через схему card-delegation x402 от Nevermined. Покупка на 7 USD создаёт новый Exa API key или пополняет существующий на 7 USD credits.

Агенты оплачивают Exa банковской картой по схеме [card-delegation x402](https://nevermined.ai/docs/specs/x402-card-delegation) от [Nevermined](https://nevermined.ai). Каждая **покупка на $7** возвращает Exa API key с **$7 credits Exa**.

<Info>
  Используйте этот идентификатор плана Nevermined:<br />`27800462147494506865542649899724877617306579171265399959488097895839186996870`<br />Этот план работает в рабочей среде Nevermined (API keys с префиксом live). Покупка даёт credits для API, а не оплачивает один поисковый запрос.
</Info>

Если плательщик Nevermined обращается впервые, `POST /team-management/nevermined/purchase-key` создаёт новый Exa API key и начисляет $7 credits. Когда credits на key заканчиваются, выпустите новый токен x402 с тем же делегированием и снова вызовите этот же эндпоинт. Exa вернёт тот же API key, начислив на него ещё $7 credits.

<div id="buy-a-key">
  ## Покупка ключа
</div>

```bash theme={null}
POST https://admin-api.exa.ai/team-management/nevermined/purchase-key
payment-signature: <x402-token>
```

* **Стоимость:** $7 за покупку; списывается с карты, привязанной к делегированию, на которое ссылается токен x402.
* **Ответ (новый плательщик):** `{ status: "ok", apiKey: "…", expiresAt: null }` — новый Exa API key с кредитами на $7.
* **Ответ (повторный плательщик):** `{ status: "ok", apiKey: "…", expiresAt: null }` — тот же Exa API key с дополнительными кредитами на $7.
* **Ответ (повторно отправленный токен):** результат из кэша, повторное списание не производится.
* **Отсутствующая/некорректная подпись:** `402 Payment Required`, в теле ответа — платёжные требования.

<div id="how-it-works">
  ## Как это работает
</div>

Платёжную часть берёт на себя Nevermined; Exa видит только подписанный токен x402.

1. **Разовая настройка (выполняется владельцем карты):** зарегистрируйте карту на [nevermined.app](https://nevermined.app), создайте для неё **делегирование** (разрешение на расходование средств: владелец задаёт лимит и срок действия и может ограничить его конкретным API key), а затем выпустите Nevermined API key для агента.
2. **Агент находит своё делегирование.** Nevermined SDK позволяет агенту найти делегирования, доступные его key для расходования, и выбрать то, где осталось достаточно бюджета (не менее $7). Если подходящего нет, владелец создаёт делегирование в панели управления — либо полностью автономный агент может создать его через SDK в пределах лимитов карты.
3. **Агент выпускает токен доступа x402** для указанного выше идентификатора плана по схеме card-delegation, ссылаясь на делегирование по ID. Делегирования должны существовать до выпуска токена: сами токены создать их на лету не могут.
4. **Агент отправляет POST-запрос с токеном на указанный выше эндпоинт** в header `payment-signature` и получает в ответе Exa API key.
5. **Key работает сразу же** со стандартным [Exa Search API](/ru/docs/search/quickstart).

Полное пошаговое руководство для агентов (методы SDK, параметры, поиск и создание делегирований, устранение неполадок) смотрите в руководстве Nevermined по интеграции с Exa: [nevermined.ai/docs/integrations/exa](https://nevermined.ai/docs/integrations/exa) (для агентов: загрузите [nevermined.ai/docs/integrations/exa.md](https://nevermined.ai/docs/integrations/exa.md)).

<div id="when-the-key-runs-out">
  ## Когда ключ исчерпан
</div>

Как только credits у API key заканчиваются, Exa возвращает **`HTTP 402`** на обычных эндпоинтах API:

```json theme={null}
{
  "requestId": "...",
  "error": "You have exceeded your credits limit. Please top up to keep using Exa at dashboard.exa.ai",
  "tag": "NO_MORE_CREDITS"
}
```

Выпустите новый токен x402 с тем же идентификатором плана и делегированием, затем снова отправьте его методом POST на тот же эндпоинт `/purchase-key`. Exa добавит ещё $7 credits к тому же API key.
