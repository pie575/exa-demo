<div id="exa-contents-skill">
  # Навык Exa Contents
</div>

> Извлекайте содержимое страниц с помощью Exa Contents, когда URL уже известны.

Используйте этот навык, чтобы научить агента вызывать Exa Contents через cURL или необработанный HTTP с соблюдением лучших практик.

<Card title="Получите свой Exa API key" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">
  Создайте key в панели управления. Новым аккаунтам начисляются бесплатные credits.
</Card>

<Note>
  Укажите свой key в переменной `EXA_API_KEY` в окружении агента.
</Note>

<div id="setup">
  ## Настройка
</div>

**Вариант A: установить этот навык напрямую:**

```bash theme={null}
npx skills add exa-labs/agent-skills --skill "exa-contents"
```

**Вариант Б: скопируйте этот промпт в свой кодинг-агент.**

Приведённый ниже промпт устанавливает навык и проверяет ваш API key, не выводя его на экран:

```text Copy this setup prompt into your agent theme={null}
Настрой на этой машине агентский навык Exa exa-contents.

Цель:
- Установить навык exa-contents, чтобы мой кодинг-агент мог вызывать Exa Contents напрямую через cURL или необработанный HTTP.
- Добиться работающего Exa API key, НИ РАЗУ не раскрывая, не выводя и не вставляя ключ в этот чат.

Выбранный агент:
- Claude Code, Codex, Cursor или любой агент, совместимый с Agent Skills
- Глобальные каталоги установки: ~/.claude/skills (Claude Code), ~/.codex/skills (Codex), ~/.agents/skills (Cursor / другие)
- Локальные каталоги установки в проекте: .claude/skills (Claude Code), .agents/skills (Codex / Cursor / другие)

Источник навыка:
- URL SKILL.md: https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md

Что нужно сделать:
1. СНАЧАЛА установи навык, до любой настройки ключа. Если работаешь внутри репозитория, предпочитай локальную установку в проект; иначе используй соответствующий глобальный каталог из списка выше. Создай выбранный каталог навыков и скачай навык:
   mkdir -p <skills-dir>/exa-contents && curl -fsSL "https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md" -o <skills-dir>/exa-contents/SKILL.md
   Затем убедись, что файл <skills-dir>/exa-contents/SKILL.md существует.
2. Проверь, доступен ли уже Exa API key В ТВОЁМ СОБСТВЕННОМ ОКРУЖЕНИИ ВЫПОЛНЕНИЯ КОМАНД — используй тот же инструмент/шелл, в котором будешь запускать навык, а не проси меня вывести ключ. Навык берёт ключ сначала из EXA_API_KEY, затем из файла ~/.config/exa/key, поэтому проверь оба варианта, не выводя значение:
   printf '%s\n' "${EXA_API_KEY:+env-set}"; [ -s ~/.config/exa/key ] && printf 'file-set\n'
   Твой шелл, скорее всего, неинтерактивный и НЕ подгружает автоматически интерактивные профили вроде ~/.zshrc или ~/.bashrc, поэтому ключ, заданный мной там, для меня выглядит установленным, а для тебя — пустым. Если ни одна проверка ничего не показала, ключ всё ещё может лежать в интерактивном профиле, который твой шелл пропускает: найди нужный файл, НЕ выводя его значение, командой `grep -l EXA_API_KEY ~/.zshrc ~/.zshenv ~/.bashrc ~/.profile ~/.config/fish/config.fish 2>/dev/null` (выводятся только имена файлов — НИКОГДА не запускай обычный `grep`/`cat`/`echo` по профилю, ведь строка `export EXA_API_KEY=...` раскроет секрет в нашем чате). Затем выполни `source` этого файла внутри своей команды и повтори проверку наличия выше; если ключ обнаружен, добавляй тот же префикс `source ...;` ко всем последующим командам, которым нужен ключ.
3. Только если ключ нигде не находится, настрой его БЕЗ ручного редактирования шелл-профилей и БЕЗ вставки ключа в этот чат. Скажи мне создать/скопировать ключ на https://dashboard.exa.ai/api-keys — дальше я сам в своём терминале либо экспортирую EXA_API_KEY, либо запишу его в ~/.config/exa/key с правами 600; никогда не проси меня вставлять ключ в чат. Затем дождись моего подтверждения, прежде чем продолжать.
4. Проверь работоспособность ключа из своего шелла — возьми его из переменной окружения или файла и выведи только код состояния:
   KEY="${EXA_API_KEY:-$(cat ~/.config/exa/key 2>/dev/null)}"
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.exa.ai/contents \
     -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"urls":["https://exa.ai"],"text":true}'
   Оставь эндпоинт, заголовки и тело запроса в точности как написано (не угадывай схему). Ответ должен быть 200, а не 401/429. Если на шаге 2 тебе понадобился префикс `source ...;`, чтобы увидеть ключ в окружении, добавь его и здесь.
5. Расскажи, как перезапустить агента или обновить список навыков, чтобы он обнаружил новый навык.

Жёсткое правило на всех шагах: ключ — это секрет. Проверять его можно только через проверку наличия/длины (`${EXA_API_KEY:+set}`, `[ -s ~/.config/exa/key ]`) или по HTTP-коду ответа — никогда не выводи на экран, не применяй `echo`, `cat` или `grep` с выводом к файлам и переменным, которые могут его содержать, и никогда не пытайся «замаскировать» файл с ключом регулярным выражением. Если ключ всё же оказался раскрыт, скажи мне сменить его на https://dashboard.exa.ai/api-keys.
```
