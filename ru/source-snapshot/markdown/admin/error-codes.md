<div id="error-codes">
  # Коды ошибок
</div>

> Справочник по распространённым кодам ошибок, используемым в Exa API

API Exa сообщают об ошибках стандартными HTTP-кодами состояния и телом ответа с ошибкой в формате JSON.

<div id="http-status-codes">
  ## HTTP-коды состояния
</div>

| Код                         | Значение                                                                                                     | Что делать                                                                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `400` Bad Request           | Тело запроса, параметры запроса, заголовки или сочетание параметров некорректны.                             | Исправьте запрос, опираясь на возвращённое сообщение.                                                                                                        |
| `401` Unauthorized          | API key отсутствует или недействителен.                                                                      | Проверьте заголовок аутентификации и API key.                                                                                                                |
| `402` Payment Required      | Кредиты исчерпаны или превышен бюджет расходов.                                                              | [Пополните кредиты](https://dashboard.exa.ai) или обратитесь к администратору команды.                                                                       |
| `403` Forbidden             | У API key нет доступа к запрошенной функции, либо запрос заблокирован политикой.                             | Проверьте возвращённое сообщение и набор функций, доступных в вашем тарифе.                                                                                  |
| `404` Not Found             | Маршрут или запрошенный ресурс не существует.                                                                | Проверьте эндпоинт и идентификатор ресурса.                                                                                                                  |
| `409` Conflict              | Запрос конфликтует с текущим состоянием — например, Webset с таким же `externalId` уже существует.           | Получите существующий ресурс или используйте другой идентификатор.                                                                                           |
| `422` Unprocessable Entity  | Запрос предпросмотра Websets не удалось разложить на корректную сущность и criteria.                         | Переформулируйте запрос предпросмотра.                                                                                                                       |
| `429` Too Many Requests     | Ваш API key, команда или сеть превысили лимит частоты запросов или параллелизма.                             | Снизьте частоту запросов; при наличии `Retry-After` подождите указанное число секунд, иначе используйте экспоненциальную задержку.                           |
| `500` Internal Server Error | Произошла непредвиденная ошибка сервера.                                                                     | Повторите запрос после короткой паузы. Если ошибка сохраняется, обратитесь в поддержку.                                                                      |
| `503` Service Unavailable   | Exa временно перегружена (`SERVICE_OVERLOADED`) или недоступна. Запрос не был обработан и не тарифицируется. | Повторите запрос с экспоненциальной задержкой. Это не зависит от частоты ваших запросов, поэтому её снижение не поможет — помогают именно повторные попытки. |
| `504` Gateway Timeout       | Запрос превысил отведённое время обработки.                                                                  | Повторите запрос или сократите его объём.                                                                                                                    |

<Note>
  Ошибки на уровне отдельных URL из `/contents` возвращаются в поле `statuses` успешного ответа `200`, а не как ошибки уровня запроса. См. [Теги статуса получения контента](#content-fetch-status-tags).
</Note>

<div id="error-response-structure">
  ## Структура ответа с ошибкой
</div>

В ответах с ошибкой возвращаются `requestId`, читаемое человеком сообщение `error` и машиночитаемый `tag`:

```json theme={null}
{
  "requestId": "67207943fab9832d162b5317f4cca830",
  "error": "Invalid request body | Validation error: Invalid value for type",
  "tag": "INVALID_REQUEST_BODY"
}
```

<Note>
  Указывайте `requestId` при обращении в поддержку — это ускорит диагностику.
</Note>

Набор тегов открытый, а их названия говорят сами за себя. Сначала ветвите логику по HTTP-коду ответа, а нераспознанные теги воспринимайте как дополнительную информацию, а не как ошибку разбора.

<div id="content-fetch-status-tags">
  ## Теги статуса получения контента
</div>

Когда в `/contents` передаётся несколько URL, обработка одного из них может завершиться ошибкой, а остальных — успешно. Ошибки на уровне отдельных URL возвращаются в поле `statuses` и не приводят к сбою всего запроса:

```json theme={null}
{
  "results": [],
  "statuses": [
    {
      "id": "https://example.com",
      "status": "error",
      "error": {
        "tag": "CRAWL_NOT_FOUND",
        "httpStatusCode": 404
      }
    }
  ]
}
```

`httpStatusCode` описывает целевую страницу, а не ответ `/contents`.

| Тег                       | Описание                                                           | Что делать                                                           |
| ------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `CRAWL_NOT_FOUND`         | Целевая страница не найдена.                                       | Проверьте корректность и доступность URL.                            |
| `CRAWL_HTTP_{status}`     | Целевой ресурс вернул HTTP-ошибку, например `CRAWL_HTTP_403`.      | Обработайте вложенный статус целевого ресурса.                       |
| `CRAWL_TIMEOUT`           | Истекло время ожидания при загрузке целевой страницы.              | Повторите запрос или попробуйте позже.                               |
| `CRAWL_LIVECRAWL_TIMEOUT` | Загрузка в реальном времени превысила заданный `livecrawlTimeout`. | Увеличьте `livecrawlTimeout` или измените `maxAgeHours`.             |
| `SOURCE_NOT_AVAILABLE`    | Доступ к источнику запрещён или источник недоступен.               | Проверьте, требует ли источник аутентификации или имеет ограничения. |
| `UNSUPPORTED_URL`         | Схема URL не поддерживается для получения контента.                | Используйте стандартный URL с HTTP или HTTPS.                        |
| `CRAWL_UNKNOWN_ERROR`     | Обход завершился ошибкой по иной причине.                          | Повторите запрос; если проблема сохраняется, обратитесь в поддержку. |

Эти теги статуса относятся только к `/contents`; `/search` не возвращает поле `statuses`.

<div id="getting-help">
  ## Как получить помощь
</div>

* Проверьте [Статус Exa](/ru/docs/admin/status), если ошибки `500`, `503` или `504` повторяются.
* Посмотрите текущие лимиты в разделе [Лимиты запросов](/ru/docs/admin/billing#rate-limits).
* Изучите [справочник API](/ru/docs/reference/search) по нужному эндпоинту, чтобы уточнить требования к запросу.
* Напишите на [hello@exa.ai](mailto:hello@exa.ai), указав статус ответа, тело ошибки и `requestId`.
