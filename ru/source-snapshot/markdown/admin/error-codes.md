<div id="error-codes">
  # Коды ошибок
</div>

> Справочник по распространённым кодам ошибок, используемым в Exa API

Exa API сообщают о сбоях стандартными HTTP-кодами состояния и телом ошибки в формате JSON.

<div id="http-status-codes">
  ## HTTP status codes
</div>

| Код                         | Значение                                                                                                     | Что делать                                                                                                                         |
| --------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `400` Bad Request           | Недопустимое тело, параметры запроса, headers или сочетание опций.                                           | Исправьте запрос согласно возвращённому сообщению.                                                                                 |
| `401` Unauthorized          | API key отсутствует или недействителен.                                                                      | Проверьте header аутентификации и API key.                                                                                         |
| `402` Payment Required      | Credits исчерпаны или превышен бюджет расходов.                                                              | [Пополните credits](https://dashboard.exa.ai) или обратитесь к администратору вашей команды.                                       |
| `403` Forbidden             | У API key нет доступа к запрошенной функции, либо запрос заблокирован политикой.                             | Проверьте возвращённое сообщение и набор функций, доступных в вашем тарифе.                                                        |
| `404` Not Found             | Маршрут или запрошенный ресурс не существует.                                                                | Проверьте эндпоинт и ID ресурса.                                                                                                   |
| `409` Conflict              | Запрос конфликтует с текущим состоянием — например, Webset с таким же `externalId` уже существует.           | Получите существующий ресурс или используйте другой идентификатор.                                                                 |
| `422` Unprocessable Entity  | Запрос предпросмотра Websets не удалось разложить на корректную сущность и criteria.                         | Переформулируйте запрос предпросмотра.                                                                                             |
| `429` Too Many Requests     | Ваш API key, команда или сеть превысили лимит частоты запросов или параллелизма.                             | Снизьте частоту запросов; при наличии `Retry-After` подождите указанное число секунд, иначе используйте экспоненциальную задержку. |
| `500` Internal Server Error | Произошла непредвиденная ошибка сервера.                                                                     | Повторите попытку через небольшую паузу. Если проблема сохраняется, обратитесь в поддержку.                                        |
| `503` Service Unavailable   | Exa временно перегружена (`SERVICE_OVERLOADED`) или недоступна. Запрос не был обработан и не тарифицируется. | Повторите с экспоненциальной задержкой. Это не зависит от частоты ваших запросов, поэтому её снижение не поможет — поможет повтор. |
| `504` Gateway Timeout       | Запрос превысил отведённое время обработки.                                                                  | Повторите запрос или сузьте его охват.                                                                                             |

<Note>
  Ошибки на уровне отдельных URL из `/contents` отражаются в поле `statuses` успешного ответа `200`, а не как ошибки уровня запроса. См. [Теги статуса получения содержимого](#content-fetch-status-tags).
</Note>

<div id="error-response-structure">
  ## Структура ответа с ошибкой
</div>

В ответах с ошибкой возвращаются `requestId`, понятное человеку сообщение `error` и машиночитаемый `tag`:

```json theme={null}
{
  "requestId": "67207943fab9832d162b5317f4cca830",
  "error": "Invalid request body | Validation error: Invalid value for type",
  "tag": "INVALID_REQUEST_BODY"
}
```

<Note>
  Указывайте `requestId` при обращении в поддержку, это ускорит диагностику.
</Note>

Набор тегов открытый, а имена тегов говорят сами за себя. Сначала стройте логику по HTTP status code, а нераспознанные теги воспринимайте как дополнительную информацию, а не как ошибку разбора.

</div>

| Tag                       | HTTP-код | Описание                                                                                 |
| ------------------------- | -------- | ---------------------------------------------------------------------------------------- |
| `INVALID_REQUEST_BODY`    | `400`    | JSON-body не прошёл валидацию по schema.                                                 |
| `INVALID_REQUEST`         | `400`    | Параметры конфликтуют между собой, либо бета-функция использована без header `Exa-Beta`. |

| `INVALID_JSON_SCHEMA`     | `400`    | Переданная schema вывода некорректна.                                                    |
| `SUBPAGES_LIMIT_EXCEEDED` | `400`    | `/contents` допускает не более 100 подстраниц на один request.                           |

<div id="content-fetch-status-tags">
  ## Теги статуса получения содержимого
</div>

Когда `/contents` принимает несколько URL, по одному из них запрос может завершиться ошибкой, а по остальным — успешно. Ошибки на уровне URL возвращаются в поле `statuses` и не приводят к сбою запроса:

```json theme={null}
{
  "results": [],
  "statuses": [
    {
      "id": "https://example.com",
      "status": "error",
      "error": {
        "tag": "CRAWL_NOT_FOUND",
        "httpStatusCode": 404
      }
    }
  ]
}
```

`httpStatusCode` описывает целевую страницу, а не ответ `/contents`.

| tag                       | Описание                                                           | Как обрабатывать                                                              |
| ------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `CRAWL_NOT_FOUND`         | Целевая страница не найдена.                                       | Проверьте, что URL указан верно и доступен.                                   |
| `CRAWL_HTTP_{status}`     | Целевой ресурс вернул ошибку HTTP, например `CRAWL_HTTP_403`.      | Обработайте статус целевого ресурса, указанный в tag.                        |
| `CRAWL_TIMEOUT`           | Истекло время ожидания при загрузке целевой страницы.              | Повторите запрос или попробуйте позже.                                        |
| `CRAWL_LIVECRAWL_TIMEOUT` | Загрузка в реальном времени превысила заданный `livecrawlTimeout`. | Увеличьте `livecrawlTimeout` или измените `maxAgeHours`.                      |
| `SOURCE_NOT_AVAILABLE`    | Доступ к источнику запрещён или источник недоступен.               | Проверьте, требует ли источник аутентификации или ограничен ли доступ к нему. |
| `UNSUPPORTED_URL`         | Схема URL не поддерживается для получения содержимого.             | Используйте стандартный URL с HTTP или HTTPS.                                 |
| `CRAWL_UNKNOWN_ERROR`     | Обход не удался по иной причине.                                   | Повторите запрос; если ошибка повторяется, обратитесь в поддержку.            |

Эти теги статуса относятся только к `/contents`; `/search` не возвращает поле `statuses`.

<div id="getting-help">
  ## Как получить помощь
</div>

* Проверьте [Exa Status](/ru/docs/admin/status), если ошибки `500`, `503` или `504` повторяются.
* Текущие лимиты смотрите в разделе [Лимиты частоты запросов](/ru/docs/admin/billing#rate-limits).
* Требования к запросу описаны в [API reference](/ru/docs/reference/search) соответствующего эндпоинта.
* Напишите на [hello@exa.ai](mailto:hello@exa.ai), указав статус ответа, тело ошибки и `requestId`.
