<div id="search-best-practices">
  # Лучшие практики поиска
</div>

> Настройте качество поиска, задержку, контекст и синтез ответов для продакшн-интеграций с Search API.

Это руководство предполагает, что у вас уже есть работающий [запрос к Search API](/ru/docs/search/quickstart). Здесь описано, как улучшить его, следуя рекомендованным Exa лучшим практикам.

<div id="start-with-the-smallest-useful-request">
  ## Начните с минимально достаточного запроса
</div>

Лучшая отправная точка — запрос на естественном языке с `highlights: true`. Exa сама подбирает длину фрагментов для каждого результата в зависимости от его релевантности, поэтому подбирать лимит символов не требуется:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      contents={"highlights": True},
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search(
    "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
    { contents: { highlights: true } }
  );
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      "contents": { "highlights": true }
    }'
  ```
</CodeGroup>

Так вы получите ранжированные страницы и экономный по токенам контекст по каждой из них, релевантный запросу.

Добавляйте остальные параметры только по мере необходимости:

| Параметр                   | Когда добавлять                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------ |
| `type`                     | Нужно уложиться в бюджет по задержке или обеспечить требуемую глубину                |
| `numResults`               | Меньше страниц для небольшого контекстного окна или больше для более широкого охвата |
| `outputSchema`             | Требуется синтезировать результаты или структурировать их в JSON                     |
| `maxAgeHours`              | Закешированное содержимое страницы может оказаться слишком старым                    |
| `highlights.maxCharacters` | Вашему приложению нужен фиксированный лимит фрагмента на страницу                    |
| Фильтры по домену или дате | Результаты вне этих ограничений будут бесполезны                                     |

<div id="search-vs-deep-search">
  ## Search и Deep Search
</div>

Стандартный search находит и ранжирует страницы по запросу. Deep Search запускает исследовательский процесс, который может
искать итеративно, анализировать найденное, уточнять поиск и синтезировать обоснованный результат.

| Задача                                                                                                                                       | С чего начать                       |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Ранжированные страницы по корректно сформулированному запросу                                                                                | `auto` или `fast`                   |
| Сложные поисковые задачи, синтез по множеству результатов или структурированный вывод, который невозможно заполнить одним поиском (3+ полей) | `deep`                              |
| 長длительные исследования, построение списков или многошаговый enrichment                                                                     | [Exa Agent](/ru/docs/agent/quickstart) |

При использовании `outputSchema` по умолчанию рекомендуются режимы deep. Полные инструкции и примеры см. в [руководстве по Deep Search](/ru/docs/search/deep-search).

<div id="improve-retrieval-quality">
  ## Улучшение качества поиска
</div>

Если результаты требуют улучшения, меняйте в запросе по одному параметру за раз.

<Steps>
  <Step title="Уточните запрос">
    Опишите нужные вам страницы, а не перечисляйте ключевые слова. Укажите тему и любые детали — тип источника,
    период времени и прочее, — которые меняют представление о релевантном результате.

    ```text theme={null}
    Benchmark papers evaluating long-context retrieval methods on legal documents
    ```
  </Step>

  <Step title="Разбирайте ответ по уровням">
    Прежде чем менять запрос, изучите заголовки, URL, даты публикации и highlights.

    ```json theme={null}
    {
      "results": [
        {
          "title": "Long-Context Retrieval Methods on Legal Documents",
          "url": "https://arxiv.org/abs/2608.00000",
          "publishedDate": "2026-08-26T00:00:00.000Z",
          "highlights": [
            "We compare long-context retrieval methods across legal document benchmarks..."
          ]
        }
      ]
    }
    ```

    Заголовок и URL показывают, какого рода источник нашла Exa, `publishedDate` — насколько он свежий,
    а highlight — то подтверждение, которое совпало с запросом. Переформулируйте запрос, чтобы
    получить другие страницы, добавьте фильтры по дате, чтобы сузить период, или запросите полный
    текст, если по полезному результату нужно больше контекста.
  </Step>

  <Step title="Добавляйте только жёсткие ограничения">
    Используйте `includeDomains`, `excludeDomains` и фильтры по дате публикации только тогда, когда
    результат, нарушающий ограничение, непригоден. Предпочтения по поиску указывайте в запросе, а при
    синтезе ответа помещайте инструкции в `systemPrompt`.
  </Step>

  <Step title="Режим поиска меняйте в последнюю очередь">
    Используйте более быстрый режим, если есть требование по задержке, или глубокий режим, когда сам
    процесс поиска требует итераций и рассуждений. Смена режима не спасёт недостаточно
    конкретный запрос.
  </Step>
</Steps>

При настройке держите под рукой небольшой набор показательных запросов. Сравнивайте релевантность результатов и успешность итоговой задачи по всему набору, а не оптимизируйте под один пример. Записывайте `requestId`, `searchTime` и `costDollars`, чтобы регрессии были воспроизводимы.

<div id="budget-latency-and-context">
  ## Расходуйте задержку и контекст с умом
</div>

Каждый параметр расходует свой ресурс:

| Параметр                  | Что добавляет                                                   |
| ------------------------- | --------------------------------------------------------------- |
| Больше результатов        | Больше страниц, данных в ответе и контекста на следующих этапах |
| Полный текст              | Более широкий контекст страницы и больший payload               |
| `summary`                 | Один дополнительный вызов языковой модели на каждый результат   |
| `outputSchema`            | Синтез по всем полученным результатам                           |
| `contents.maxAgeHours: 0` | Свежую загрузку страницы вместо кешированного контента          |
| Глубокие типы поиска      | Итеративный поиск, синтез и рассуждения                         |

Для сценариев реального времени, где кешированный контент допустим, сочетайте режим с наименьшей задержкой, highlights и контент только из кеша:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent product updates from major AI labs",
      type="instant",
      contents={
          "highlights": True,
          "max_age_hours": -1,
      },
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search("Recent product updates from major AI labs", {
    type: "instant",
    contents: {
      highlights: true,
      maxAgeHours: -1
    }
  });
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent product updates from major AI labs",
      "type": "instant",
      "contents": {
        "highlights": true,
        "maxAgeHours": -1
      }
    }'
  ```
</CodeGroup>

Не применяйте этот рецепт, если свежесть страницы влияет на корректность. Начинайте с `auto` и свежести по умолчанию, если у продукта нет измеренного целевого показателя задержки.

Чтобы Exa распределяла единый бюджет контекста по всему набору результатов — больше на сильные источники, меньше на избыточные, — см. [исследовательскую предварительную версию Dynamic Highlights](/ru/docs/search/highlights#dynamic-highlights).

<div id="tips-for-common-use-cases">
  ## Советы для типичных сценариев
</div>

| Что нужно                                          | Используйте                                                         | Избегайте                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| Более свежие публикации                            | Укажите временной интервал в запросе или фильтры по дате публикации | `maxAgeHours`                                                 |
| Актуальный контент со страниц, которые обновляются | `contents.maxAgeHours`                                              | Фильтры по дате публикации                                    |
| Определённый тип источников                        | Формулировку запроса; `systemPrompt` при синтезе                    | Жёсткий список разрешённых доменов                            |
| Результаты только из проверенных источников        | `includeDomains`                                                    | Повторение `site:` в запросе                                  |
| Небольшой структурированный вывод                  | `outputSchema` со стандартным Search                                | Выбор Deep только из-за того, что вывод в JSON                |
| Исследовательский вывод по нескольким элементам    | `deep` с `outputSchema` или [Exa Agent](/ru/docs/agent/quickstart)     | Расчёт на то, что один поиск соберёт все элементы             |
| Больше контекста с нескольких страниц              | Search с highlights, затем вызов Contents                           | Полный текст для каждого результата                           |
| Меньшую задержку                                   | Замерьте `fast` или `instant` с компактным контентом                | Добавление настроек свежести или синтеза по умолчанию         |

<div id="when-to-use-another-endpoint">
  ## Когда использовать другой эндпоинт
</div>

| Задача                                                     | Используйте                           |
| ---------------------------------------------------------- | ------------------------------------- |

| Запуск search по расписанию                                | [Monitors](/ru/docs/monitors/quickstart) |
