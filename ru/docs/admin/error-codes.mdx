API Exa сообщают о сбоях стандартными HTTP-кодами состояния и телом ошибки в формате JSON.

## HTTP status codes {#http-status-codes}

| Код                         | Значение                                                                                                     | Что делать                                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400` Bad Request           | Некорректное тело запроса, query-параметры, headers или сочетание опций.                                     | Исправьте запрос, опираясь на возвращённое сообщение.                                                                                                       |
| `401` Unauthorized          | API key отсутствует или недействителен.                                                                      | Проверьте header аутентификации и API key.                                                                                                                  |
| `402` Payment Required      | Credits исчерпаны или превышен бюджет расходов.                                                              | [Пополните credits](https://dashboard.exa.ai) или обратитесь к администратору вашей команды.                                                                |
| `403` Forbidden             | У API key нет доступа к запрошенной функции, либо запрос заблокирован политикой.                             | Проверьте возвращённое сообщение и набор функций, доступных в вашем тарифе.                                                                                 |
| `404` Not Found             | Маршрут или запрошенный ресурс не существует.                                                                | Проверьте эндпоинт и ID ресурса.                                                                                                                            |
| `409` Conflict              | Запрос конфликтует с текущим состоянием — например, Webset с таким же `externalId` уже существует.           | Получите существующий ресурс или используйте другой идентификатор.                                                                                          |
| `422` Unprocessable Entity  | Запрос предпросмотра Websets не удалось разложить на корректную сущность и criteria.                         | Переформулируйте запрос предпросмотра.                                                                                                                      |
| `429` Too Many Requests     | Ваш API key, команда или сеть превысили лимит частоты запросов или параллелизма.                             | Снизьте частоту запросов; если присутствует `Retry-After`, подождите указанное число секунд, иначе используйте экспоненциальную задержку.                   |
| `500` Internal Server Error | Произошла непредвиденная ошибка сервера.                                                                     | Повторите запрос после короткой паузы. Если ошибка сохраняется, обратитесь в поддержку.                                                                     |
| `503` Service Unavailable   | Exa временно перегружена (`SERVICE_OVERLOADED`) или недоступна. Запрос не был обработан и не тарифицируется. | Повторите запрос с экспоненциальной задержкой. Это не зависит от частоты ваших запросов, поэтому её снижение не поможет — помогут именно повторные попытки. |
| `504` Gateway Timeout       | Запрос превысил отведённое время обработки.                                                                  | Повторите запрос или сузьте его охват.                                                                                                                      |

<Note>
  Сбои на уровне отдельных URL в `/contents` отражаются в поле `statuses` успешного ответа `200`, а не как ошибки уровня запроса. См. [Теги статуса получения содержимого](#content-fetch-status-tags).
</Note>

## Структура ответа при ошибке {#error-response-structure}

Ответ с ошибкой содержит `requestId`, понятное человеку сообщение `error` и машиночитаемый `tag`:

```json theme={null}
{
  "requestId": "67207943fab9832d162b5317f4cca830",
  "error": "Invalid request body | Validation error: Invalid value for type",
  "tag": "INVALID_REQUEST_BODY"
}
```

<Note>
  Указывайте `requestId` при обращении в поддержку, это ускорит диагностику.
</Note>

Набор тегов не является фиксированным, а имена тегов говорят сами за себя. Сначала разветвляйте логику по HTTP-коду статуса, а нераспознанные теги считайте дополнительной информацией, а не ошибкой разбора.

| `FEATURE_DISABLED`        | `403`    | Запрошенный эндпоинт, тип поиска или опция недоступны в вашем тарифе.                                          |
| `PROHIBITED_CONTENT`      | `403`    | Запрос отклонён модерацией безопасности контента.                                                              |

| `SERVICE_OVERLOADED`      | `503`    | Exa временно перегружена и отклонила запрос до его обработки — повторите попытку с экспоненциальной задержкой. |

### Валидация запроса {#request-validation}

| Tag                       | HTTP-код | Описание                                                                               |
| ------------------------- | -------- | -------------------------------------------------------------------------------------- |
| `INVALID_REQUEST_BODY`    | `400`    | JSON-body не прошёл проверку по schema.                                                |
| `INVALID_REQUEST`         | `400`    | Опции конфликтуют друг с другом, либо бета-функция использована без header `Exa-Beta`. |
| `INVALID_NUM_RESULTS`     | `400`    | Значение `numResults` не должно превышать 100, если запрашиваются highlights.          |
| `NUM_RESULTS_EXCEEDED`    | `400`    | Запрошенное количество результатов превышает лимит вашего тарифа.                      |
| `INVALID_JSON_SCHEMA`     | `400`    | Указанная schema вывода недопустима.                                                   |
| `SUBPAGES_LIMIT_EXCEEDED` | `400`    | `/contents` допускает не более 100 подстраниц на один request.                         |

### Платёжные протоколы {#payment-protocols}

Запросы, оплаченные через x402 или MPP, также могут возвращать:

| Tag                        | HTTP-код | Описание                                              |
| -------------------------- | -------- | ----------------------------------------------------- |
| `X402_PAYMENT_REQUIRED`    | `402`    | Требуется оплата.                                     |
| `X402_INVALID_SIGNATURE`   | `400`    | Недействительная подпись платежа x402.                |
| `X402_VERIFICATION_FAILED` | `402`    | Не удалось верифицировать платёж x402.                |
| `MPP_VERIFICATION_FAILED`  | `402`    | Не удалось верифицировать платёж MPP.                 |
| `X402_TOO_MANY_UNPAID`     | `429`    | Слишком много запросов x402 ожидают оплаты.           |
| `X402_WALLET_RATE_LIMITED` | `429`    | Кошелёк x402 превысил свой лимит запросов.            |
| `X402_INTERNAL_ERROR`      | `500`    | Exa не смогла сформировать платёжные требования x402. |

## Теги статуса получения содержимого {#content-fetch-status-tags}

Когда `/contents` получает несколько URL, для одного из них запрос может завершиться ошибкой, тогда как остальные будут обработаны успешно. Ошибки на уровне URL возвращаются в поле `statuses` и не приводят к сбою всего запроса:

```json theme={null}
{
  "results": [],
  "statuses": [
    {
      "id": "https://example.com",
      "status": "error",
      "error": {
        "tag": "CRAWL_NOT_FOUND",
        "httpStatusCode": 404
      }
    }
  ]
}
```

`httpStatusCode` описывает целевую страницу, а не ответ `/contents`.

| Tag                       | Описание                                                           | Как обрабатывать                                                              |
| ------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `CRAWL_NOT_FOUND`         | Целевая страница не найдена.                                       | Убедитесь, что URL корректен и доступен.                                      |
| `CRAWL_HTTP_{status}`     | Целевой ресурс вернул ошибку HTTP, например `CRAWL_HTTP_403`.      | Обработайте вложенный статус целевого ресурса.                                |
| `CRAWL_TIMEOUT`           | Истекло время ожидания при обходе целевой страницы.                | Повторите запрос или попробуйте позже.                                        |
| `CRAWL_LIVECRAWL_TIMEOUT` | Загрузка в реальном времени превысила заданный `livecrawlTimeout`. | Увеличьте `livecrawlTimeout` или измените `maxAgeHours`.                      |
| `SOURCE_NOT_AVAILABLE`    | Доступ к источнику запрещён или источник недоступен.               | Проверьте, требует ли источник аутентификации или ограничен ли доступ к нему. |
| `UNSUPPORTED_URL`         | Схема URL не поддерживается для получения содержимого.             | Используйте стандартный URL с HTTP или HTTPS.                                 |
| `CRAWL_UNKNOWN_ERROR`     | Обход не удался по другой причине.                                 | Повторите запрос; если ошибка повторяется, обратитесь в поддержку.            |

Эти теги статуса относятся только к `/contents`; `/search` не возвращает поле `statuses`.

## Получение помощи {#getting-help}

* Проверьте [Exa Status](/ru/docs/admin/status), если ошибки `500`, `503` или `504` повторяются.
* Посмотрите текущие лимиты в разделе [Лимиты запросов](/ru/docs/admin/billing#rate-limits).
* Ознакомьтесь с требованиями к запросу в [API-справочнике](/ru/docs/reference/search) по нужному эндпоинту.
* Напишите на [hello@exa.ai](mailto:hello@exa.ai), указав статус ответа, тело ошибки и `requestId`.
