Exa Agent — это асинхронный эндпоинт с оплатой по использованию для ресурсоёмких задач: построения списков, enrichment и deep research. Он справляется со сложными рассуждениями и может возвращать множество полей структурированного вывода.

Считайте его контекстным agent: вы описываете, какие данные нужны и в каком виде их вернуть, а Exa Agent оркестрирует необходимые для этого tool calls. В рамках одного выполнения он может запустить множество searches с разных сторон, прочитать и сжать найденные страницы, разбить построение списков на параллельные подзадачи, проверить каждого кандидата по вашим criteria, обогатить контакты и отправить запрос любым партнёрам данных [Exa Connect](/ru/docs/agent/connect/overview), которых вы подключили. Собранный context возвращается вам единым обоснованным структурированным результатом, и вам не нужно самостоятельно оркестрировать каждый вызов `/search` и `/contents`.

Каждое выполнение может вернуть ответ на естественном языке, JSON, проверенный по schema, grounding на уровне полей, metadata и разбивку стоимости. Позже вы можете получить завершённые выполнения, вывести список прошлых выполнений, повторно воспроизвести события или продолжить с предыдущего выполнения.

<Tip>
  Предпочитаете MCP? Exa Agent и [Exa Connect](/ru/docs/agent/connect/overview) доступны в [Exa MCP](/ru/docs/get-started/exa-mcp#exa-agent). Включите `tools=agent_run`, чтобы запускать многошаговые Research, построение списков, enrichment и структурированный вывод из Claude, Cursor и других MCP-клиентов.
</Tip>

## Когда использовать Exa Agent {#when-to-use-exa-agent}

Используйте Exa Agent, когда рабочему процессу недостаточно одного вызова search или извлечения контента, либо когда вам иначе пришлось бы писать собственный цикл из поисков, чтения страниц и шагов верификации, чтобы собрать данные:

* Формирование списков по открытым criteria с последующим обогащением каждого результата
* Исследование сущностей по множеству полей с citations
* Выполнение многошаговых задач вида «найти компании, а затем их лиц, принимающих решения»
* Получение структурированного JSON из длительной задачи по веб-исследованию
* Объединение веб-исследования с премиальными партнёрами данных в одном ответе с опорой на источники
* Продолжение предыдущего выполнения с помощью follow-up request вида «найди ещё 10 результатов»

Exa Agent изначально асинхронен и работает с более высокой задержкой. Если вам нужен один поиск с низкой задержкой, а оркестрацией вызовов вы управляете сами, начните с [Search API](/ru/docs/search/quickstart).

### 4. Опрос до завершения {#4-poll-for-completion}

Если вы не используете потоковую передачу событий, сохраните возвращённый `id` и опрашивайте выполнение, пока оно не достигнет терминального статуса.

<CodeGroup>
  ```python Python theme={null}
  import json
  from exa_py import Exa

  exa = Exa()
  run_id = "agent_run_01j..."
  run = exa.agent.runs.poll_until_finished(
      run_id,
      poll_interval=4000,
  )

  print(json.dumps(run.model_dump(), indent=2))
  ```

  ```javascript JavaScript theme={null}
  import Exa from "exa-js";

  const exa = new Exa();
  const runId = "agent_run_01j...";
  const run = await exa.agent.runs.pollUntilFinished(runId, {
    pollInterval: 4000
  });

  console.log(JSON.stringify(run, null, 2));
  ```

  ```bash cURL theme={null}
  RUN_ID="agent_run_01j..."

  while true; do
    RUN_JSON="$(curl -s "https://api.exa.ai/agent/runs/$RUN_ID" \
      -H "Authorization: Bearer $EXA_API_KEY")"

    STATUS="$(echo "$RUN_JSON" | python3 -c 'import json,sys; print(json.load(sys.stdin)["status"])')"
    echo "status=$STATUS"

    if [ "$STATUS" = "completed" ] || [ "$STATUS" = "failed" ] || [ "$STATUS" = "cancelled" ]; then
      echo "$RUN_JSON"
      break
    fi

    sleep 4
  done
  ```
</CodeGroup>

Завершённые выполнения содержат:

* `output.text`: ответ на естественном языке
* `output.structured`: проверенный JSON, если вы передали `outputSchema`
* `output.grounding`: citations для текстовых или структурированных полей, если они формируются
* `costDollars`: разбивка стоимости выполнения

<Note>
  Exa Agent также доступен через совместимый с OpenAI Responses API. Направьте
  OpenAI SDK на `https://api.exa.ai`, укажите `model: "exa-agent"` и выберите
  синхронное, потоковое или фоновое выполнение. См. [совместимость с OpenAI
  SDK](/ru/docs/integrations/openai-sdk#agent-via-responses-api).
</Note>

## Stream events {#stream-events}

Потоковая передача оставляет запрос на создание открытым и отправляет Server-Sent Events (SSE), пока выполнение не завершится. Типы событий и их payload описаны в разделе [Event format](#event-format).

Укажите `stream=True` в Python, `stream: true` в JavaScript или отправьте заголовок `Accept: text/event-stream` по HTTP:

<CodeGroup>
  ```python Python theme={null}
  from exa_py import Exa

  exa = Exa()
  events = exa.agent.runs.create(
      query="Find five recently launched developer tools for evaluating AI agents.",
      stream=True,
  )

  for event in events:
      print(event.event, event.data)
  ```

  ```javascript JavaScript theme={null}
  import Exa from "exa-js";

  const exa = new Exa();
  const events = await exa.agent.runs.create({
    query: "Find five recently launched developer tools for evaluating AI agents.",
    stream: true
  });

  for await (const event of events) {
    console.log(event.event, event.data);
  }
  ```

  ```bash cURL theme={null}
  curl -N -X POST "https://api.exa.ai/agent/runs" \
    -H "Content-Type: application/json" \
    -H "Accept: text/event-stream" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Find five recently launched developer tools for evaluating AI agents."
    }'
  ```
</CodeGroup>

### Формат события {#event-format}

Каждый SSE-кадр содержит идентификатор события, имя события и JSON-payload:

```text theme={null}
id: 1
event: agent_run.created
data: {"id":"agent_run_01j...","status":"queued","createdAt":"2026-05-07T21:21:52.051Z"}
```

Поток также может содержать строки-комментарии, например `: keep-alive`. SSE-клиенты игнорируют комментарии автоматически; собственные парсеры должны делать то же самое.

### Типы событий {#event-types}

| Событие               | `data` payload                        | Как использовать                                                                                                      |
| --------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `agent_run.created`   | `{ id, status: "queued", createdAt }` | Сохраните ID выполнения сразу после того, как request принят.                                                         |
| `agent_run.started`   | `{ id, status: "running" }`           | Отметьте, что выполнение активно обрабатывается.                                                                      |
| `agent_run.completed` | Объект завершённого выполнения Agent   | Считайте итоговый ответ из `data.output.text` или `data.output.structured`, а citations — из `data.output.grounding`. |
| `agent_run.failed`    | `{ id, status: "failed", error }`     | Покажите `error.code` и `error.message`; завершённый вывод недоступен.                                                |
| `agent_run.cancelled` | `{ id, status: "cancelled", ... }`    | Прекратите чтение потока и обработайте выполнение как отменённое.                                                     |

События, относящиеся к одному шагу Research, содержат `callId`. Он соответствует `item.call_id` в событиях прогресса tool. Используйте его для группировки трассировок search, sources и прогресса tool. Некоторые описания трассировок search генерируются асинхронно и могут прийти позже того события source или tool, которое они описывают, поэтому не сопоставляйте их только по порядку поступления.

Рассматривайте `agent_run.source.added` как предварительный просмотр в реальном времени, а не как полный список citations. Авторитетным grounding-выводом является `output.grounding` завершённого выполнения.

### Повторная отправка сохранённых событий {#replay-stored-events}

Для выполнений без ZDR эндпоинт [`GET /agent/runs/{id}/events`](/ru/docs/reference/agent-api/list-run-events) возвращает сохранённые события в виде постраничного JSON. Передайте `Accept: text/event-stream`, чтобы повторно отправить сохранённые события как SSE, и `Last-Event-ID`, чтобы пропустить события, уже обработанные вашим клиентом:

```bash cURL theme={null}
curl -N "https://api.exa.ai/agent/runs/agent_run_01j.../events" \
  -H "Accept: text/event-stream" \
  -H "Last-Event-ID: 12" \
  -H "Authorization: Bearer $EXA_API_KEY"
```

Эндпоинт повторной отправки передаёт события, сохранённые на момент запроса, после чего закрывает соединение; он не продолжает отслеживать активное выполнение. Выполнения в режиме ZDR не сохраняют события, поэтому повторно отправить их нельзя.

Для совместимости с будущими версиями игнорируйте имена событий, которые ваше приложение не распознаёт, и продолжайте обработку до поступления терминального события.

## Возврат структурированного JSON {#return-structured-json}

Используйте `outputSchema`, чтобы получать в `output.structured` JSON, проверенный по схеме.

`outputSchema` поддерживает [спецификацию JSON Schema](https://json-schema.org/).

Чтобы запросить контактную информацию, опишите нужные контактные поля в `outputSchema`. Используйте стандартные конструкции JSON Schema: `{ "type": "string", "format": "email" }` для адресов электронной почты, `{ "type": "string", "format": "phone" }` для номеров телефонов и `{ "type": "string", "format": "uri" }` для URL. По возможности ограничивайте размер списков с помощью `maxItems` — так максимальная стоимость contact-enrichment будет предсказуемой.

<CodeGroup>
  ```python Python theme={null}
  import json
  from exa_py import Exa

  exa = Exa()
  run = exa.agent.runs.create(
      query="Find AI infrastructure companies that raised a Series A or B in the last 6 months.",
      effort="auto",
      output_schema={
          "type": "object",
          "properties": {
              "companies": {
                  "type": "array",
                  "items": {
                      "type": "object",
                      "properties": {
                          "name": {"type": "string"},
                          "round": {"type": "string"},
                          "website": {"type": "string"},
                      },
                      "required": ["name", "round"],
                  },
              }
          },
  ```

## Подключение источников данных {#connect-data-sources}

Индекс уже доступен при каждом выполнении. Используйте `dataSources` только для подключения партнёров [Exa Connect](/ru/docs/agent/connect/overview). В каждой записи указывается `provider`. Если свойство в вашем `outputSchema` ссылается на конкретный источник (например, &quot;from Similarweb&quot;), Exa Agent вызовет соответствующий инструмент провайдера, а не станет угадывать данные по веб-странице.

```json theme={null}
{
  "dataSources": [
    { "provider": "similarweb" },
    { "provider": "fiber" }
  ]
}
```

Полный список партнёров данных с примерами для каждого из них см. в разделе [Exa Connect](/ru/docs/agent/connect/overview).

## Pricing {#pricing}

Стоимость зависит от использования и рассчитывается по компонентам:

| Компонент                 | Цена              |
| ------------------------- | ----------------- |
| Agent Compute Units       | `1 ACU = $0.10`   |
| Вызовы инструмента search | `$0.005 / search` |

<Note>
  Обогащение контактов не входит в основные компоненты стоимости, перечисленные выше: обогащение контактов по email стоит `$0.02 / email`, а по номеру телефона — `$0.07 / phone number`.
</Note>

`usage.agentComputeUnits` измеряет объём вычислений модели за всё выполнение. Сложные запросы, особенно с большим полем `input.data`, требуют больше шагов рассуждения и вызовов инструментов, а значит расходуют больше ACU.

Информацию о параллелизме и лимитах частоты запросов см. в разделе [Лимиты Agent](/ru/docs/admin/billing#agent-limits).

### Effort {#effort}

С помощью `effort` можно выбрать уровень стоимости и рассуждений для каждого выполнения. Поддерживаются значения `minimal`, `low`, `medium`, `high`, `xhigh`, `auto` и `max`; значение по умолчанию — `auto`. У фиксированных уровней effort цена за запрос предсказуема, а `auto` и бета-режим `max` тарифицируются по использованию:

| Effort    | Цена                                                     |
| --------- | -------------------------------------------------------- |
| `minimal` | `$0.012 / request`                                       |
| `low`     | `$0.025 / request`                                       |
| `medium`  | `$0.10 / request`                                        |
| `high`    | `$0.50 / request`                                        |
| `xhigh`   | `$1.00 / request`                                        |
| `auto`    | По использованию; до лимита по умолчанию `$5`            |
| `max`     | **Бета**, по использованию; до лимита по умолчанию `$20` |

<Info>
  Agent Max — это уровень с наивысшим effort для задач, где полнота и тщательность
  важнее задержки и стоимости: масштабное построение списков, глубокое исследование
  по множеству источников и criteria, которые сложно проверить. Режим находится в публичной бете:
  запросы с `effort: "max"` должны включать `Exa-Beta: agent-max-effort-2026-07-27`.
  Этот header принимает список бета-токенов через запятую.
</Info>

`budget.maxCostDollars` — необязательный верхний предел на одно выполнение для `auto` и `max`. Принимаются значения от `$1` до `$100`; максимум в поставке — `$100`, но server может задать меньшее значение. Лимит по умолчанию составляет `$5` для `auto` и `$20` для `max`. Это именно предельная, а не фиксированная цена: выполнения, завершившиеся раньше, обходятся дешевле. Для фиксированных уровней effort бюджет не принимается.

### Выбор режима effort {#choosing-an-effort-mode}

Фиксированные режимы effort хорошо подходят, когда нужна предсказуемая стоимость запроса при стандартных исследованиях. Используйте `auto` для задач с переменным объёмом, например для построения списков, где количество сущностей меняется от запроса к запросу.

| Effort    | Лучше всего подходит для                                                         | Рекомендуемая сложность schema                                     | Ожидаемое время выполнения          |
| --------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------- |
| `minimal` | Самых дешёвых поисков, очень узких фактических задач, коротких ответов           | Одно-два поля, простая schema                                      | Дешевле всего, наименее полно       |
| `low`     | Простых поисков, узких фактических задач, коротких ответов                       | Несколько полей, простая schema                                    | Быстро, неглубокое исследование     |
| `medium`  | Отправной точки по умолчанию для большинства стандартных исследовательских задач | Умеренное число полей, простые вложенные объекты                   | Баланс качества и времени           |
| `high`    | Более сложных исследований, большего числа citations, строгой полноты            | Крупные schema или более тонкие поля                               | Медленнее, тщательнее               |
| `xhigh`   | Важных задач, где полнота важнее стоимости и задержки                            | Сложные schema, много полей, трудная верификация                   | Самый медленный фиксированный режим |
| `auto`    | Задач с переменным объёмом, построения списков, неизвестной сложности            | Гибкий; полезен, когда число сущностей или объём работы неизвестны | Переменное                          |
| `max`     | Исследований с максимальным effort (бета)                                        | Сложные schema, много полей, трудная верификация                   | Самое долгое выполнение             |

Начинайте с `medium` для стандартных исследований по одной сущности. Переходите на `low` или `minimal`, когда стоимость и задержка важнее полноты. Повышайте до `high` или `xhigh`, если выходная schema крупнее, поля требуют верификации или задача требует более глубоких рассуждений. Используйте `auto`, когда объём работы заранее неизвестен, например при построении списков или в рабочих процессах, способных вернуть много сущностей.

Время выполнения зависит от сложности запроса, сложности schema и доступности внешних источников. Рассматривайте режимы effort как компромисс между качеством, стоимостью и временем выполнения, а не как строгие гарантии задержки.

## Нулевое хранение данных {#zero-data-retention}

Exa Agent поддерживает [нулевое хранение данных](/ru/docs/admin/security/zero-data-retention) (ZDR). ZDR включается на уровне команды. [Свяжитесь с нами](mailto:sales@exa.ai), чтобы активировать его для вашего аккаунта.

Если для вашей команды включён ZDR:

* Создавайте выполнения с потоковой передачей (`Accept: text/event-stream`), чтобы получать вывод в реальном времени, либо опрашивайте асинхронные выполнения в пределах окна хранения.
* Данные выполнения доступны во время его выполнения и ещё до 10 минут после перехода в терминальное состояние. По истечении этого окна получить выполнение уже нельзя.
* `previousRunId` недоступен.
* `dataSources` в Exa Connect недоступны; запросы, содержащие их, возвращают ошибку `400`.
