<div id="what-is-x402">
  ## Что такое x402?
</div>

[x402](https://x402.org) — это открытый платёжный стандарт, основанный на HTTP-коде состояния `402 Payment Required`. Он позволяет клиентам оплачивать доступ к API отдельно за каждый запрос с помощью стейблкоинов USDC в сетях Base или Solana, без аккаунтов, API key и подписок.

Exa поддерживает x402 на двух эндпоинтах: **`/search`** и **`/contents`**. Если вы отправляете запрос без API key или платёжного header, Exa возвращает `402` и header `PAYMENT-REQUIRED` с информацией о pricing и списком поддерживаемых платёжных сетей. Ваш client подписывает платёж в USDC, повторяет запрос с header `PAYMENT-SIGNATURE` и получает результаты, как только расчёт подтверждается в блокчейне.

Это идеальный вариант для **AI agents**, которым нужно самостоятельно оплачивать веб-поиск без заранее выданных credentials.

<Info>
  x402 и доступ по API key независимы друг от друга. Если запрос содержит header `x-api-key` или `Authorization: Bearer`, применяется обычная схема тарификации по API key, а x402 полностью не используется.
</Info>

<div id="supported-endpoints">
  ## Поддерживаемые эндпоинты
</div>

| Эндпоинт    | Метод | Описание                                                                                            |
| ----------- | ----- | --------------------------------------------------------------------------------------------------- |
| `/search`   | POST  | Веб-поиск со всеми типами поиска (`instant`, `auto`, `fast`, `deep`, `deep-lite`, `deep-reasoning`) |
| `/contents` | POST  | Получение содержимого по URL или идентификатору документа                                           |

Все остальные эндпоинты через x402 **недоступны**.

<div id="step-1-discovery">
  ### Шаг 1: Discovery
</div>

Отправьте запрос к поддерживаемому эндпоинту без API key и без payment header:

```bash theme={null}
curl -X POST "https://api.exa.ai/search" \
  -H "Content-Type: application/json" \
  -d '{"query": "best machine learning frameworks", "numResults": 5}'
```

Вы получите ответ `402` с header `PAYMENT-REQUIRED`, закодированным в base64. В декодированном виде он выглядит так:

```json theme={null}
{
  "x402Version": 2,
  "resource": {
    "url": "https://api.exa.ai/search",
    "description": "Exa /search endpoint"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "amount": "7000",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "payTo": "0x...",
      "maxTimeoutSeconds": 60,
      "extra": { "name": "USD Coin", "version": "2" }
    },
    {
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "amount": "7000",
      "asset": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
      "payTo": "...",
      "maxTimeoutSeconds": 60,
      "extra": { "name": "USD Coin", "version": "2", "feePayer": "..." }
    }
  ]
}
```

Значение `amount` указывается в атомарных единицах USDC (6 знаков после запятой), то есть `"7000"` = $0.007.
Клиент может оплатить через любую из объявленных записей `accepts`, которую он поддерживает. Записи Solana содержат поля, предоставленные facilitator, например `extra.feePayer`; при формировании платежа используйте запись из header `PAYMENT-REQUIRED` без изменений.

<div id="step-2-pay-and-retry">
  ### Шаг 2: оплата и повторный запрос
</div>

Подпишите платёж своим wallet и отправьте запрос повторно, добавив header `PAYMENT-SIGNATURE` с полезной нагрузкой платежа в кодировке base64. Клиентские SDK x402 делают это автоматически.

<div id="step-3-settlement">
  ### Шаг 3: Расчёт
</div>

Exa проверяет вашу payment signature через facilitator, а затем запускает on-chain расчёт **параллельно** с обработкой вашего request. Response задерживается до подтверждения расчёта. В случае успеха вы получаете:

* HTTP `200` с вашими результатами
* Header `PAYMENT-RESPONSE` с settlement receipt (в кодировке base64), включая хеш on-chain транзакции

Если расчёт не удался, вы получите `402` вместе с `PAYMENT-RESPONSE` (детали ошибки) и `PAYMENT-REQUIRED` (чтобы можно было повторить попытку).

<div id="pricing">
  ## Цены
</div>

x402 использует ту же пакетную тарификацию, что и схема тарификации по API key. Стоимость рассчитывается заранее, исходя из параметров вашего запроса (а не фактически возвращённых результатов).

<div id="search-search">
  ### Search (`/search`)
</div>

| Тип поиска                | Базовая цена (до 10 результатов) | За результат сверх 10 |
| ------------------------- | -------------------------------- | --------------------- |
| `instant`, `auto`, `fast` | $0.007 / запрос                  | Н/Д (лимит 10)        |
| `deep-lite`               | $0.012 / запрос                  | Н/Д (лимит 10)        |
| `deep`                    | $0.012 / запрос                  | Н/Д (лимит 10)        |
| `deep-reasoning`          | $0.015 / запрос                  | Н/Д (лимит 10)        |

Добавление `contents.summary` стоит дополнительно **$0.001 за результат**.

<Warning>
  Запросы x402 ограничены **максимум 10 результатами**. Если запросить больше 10, значение `numResults` будет молча сокращено до 10, а стоимость рассчитается исходя из 10 результатов.
</Warning>

<div id="contents-contents">
  ### Contents (`/contents`)
</div>

Каждый тип содержимого тарифицируется за страницу/URL:

| Тип содержимого | Цена за страницу |
| --------------- | ---------------- |
| `text`          | $0.001           |
| `highlights`    | $0.001           |
| `summary`       | $0.001           |

Если вы не запрашиваете ни одного типа содержимого (ни `text`, ни `highlights`, ни `summary`), по умолчанию включается `text`.

| `/contents` для 2 URL с `text: true`                 | $0.002 | 2000        |
| `/contents` для 1 URL с `text` + `summary`           | $0.002 | 2000        |

<div id="make-a-paid-search-request">
  ### Отправка платного поискового запроса
</div>

<CodeGroup>
  ```typescript JavaScript theme={null}
  import { wrapFetchWithPayment } from "@x402/fetch";
  import { x402Client, x402HTTPClient } from "@x402/core/client";
  import { ExactEvmScheme } from "@x402/evm/exact/client";
  // Для поддержки Solana также импортируйте:
  // import { ExactSvmScheme } from "@x402/svm/exact/client";
  import { privateKeyToAccount } from "viem/accounts";

  const signer = privateKeyToAccount(process.env.WALLET_PRIVATE_KEY as `0x${string}`);
  const client = new x402Client();
  client.register("eip155:*", new ExactEvmScheme(signer));
  // Зарегистрируйте также подписанта Solana, если хотите, чтобы клиент использовал
  // записи accept для Solana, например `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`:
  // client.register("solana:*", new ExactSvmScheme(svmSigner));
  const fetchWithPayment = wrapFetchWithPayment(fetch, client);

  const response = await fetchWithPayment("https://api.exa.ai/search", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      query: "best machine learning frameworks",
      numResults: 5,
    }),
  });

  const data = await response.json();
  console.log(data.results);

  // Проверка квитанции о расчёте
  const httpClient = new x402HTTPClient(client);
  const receipt = httpClient.getPaymentSettleResponse(
    (name) => response.headers.get(name)
  );
  console.log("Transaction:", receipt?.transaction);
  ```

  ```python Python theme={null}
  import os
  import requests
  from eth_account import Account
  from x402 import x402ClientSync
  from x402.http.clients import wrapRequestsWithPayment
  from x402.mechanisms.evm.exact import register_exact_evm_client
  from x402.mechanisms.evm.signers import EthAccountSigner

  account = Account.from_key(os.environ["WALLET_PRIVATE_KEY"])
  client = x402ClientSync()
  register_exact_evm_client(
      client,
      EthAccountSigner(account),
      networks="eip155:*",
  )
  session = wrapRequestsWithPayment(requests.Session(), client)

  response = session.post("https://api.exa.ai/search", json={
      "query": "best machine learning frameworks",
      "numResults": 5,
  })

  data = response.json()
  for result in data["results"]:
      print(result["url"], result["title"])
  print("Payment response:", response.headers.get("PAYMENT-RESPONSE"))
  ```

  ```bash cURL theme={null}
  # Шаг 1: Discovery, получение информации о ценах
  curl -s -o /dev/null -w "%{http_code}" -D - \
    -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -d '{"query": "best machine learning frameworks", "numResults": 5}'
  # Возвращает 402 с header PAYMENT-REQUIRED, содержащим цены в кодировке base64

  # Шаг 2: Подпишите платёж своим wallet (используйте для этого SDK)
  # Шаг 3: Повторите запрос с payment signature
  curl -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "PAYMENT-SIGNATURE: <base64-encoded-payment>" \
    -d '{"query": "best machine learning frameworks", "numResults": 5}'
  # Возвращает 200 с результатами + header PAYMENT-RESPONSE (settlement receipt)
  ```
</CodeGroup>

<Info>
  В cURL платёж нужно подписывать вручную. Для production используйте SDK для JavaScript или Python: он автоматически выполняет весь цикл 402 &gt; подпись &gt; повтор запроса.
</Info>

<div id="discovery-mode-no-wallet-needed">
  ### Режим Discovery (wallet не нужен)
</div>

Узнайте pricing без wallet, отправив requests без аутентификации:

<CodeGroup>
  ```typescript JavaScript theme={null}
  const res = await fetch("https://api.exa.ai/search", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ query: "test query", numResults: 3 }),
  });

  // res.status === 402
  const paymentRequired = JSON.parse(
    atob(res.headers.get("PAYMENT-REQUIRED")!)
  );
  console.log(
    paymentRequired.accepts.map(({ network, amount }) => ({
      network,
      amount,
    }))
  );
  ```

  ```python Python theme={null}
  import base64, json, requests

  res = requests.post("https://api.exa.ai/search", json={
      "query": "test query",
      "numResults": 3,
  })

  # res.status_code == 402
  pricing = json.loads(base64.b64decode(res.headers["PAYMENT-REQUIRED"]))
  print([(accept["network"], accept["amount"]) for accept in pricing["accepts"]])
  ```

  ```bash cURL theme={null}
  curl -s -D - -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -d '{"query": "test query", "numResults": 3}'
  # Найдите header PAYMENT-REQUIRED в response со статусом 402
  # Декодируйте его: echo "<header-value>" | base64 -d
  ```
</CodeGroup>

<div id="payment-networks">
  ## Платёжные сети
</div>

Exa перечисляет все поддерживаемые на текущий момент сети в массиве `accepts`. Выберите запись, которая соответствует вашему wallet и зарегистрированной схеме x402-клиента.

| Сеть               | Идентификатор                             | Token | Актив                                          |
| ------------------ | ----------------------------------------- | ----- | ---------------------------------------------- |
| Base (Ethereum L2) | `eip155:8453`                             | USDC  | `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`   |
| Solana mainnet     | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` | USDC  | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |

Обе сети используют USDC с 6 знаками после запятой (`1000000` = $1.00) и проводят расчёты on-chain через facilitator x402.

<div id="rate-limits">
  ## Лимиты частоты запросов
</div>

В x402 действуют собственные лимиты частоты запросов, независимые от лимитов API key:

| Лимит                                  | Порог               | Окно      |
| -------------------------------------- | ------------------- | --------- |
| Неоплаченные discovery-запросы (на IP) | 5 запросов          | 60 секунд |
| Оплаченные запросы (на wallet)         | 10 запросов/секунду | 1 секунда |

После 5 неаутентифицированных discovery-запросов с кодом `402` с одного IP в течение 60 секунд все последующие запросы возвращают `429 Too Many Requests`. Успешный оплаченный запрос уменьшает значение счётчика.

Лимит QPS для wallet действует для всех оплаченных запросов с одного адреса wallet.

<div id="headers-reference">
  ## Справочник по header
</div>

<div id="request-headers">
  ### Заголовки запроса
</div>

| header              | Описание                                     |
| ------------------- | -------------------------------------------- |
| `PAYMENT-SIGNATURE` | Payment payload в кодировке Base64 (x402 v2) |
| `payment-signature` | Псевдоним (также принимается)                |
| `x-payment`         | Устаревший псевдоним (совместимость с v1)    |

<div id="response-headers">
  ### Заголовки ответа
</div>

| Header             | Когда                                  | Описание                                                                       |
| ------------------ | -------------------------------------- | ------------------------------------------------------------------------------ |
| `PAYMENT-REQUIRED` | ответы `402`                           | Объект `PaymentRequired` в кодировке Base64 с pricing и инструкциями по оплате |
| `PAYMENT-RESPONSE` | `200` или `402` (после попытки оплаты) | Результат расчёта в кодировке Base64 с хешем транзакции или ошибкой            |

<div id="error-codes">
  ## Коды ошибок
</div>

| Status | Tag                        | Описание                                                            |
| ------ | -------------------------- | ------------------------------------------------------------------- |
| `402`  | `X402_PAYMENT_REQUIRED`    | Payment не предоставлен. Pricing указан в header `PAYMENT-REQUIRED` |
| `402`  | `X402_VERIFICATION_FAILED` | Payment signature не прошла верификацию у facilitator               |
| `400`  | `X402_INVALID_SIGNATURE`   | Некорректная или нечитаемая payment signature                       |
| `429`  | `X402_TOO_MANY_UNPAID`     | Слишком много unpaid discovery-запросов с этого IP                  |
| `429`  | `X402_WALLET_RATE_LIMITED` | Wallet превысил лимит в 10 requests/секунду                         |
| `500`  | `X402_INTERNAL_ERROR`      | Ошибка на стороне server при формировании требований к payment      |

<div id="faq">
  ## Частые вопросы
</div>

<AccordionGroup>
  <Accordion title="Можно ли использовать x402 и API key одновременно?">
    Если ваш request содержит header `x-api-key` или token `Authorization: Bearer`, приоритет получает сценарий с API key, а x402 не применяется. Они не сочетаются: в каждом request используется что-то одно.
  </Accordion>

  <Accordion title="Что произойдёт, если расчёт не пройдёт уже после обработки моего request?">
    Ваш response будет заблокирован. Вы получите `402` с заголовками `PAYMENT-RESPONSE` (с описанием ошибки) и `PAYMENT-REQUIRED` (чтобы ваш client мог повторить попытку). Результаты не возвращаются, пока расчёт не пройдёт успешно.
  </Accordion>

  <Accordion title="Почему numResults ограничен значением 10?">
    Для request через x402 действует ограничение в 10 результатов на один search. Если нужно больше, используйте сценарий с API key и платный тариф.
  </Accordion>

  <Accordion title="Какие wallet поддерживаются?">
    Любой EVM-совместимый wallet, способный подписывать типизированные данные EIP-712 в сети Base, либо Solana wallet, поддерживаемый x402 SVM client для `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`. x402 SDK поддерживает `viem`, `ethers`, подписантов Coinbase Wallet и подписантов Solana SVM. Для AI agents на базе EVM [Coinbase Agentic Wallets](https://docs.cdp.coinbase.com/agent-kit/core-concepts/wallet-management) предлагают изолированное в TEE управление ключами, так что ваш agent никогда не работает напрямую с «сырыми» private keys.
  </Accordion>
</AccordionGroup>
