Агенты оплачивают Exa банковской картой по схеме [делегирования карты x402](https://nevermined.ai/docs/specs/x402-card-delegation) от [Nevermined](https://nevermined.ai). Каждая **покупка на $7** возвращает Exa API key с **$7 кредитов Exa**.

<Info>
  Используйте этот идентификатор плана Nevermined:<br />`27800462147494506865542649899724877617306579171265399959488097895839186996870`<br />Этот план работает в рабочей среде Nevermined (API keys с префиксом live). Покупка даёт кредиты API, а не один поисковый запрос.
</Info>

Если плательщик обращается к Nevermined впервые, запрос `POST /team-management/nevermined/purchase-key` создаёт новый Exa API key и начисляет $7 кредитов. Когда кредиты на key закончатся, сгенерируйте новый токен x402 с тем же делегированием и вызовите тот же эндпоинт ещё раз. Exa вернёт тот же API key, начислив на него ещё $7 кредитов.

<div id="buy-a-key">
  ## Купить key
</div>

```bash theme={null}
POST https://admin-api.exa.ai/team-management/nevermined/purchase-key
payment-signature: <x402-token>
```

* **Стоимость:** $7 за покупку, списываются с карты, привязанной к делегированию, на которое ссылается токен x402.
* **Ответ (новый плательщик):** `{ status: "ok", apiKey: "…", expiresAt: null }` — новый Exa API key с кредитами на $7.
* **Ответ (повторная покупка):** `{ status: "ok", apiKey: "…", expiresAt: null }` — тот же Exa API key с дополнительными кредитами на $7.
* **Ответ (повторно отправленный токен):** результат из кеша, повторное списание не выполняется.
* **Отсутствующая/недействительная подпись:** `402 Payment Required`, в теле ответа — платёжные требования.

<div id="how-it-works">
  ## Как это работает
</div>

Платёжную часть берёт на себя Nevermined; Exa видит только подписанный токен x402.

1. **Разовая настройка (выполняется владельцем карты):** зарегистрируйте карту на [nevermined.app](https://nevermined.app), создайте для неё **делегирование** (разрешение на расходование: владелец задаёт лимит и срок действия и может ограничить его конкретным API key), затем выпустите Nevermined API key для агента.
2. **Агент находит своё делегирование.** Nevermined SDK позволяет агенту найти делегирования, с которых может расходовать средства его key, и выбрать то, где остаётся достаточно бюджета (не менее $7). Если таких нет, владелец создаёт делегирование в панели управления, либо полностью автономный агент создаёт его сам через SDK в пределах лимитов карты.
3. **Агент выпускает токен доступа x402** для указанного выше идентификатора плана по схеме делегирования карты, ссылаясь на делегирование по ID. Делегирования должны существовать до выпуска токена — создать их «на лету» токены не могут.
4. **Агент отправляет POST-запрос с токеном на указанный выше эндпоинт** в заголовке `payment-signature` и получает Exa API key в ответе.
5. **Key работает сразу же** со стандартным [Exa Search API](/ru/docs/search/quickstart).

Полное пошаговое руководство для агентов (методы SDK, параметры, поиск и создание делегирований, устранение неполадок) смотрите в руководстве Nevermined по интеграции с Exa: [nevermined.ai/docs/integrations/exa](https://nevermined.ai/docs/integrations/exa) (для агентов: загрузите [nevermined.ai/docs/integrations/exa.md](https://nevermined.ai/docs/integrations/exa.md)).

<div id="when-the-key-runs-out">
  ## Когда средства по ключу заканчиваются
</div>

Exa возвращает **`HTTP 402`** на обычных эндпоинтах API, как только кредиты API key исчерпаны:

```json theme={null}
{
  "requestId": "...",
  "error": "You have exceeded your credits limit. Please top up to keep using Exa at dashboard.exa.ai",
  "tag": "NO_MORE_CREDITS"
}
```

Выпустите новый токен x402 с тем же идентификатором плана и делегированием и снова отправьте его POST-запросом на тот же эндпоинт `/purchase-key`. Exa начислит ещё $7 кредитов на тот же API key.
