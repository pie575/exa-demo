Это руководство предполагает, что у вас уже есть работающий [запрос к Search API](/ru/docs/search/quickstart). Здесь описано, как улучшить его, следуя рекомендациям Exa.

<div id="start-with-the-smallest-useful-request">
  ## Начните с минимального полезного запроса
</div>

Лучшая отправная точка — запрос на естественном языке с `highlights: true`. Exa сама подбирает объём фрагментов для каждого результата в зависимости от его релевантности, поэтому подстраивать лимит символов не нужно:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      contents={"highlights": True},
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search(
    "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
    { contents: { highlights: true } }
  );
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      "contents": { "highlights": true }
    }'
  ```
</CodeGroup>

Так вы получите ранжированные страницы и экономичный по токенам контекст по каждой из них, релевантный запросу.

Остальные параметры добавляйте только по мере необходимости:

| Параметр                   | Когда добавлять                                                                |
| -------------------------- | ------------------------------------------------------------------------------ |
| `type`                     | Нужно уложиться в бюджет задержки или обеспечить требуемую глубину             |
| `numResults`               | Меньше страниц для небольшого контекстного окна или больше для широкого охвата |
| `outputSchema`             | Требуется синтезировать результаты или структурировать их в JSON               |
| `maxAgeHours`              | Содержимое страниц из кэша может оказаться слишком устаревшим                  |
| `highlights.maxCharacters` | Приложению нужен фиксированный лимит фрагмента на страницу                     |
| Фильтры по домену или дате | Результаты за пределами ограничения окажутся непригодными                      |

<div id="search-vs-deep-search">
  ## Search и Deep Search
</div>

Обычный search находит и ранжирует страницы по запросу. Deep Search запускает исследовательский процесс: он может
искать итеративно, анализировать найденное, уточнять поиск и формировать обоснованный результат.

| Задача                                                                                                                               | С чего начать                       |
| ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| Ранжированные страницы по чётко сформулированному запросу                                                                            | `auto` или `fast`                   |
| Сложные поисковые задачи, синтез по множеству результатов или структурированный вывод, который не заполнить одним поиском (3+ полей) | `deep`                              |
| Длительные исследования, построение списков или многошаговое обогащение (enrichment)                                                 | [Exa Agent](/ru/docs/agent/quickstart) |

При использовании `outputSchema` по умолчанию рекомендуются глубокие режимы. Полные инструкции и примеры — в [руководстве по Deep Search](/ru/docs/search/deep-search).

<div id="improve-retrieval-quality">
  ## Повышение качества поиска
</div>

Если результаты нужно улучшить, меняйте запрос по одному параметру за раз.

<Steps>
  <Step title="Уточните запрос">
    Опишите нужные вам страницы, а не набор ключевых слов. Укажите тему и, если это важно, тип источника,
    период времени или другие детали, которые меняют представление о релевантном результате.

    ```text theme={null}
    Benchmark papers evaluating long-context retrieval methods on legal documents
    ```
  </Step>

  <Step title="Разбирайте ответ по уровням">
    Прежде чем менять запрос, посмотрите на заголовки, URL, даты публикации и highlights.

    ```json theme={null}
    {
      "results": [
        {
          "title": "Long-Context Retrieval Methods on Legal Documents",
          "url": "https://arxiv.org/abs/2608.00000",
          "publishedDate": "2026-08-26T00:00:00.000Z",
          "highlights": [
            "We compare long-context retrieval methods across legal document benchmarks..."
          ]
        }
      ]
    }
    ```

    Заголовок и URL показывают, какой источник нашла Exa, `publishedDate` — насколько он свежий,
    а highlight — фрагмент, который совпал с запросом. Уточняйте запрос, чтобы получать другие
    страницы, добавляйте фильтры по дате, чтобы сузить период, или запрашивайте полный текст, если
    удачного результата не хватает для контекста.
  </Step>

  <Step title="Добавляйте только жёсткие ограничения">
    Используйте `includeDomains`, `excludeDomains` и фильтры по дате публикации только тогда, когда
    результат, нарушающий ограничение, непригоден. Предпочтения по поиску указывайте в запросе, а при
    синтезе ответа — инструкции к ответу в `systemPrompt`.
  </Step>

  <Step title="Меняйте режим поиска в последнюю очередь">
    Используйте более быстрый режим, если есть требования к задержке, или глубокий режим, когда сам процесс
    поиска требует итераций и рассуждения. Смена режима не исправит недостаточно конкретный запрос.
  </Step>
</Steps>

Во время настройки держите под рукой небольшой набор показательных запросов. Сравнивайте релевантность результатов и успешность итоговой задачи по всему набору, а не оптимизируйте под один пример. Фиксируйте `requestId`, `searchTime` и `costDollars`, чтобы регрессии были воспроизводимы.

<div id="budget-latency-and-context">
  ## Управление задержкой и объёмом контекста
</div>

Каждый параметр расходует свой ресурс:

| Параметр                  | Что добавляет                                                    |
| ------------------------- | ---------------------------------------------------------------- |
| Больше результатов        | Больше страниц, данных в ответе и контекста на дальнейших этапах |
| Полный текст              | Более широкий контекст страницы и больший payload                |
| `summary`                 | Один дополнительный вызов языковой модели на каждый результат    |
| `outputSchema`            | Синтез по всем полученным результатам                            |
| `contents.maxAgeHours: 0` | Свежую загрузку страницы вместо кешированного содержимого        |
| Глубокие типы search      | Итеративный search, синтез и рассуждение                         |

Если задержка критична, а кешированное содержимое допустимо, сочетайте режим с наименьшей задержкой, highlights и контент только из кеша:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent product updates from major AI labs",
      type="instant",
      contents={
          "highlights": True,
          "max_age_hours": -1,
      },
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search("Recent product updates from major AI labs", {
    type: "instant",
    contents: {
      highlights: true,
      maxAgeHours: -1
    }
  });
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent product updates from major AI labs",
      "type": "instant",
      "contents": {
        "highlights": true,
        "maxAgeHours": -1
      }
    }'
  ```
</CodeGroup>

Не применяйте этот рецепт, если свежесть страницы влияет на корректность результата. Начинайте с `auto` и значения свежести по умолчанию, если у продукта нет измеренного целевого показателя задержки.

Чтобы Exa распределяла единый бюджет контекста по всему набору результатов — больше на сильные источники, меньше на избыточные, — см. [исследовательскую версию Dynamic Highlights](/ru/docs/search/highlights#dynamic-highlights).

<div id="tips-for-common-use-cases">
  ## Советы по типичным сценариям
</div>

| Если вам нужно                                 | Используйте                                                            | Избегайте                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------- |
| Более свежие публикации                        | Указание временного интервала в запросе или фильтры по дате публикации | `maxAgeHours`                                                 |
| Актуальное содержимое часто меняющихся страниц | `contents.maxAgeHours`                                                 | Фильтры по дате публикации                                    |
| Определённый тип источников                    | Формулировку запроса; `systemPrompt` при синтезе                       | Жёсткий список разрешённых доменов                            |
| Результаты только из одобренных источников     | `includeDomains`                                                       | Повторение `site:` в запросе                                  |
| Небольшой структурированный вывод              | `outputSchema` со стандартным Search                                   | Выбор Deep только из-за того, что вывод в формате JSON        |
| Проработанный вывод из нескольких элементов    | `deep` с `outputSchema` или [Exa Agent](/ru/docs/agent/quickstart)        | Расчёт на то, что один проход извлечения соберёт все элементы |
| Больше контекста с нескольких страниц          | Search с highlights, затем вызов Contents                              | Полный текст для каждого результата                           |
| Меньшую задержку                               | Замеры с `fast` или `instant` и компактным содержимым                  | Включение по умолчанию параметров свежести или синтеза        |

<div id="when-to-use-another-endpoint">
  ## Когда использовать другой эндпоинт
</div>

Используйте другой эндпоинт Exa, когда меняется характер задачи:

| Задача                                                     | Используйте                           |
| ---------------------------------------------------------- | ------------------------------------- |
| Длительные исследования, построение списков или enrichment | [Exa Agent](/ru/docs/agent/quickstart)   |
| URL уже известны                                           | [Contents](/ru/docs/contents/quickstart) |
| Запуск search по расписанию                                | [Monitors](/ru/docs/monitors/quickstart) |
