Это руководство предполагает, что у вас уже есть работающий [запрос к Search API](/ru/docs/search/quickstart). В нём описано, как улучшить такой запрос, следуя рекомендациям Exa.

<div id="start-with-the-smallest-useful-request">
  ## Начните с минимального полезного запроса
</div>

Лучшая отправная точка — запрос на естественном языке с `highlights: true`. Exa подбирает размер фрагментов для каждого результата в соответствии с его релевантностью, поэтому настраивать character budget не требуется:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      contents={"highlights": True},
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search(
    "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
    { contents: { highlights: true } }
  );
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent technical articles comparing hybrid and semantic retrieval for RAG systems",
      "contents": { "highlights": true }
    }'
  ```
</CodeGroup>

Так вы получите ранжированные страницы и экономичный по токенам контекст по каждой странице, релевантный запросу.

Добавляйте остальные параметры только по мере необходимости:

| Параметр                   | Когда добавлять                                                             |
| -------------------------- | --------------------------------------------------------------------------- |
| `type`                     | Нужно уложиться в бюджет задержки или обеспечить нужную глубину             |
| `numResults`               | Меньше страниц для небольшого окна контекста или больше для широкого охвата |
| `outputSchema`             | Нужно синтезировать результаты или представить их в виде JSON               |
| `maxAgeHours`              | Кэшированное содержимое страницы может быть слишком старым                  |
| `highlights.maxCharacters` | Вашему приложению нужен фиксированный лимит фрагмента на страницу           |
| Фильтры по домену или дате | Результаты вне ограничения будут непригодны                                 |

<div id="search-vs-deep-search">
  ## Search и глубокий поиск
</div>

Стандартный search находит и ранжирует страницы по запросу. Глубокий поиск запускает исследовательский процесс, который может
искать итеративно, анализировать найденное, уточнять поиск и синтезировать grounded-результат.

| Задача                                                                                                                                  | С чего начать                       |
| --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Ранжированные страницы по корректно сформулированному запросу                                                                           | `auto` или `fast`                   |
| Сложные поисковые задачи, синтез по множеству результатов или структурированный вывод, который нельзя получить одним поиском (3+ полей) | `deep`                              |
| Длительные исследования, построение списков или многошаговый enrichment                                                                 | [Exa Agent](/ru/docs/agent/quickstart) |

При использовании `outputSchema` по умолчанию рекомендуются глубокие режимы. Полные инструкции и примеры смотрите в [руководстве по глубокому поиску](/ru/docs/search/deep-search).

<div id="improve-retrieval-quality">
  ## Улучшение качества поиска
</div>

Если результаты требуют улучшения, меняйте по одной части запроса за раз.

<Steps>
  <Step title="Уточните запрос">
    Опишите нужные вам страницы, а не набор ключевых слов. Укажите тему и любые детали — тип источника,
    временной период и прочее, — которые меняют представление о релевантном результате.

    ```text theme={null}
    Benchmark papers evaluating long-context retrieval methods on legal documents
    ```
  </Step>

  <Step title="Разбирайте ответ по уровням">
    Прежде чем менять запрос, посмотрите на заголовки, URL, даты публикации и highlights.

    ```json theme={null}
    {
      "results": [
        {
          "title": "Long-Context Retrieval Methods on Legal Documents",
          "url": "https://arxiv.org/abs/2608.00000",
          "publishedDate": "2026-08-26T00:00:00.000Z",
          "highlights": [
            "We compare long-context retrieval methods across legal document benchmarks..."
          ]
        }
      ]
    }
    ```

    Заголовок и URL показывают, какой источник нашла Exa, `publishedDate` — насколько он свежий,
    а highlight — данные, совпавшие с запросом. Уточните запрос, чтобы получить другие страницы,
    добавьте фильтры по дате, чтобы сузить временной период, или запросите full text, если
    по полезному результату нужно больше контекста.
  </Step>

  <Step title="Добавляйте только жёсткие ограничения">
    Используйте `includeDomains`, `excludeDomains` и фильтры по дате публикации только тогда, когда результат,
    нарушающий ограничение, непригоден. Предпочтения по поиску выражайте в запросе, а при
    синтезе указывайте инструкции к ответу в `systemPrompt`.
  </Step>

  <Step title="Меняйте search mode в последнюю очередь">
    Выбирайте более быстрый режим, если есть требования к задержке, или режим deep, если сам процесс поиска
    требует итераций и рассуждений. Смена режима не исправит плохо сформулированный запрос.
  </Step>
</Steps>

При настройке держите под рукой небольшой набор показательных запросов. Сравнивайте релевантность результатов и успешность последующих задач по всему набору, а не оптимизируйте под один пример. Записывайте `requestId`, `searchTime` и `costDollars`, чтобы регрессии были воспроизводимы.

<div id="budget-latency-and-context">
  ## Бюджет задержки и контекст
</div>

Каждый параметр расходует свой ресурс:

| Параметр                  | Что добавляет                                             |
| ------------------------- | --------------------------------------------------------- |
| Больше результатов        | Больше страниц, данных ответа и последующего контекста      |
| Full text                 | Более широкий контекст страницы и больший payload          |
| `summary`                 | Один дополнительный вызов языковой модели на результат    |
| `outputSchema`            | Синтез по всем полученным результатам                  |
| `contents.maxAgeHours: 0` | Свежая загрузка страницы вместо кэшированного содержимого |
| Deep search types         | Итеративный поиск, синтез и рассуждения                |

Для сценариев реального времени, где кэшированное содержимое допустимо, сочетайте режим с наименьшей задержкой, highlights и содержимое только из кэша:

<CodeGroup>
  ```python Python theme={null}
  result = exa.search(
      "Recent product updates from major AI labs",
      type="instant",
      contents={
          "highlights": True,
          "max_age_hours": -1,
      },
  )
  ```

  ```javascript JavaScript theme={null}
  const result = await exa.search("Recent product updates from major AI labs", {
    type: "instant",
    contents: {
      highlights: true,
      maxAgeHours: -1
    }
  });
  ```

  ```bash cURL theme={null}
  curl -s -X POST "https://api.exa.ai/search" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $EXA_API_KEY" \
    -d '{
      "query": "Recent product updates from major AI labs",
      "type": "instant",
      "contents": {
        "highlights": true,
        "maxAgeHours": -1
      }
    }'
  ```
</CodeGroup>

Не применяйте этот рецепт, если свежесть страницы влияет на корректность. Начинайте с `auto` и свежести по умолчанию, если у продукта нет измеренной цели по задержке.

Чтобы Exa распределяла единый бюджет контекста по всему набору результатов — больше на сильные источники, меньше на избыточные — см. [исследовательское превью Dynamic Highlights](/ru/docs/search/highlights#dynamic-highlights).

<div id="tips-for-common-use-cases">
  ## Советы для типовых сценариев
</div>

| Если вам нужно                                    | Используйте                                                               | Избегайте                                                    |
| ------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Более свежие publications                         | Укажите временное окно в запросе или используйте publication-date filters | `maxAgeHours`                                                |
| Свежий контент со страниц, которые часто меняются | `contents.maxAgeHours`                                                    | Publication-date filters                                     |
| Определённый тип источников                       | Формулировку запроса; `systemPrompt` при синтезе                        | Жёсткий список разрешённых доменов                           |
| Результаты только из одобренных источников        | `includeDomains`                                                          | Повторение `site:` в запросе                                 |
| Небольшой structured вывод                       | `outputSchema` со standard Search                                         | Выбор Deep только потому, что вывод в JSON                   |
| Проработанный вывод из нескольких элементов       | `deep` с `outputSchema` или [Exa Agent](/ru/docs/agent/quickstart)           | Расчёт на то, что один проход retrieval соберёт все элементы |
| Больше контекста с нескольких страниц               | Search с highlights, затем вызов Contents                                 | Full text для каждого результата                             |
| Меньшую задержку                                  | Замеры `fast` или `instant` с компактным содержимым                       | Добавление параметров свежести или синтеза по умолчанию    |

<div id="when-to-use-another-endpoint">
  ## Когда использовать другой эндпоинт
</div>

Используйте другой эндпоинт Exa, если характер задачи меняется:

| Задача                                                     | Что использовать                      |
| ---------------------------------------------------------- | ------------------------------------- |
| Длительные исследования, построение списков или enrichment | [Exa Agent](/ru/docs/agent/quickstart)   |
| URL уже известны                                           | [Contents](/ru/docs/contents/quickstart) |
| Запуск поиска по расписанию                                | [Monitors](/ru/docs/monitors/quickstart) |
