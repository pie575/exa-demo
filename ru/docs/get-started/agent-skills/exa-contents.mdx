Используйте этот навык, чтобы научить агента вызывать Exa Contents через cURL или обычный HTTP с соблюдением лучших практик.

<Card title="Получите свой Exa API key" icon="key" horizontal href="https://dashboard.exa.ai/api-keys">
  Создайте key в панели управления. Новым аккаунтам начисляются бесплатные кредиты.
</Card>

<Note>
  Задайте key в переменной `EXA_API_KEY` в окружении агента.
</Note>

<div id="setup">
  ## Настройка
</div>

**Вариант A: установить навык напрямую:**

```bash theme={null}
npx skills add exa-labs/agent-skills --skill "exa-contents"
```

**Вариант Б: скопируйте этот промпт в свой кодинг-агент.**

Приведённый ниже промпт устанавливает навык и проверяет ваш API key, не выводя его в консоль:

```text Copy this setup prompt into your agent theme={null}
Настрой на этой машине навык агента Exa exa-contents.

Цель:
- Установить навык exa-contents, чтобы мой кодинг-агент мог вызывать Exa Contents напрямую через cURL или обычный HTTP.
- Добиться, чтобы Exa API key работал, НИ РАЗУ не раскрывая, не выводя и не вставляя ключ в этот чат.

Выбранный агент:
- Claude Code, Codex, Cursor или любой агент, совместимый с Agent Skills
- Глобальные каталоги установки: ~/.claude/skills (Claude Code), ~/.codex/skills (Codex), ~/.agents/skills (Cursor / другие)
- Каталоги установки внутри проекта: .claude/skills (Claude Code), .agents/skills (Codex / Cursor / другие)

Источник навыка:
- URL SKILL.md: https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md

Что нужно сделать:
1. СНАЧАЛА установи навык, до любой настройки ключа. Если работа идёт внутри репозитория, предпочитай установку в проект; иначе используй соответствующий глобальный каталог из списка выше. Создай выбранный каталог навыков и скачай навык:
   mkdir -p <skills-dir>/exa-contents && curl -fsSL "https://raw.githubusercontent.com/exa-labs/agent-skills/main/skills/exa-contents/SKILL.md" -o <skills-dir>/exa-contents/SKILL.md
   Затем убедись, что файл <skills-dir>/exa-contents/SKILL.md существует.
2. Проверь, доступен ли уже Exa API key В ТВОЁМ СОБСТВЕННОМ ОКРУЖЕНИИ ВЫПОЛНЕНИЯ КОМАНД — используй тот же инструмент/оболочку, в которых будешь запускать навык, а не проси меня вывести ключ. Навык сначала берёт ключ из EXA_API_KEY, затем из файла ~/.config/exa/key, поэтому проверь оба варианта, ни разу не выводя значение:
   printf '%s\n' "${EXA_API_KEY:+env-set}"; [ -s ~/.config/exa/key ] && printf 'file-set\n'
   Твоя оболочка, скорее всего, неинтерактивная и НЕ подгружает автоматически интерактивные профили вроде ~/.zshrc или ~/.bashrc, поэтому заданный мной там ключ может выглядеть установленным для меня, но пустым для тебя. Если ни одна проверка ничего не показала, ключ всё ещё может лежать в интерактивном профиле, который твоя оболочка пропускает: найди нужный файл, НЕ выводя его значение, командой `grep -l EXA_API_KEY ~/.zshrc ~/.zshenv ~/.bashrc ~/.profile ~/.config/fish/config.fish 2>/dev/null` (она выводит только имена — НИКОГДА не запускай обычный `grep`/`cat`/`echo` по профилю, так как строка `export EXA_API_KEY=...` раскроет секрет в нашем чате). Затем выполни `source` для этого файла внутри своей команды и повтори проверку наличия выше; если ключ обнаружился, добавляй такой же префикс `source ...;` ко всем последующим командам, которым нужен ключ.
3. Только если ключ нигде не удаётся получить, настрой его БЕЗ ручного редактирования профилей оболочки и БЕЗ вставки ключа в этот чат. Скажи мне создать/скопировать ключ на https://dashboard.exa.ai/api-keys, а затем в своём терминале я либо сам экспортирую EXA_API_KEY, либо запишу его в ~/.config/exa/key с правами 600 — никогда не проси меня вставлять ключ в чат. После этого дождись моего подтверждения, прежде чем продолжать.
4. Проверь ключ пробным запросом из своей оболочки — возьми его из переменной окружения или из файла и выведи только код статуса:
   KEY="${EXA_API_KEY:-$(cat ~/.config/exa/key 2>/dev/null)}"
   curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.exa.ai/contents \
     -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"urls":["https://exa.ai"],"text":true}'
   Оставь эндпоинт, заголовки и тело запроса ровно такими, как написано (не угадывай схему). Ответ должен быть 200, а не 401/429. Если на шаге 2 тебе понадобился префикс `source ...;`, чтобы увидеть ключ в окружении, добавь его и здесь.
5. Объясни, как перезапустить агента или пересканировать навыки, чтобы он обнаружил навык.

Жёсткое правило на всех шагах: ключ — это секрет. Проверять его можно только через проверку наличия/длины (`${EXA_API_KEY:+set}`, `[ -s ~/.config/exa/key ]`) или по HTTP-коду статуса — никогда не выводи и не применяй `echo`, `cat` или `grep` с выводом к файлам и переменным, которые могут его содержать, и никогда не пытайся «замаскировать» файл с ключом регулярным выражением. Если ключ всё же оказался раскрыт, скажи мне сменить его на https://dashboard.exa.ai/api-keys.
```
